Что сохраняется для продолжения:

- Codex: только `sessions/`; конфигурация, `auth.json`, логи и база интерфейса не входят.
- Kimi: [расположение данных](https://github.com/MoonshotAI/kimi-code/blob/f67e6398fb3210ad8ace970e2dfd5bcc984ed61f/docs/en/configuration/data-locations.md), [ключ рабочего каталога](https://github.com/MoonshotAI/kimi-code/blob/f67e6398fb3210ad8ace970e2dfd5bcc984ed61f/packages/agent-core-v2/src/_base/utils/workdir-slug.ts). В снимок входят `session_index.jsonl`, `state.json` выбранной сессии и её `agents/`. В 2.1.1 `session.resume_hint` уже передаёт native id на stdout. До `sessionState` этот id нужно записать в `run.context.nativeSessionId`.
- Qwen: [chatRecordingService](https://github.com/QwenLM/qwen-code/blob/753bd075a24ca886b7d0119ca53d97bd65c09e4a/packages/core/src/services/chatRecordingService.ts), [storage](https://github.com/QwenLM/qwen-code/blob/753bd075a24ca886b7d0119ca53d97bd65c09e4a/packages/core/src/config/storage.ts), [sanitizeCwd](https://github.com/QwenLM/qwen-code/blob/753bd075a24ca886b7d0119ca53d97bd65c09e4a/packages/core/src/utils/paths.ts). Только `.qwen/projects/-workspace-repo/chats/<nativeSessionId>.jsonl`. Runtime-файлы процессов, другие сессии и настройки не входят.
- OpenCode: [путь SQLite](https://github.com/anomalyco/opencode/blob/545f51d26cc39a907d2867492d498d9607ea5fa4/packages/core/src/database/database.ts), [XDG paths](https://github.com/anomalyco/opencode/blob/545f51d26cc39a907d2867492d498d9607ea5fa4/packages/core/src/global.ts). Только `opencode.db` и его WAL для stable release с HOME под `/agent-home/opencode`, после остановки CLI. `auth.json`, config, log, repos и snapshot не входят. Продолжение в новом контейнере только из этих двух файлов подтверждено в G3 на закреплённом 1.18.34 (абзац ниже).

OpenCode 1.18.34 (G3, 09.10.2026). Драйвер OpenCode больше не код P1: `prepare` и `command` реализованы, а формат сверен с исполнением закреплённого CLI, а не с исходниками 1.18.32.

- `opencode.jsonl` — тот же минимальный ход, но в форме строк 1.18.34: у частей есть `messageID` и `sessionID`, у `step-finish` — `tokens.total`, вызовы `write` и MCP-инструмента идут отдельными строками `tool_use`.
- `opencode-turns.json` — десять ходов, записанных настоящим CLI в разведке G1 и очищенных `infra/dev/llm-verify/sanitize-samples.mjs` (источник — `docs/research/2026-10-opencode-glm/samples/72-g1-refusals/events/` и `74-g1-config/`): сжатие контекста, отклонённый запрос разрешения, отказы 403 и внутри потока, отказ после шага с инструментом, исчерпанные повторы, переполнение контекста, `finish_reason` `content_filter`, `length` и неизвестный. Тексты и идентификаторы заменены, ключей в записях нет.
- Строки конца хода CLI не печатает. `step_finish` с `reason: "stop"` даёт `completed`, но итог у хода есть, только если вывод кончается шагом ответа: `started`, собственный текст шага, `completed` — и ничего после (`extractOpencodeResult` в `opencode.ts`). Шаг с `reason` `length`, `content-filter`, `unknown` и любым другим, кроме `stop` и `tool-calls`, — `failed`.
- В снимок идут те же два файла — `opencode.db` и его WAL. Следующий ход их не использует как есть: обёртка драйвера читает базу командой `opencode export`, собирает файл импорта заново из девяти полей строки сессии и сообщений, удаляет базу и создаёт новую командой `opencode import` ([отчёт G3](../../../../docs/plan/42-opencode-driver.md)).

Ограничения адаптации:

- Парсеры stateless: экземпляры реестра могут обслуживать несколько задач. Частичные события, reasoning и произвольный вывод инструментов не попадают в клиентские сообщения. У Kimi/Qwen tool-result не содержит имени инструмента; сопоставление с предыдущими вызовами потребует отдельного контекста на запуск в P5. Неподтверждённый успех инструмента не выдумывается.
- У Codex отказ хода — только `turn.failed`. Строкой верхнего уровня `error` закреплённый 0.158.0 печатает и уведомление о переподключении (`Reconnecting... n/5`), после которого ход может завершиться успешно; перед окончательным отказом за ней следует `turn.failed`, а процесс выходит с ненулевым кодом. Проверено на настоящем CLI: `pnpm verify:codex` обрывает поток посреди ответа.
- Kimi stream-json не передаёт usage и финальный terminal event. Завершение подтверждается exit code процесса в P5; последний текст сам по себе не доказывает успешное выполнение.
- Qwen usage: `input_tokens` получен из `promptTokenCount`, кэш вычитается. Несогласованные счётчики отбрасываются. OpenCode `tokens.input` уже исключает кэш, а `tokens.output` исключает reasoning: в общий `output` reasoning добавляется один раз. Суммы `cost` игнорируются; ни один stdout-счётчик не используется для биллинга.
- `capabilities` описывает возможности CLI. В P1 были готовы разбор вывода, извлечение результата и выбор файлов; `prepare` и `command` появились позже — у Codex в P4, у Kimi в P5, у OpenCode в G3 (абзац выше), — а у Qwen остаются `NOT_IMPLEMENTED`. Полный запуск и resume проверяют стенды драйверов, эти фикстуры их не проверяют.
- Результат извлекается только из последнего сообщения или явно переданного last-message файла. Допустим JSON-объект либо один JSON code fence; нужен `turnResultSchema`. Произвольный текст, старый успешный объект перед ошибкой, несколько блоков и невалидный итог дают `null`.
