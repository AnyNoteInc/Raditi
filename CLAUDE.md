# Радити

Радити (raditi.ru) — сервис для малого бизнеса: владелец пишет в веб-чат или Telegram, что поменять на сайте, и AI-агент меняет его сайт — в MVP на WordPress, дальше на 1С-Битрикс и других CMS. Контент правится прямо на сайте со снимком для отката, код — через git-репозиторий сайта (наша Gitea или GitHub/GitLab клиента): ветка, PR, «Применить», выкладка с бэкапом, проверкой и автооткатом. Окружение у сайта одно — прод.

## Правила, которые нельзя нарушать

1. **Хранилища — в России, модели — по подпискам Codex и Kimi.** С G8 (11.10.2026) код Codex и Kimi, OAuth и инструменты разведки P3.0 (`record-proxy`, локальная проверка на подписке) из дерева удалены, единственная оболочка — OpenCode с GLM на Z.ai; этот абзац ещё описывает прежние подписки и исключения для разведки и переписывается в G9. База, S3, логи, снимки и журналы платформы — только у российских провайдеров. Задания, сообщения и файлы клиента, код и содержимое его сайта обрабатывают модели OpenAI (США) через подписки ChatGPT для Codex CLI и Moonshot AI через подписки Kimi Code (юрлицо и страна — по заключению юриста) — решение владельца от 28.09.2026. Других провайдеров моделей нет: GigaChat, Yandex AI Studio и Cloud.ru убраны. Сообщения и файлы клиента сначала записываются в PostgreSQL и S3 в России; прямого пути «браузер → провайдер модели» нет. В работе платформы к провайдерам ходит только шлюз подписок (роль `llm`): к OpenAI и Kimi — только через узел выхода за рубежом, к Z.ai — напрямую либо через тот же узел, когда его прокси задан; тела запросов нигде не пишутся. Для штатной разведки P3.0 (§21) на одноразовой `spike-1` разрешены временный `CODEX_HOME/auth.json` отдельного тестового аккаунта и очищенная запись синтетических обменов `record-proxy`; после неё — выход с отзывом токенов, удаление временных каталогов и ВМ. Решением владельца от 29.09.2026 отдельно разрешена локальная проверка на его текущей подписке Codex: только синтетика, изолированный временный `CODEX_HOME` без `auth.json`, существующий файл входа читает только `record-proxy` по `RECORD_CODEX_AUTH`, без копирования, повторного входа, обновления и отзыва токенов или `logout`. При истёкшем токене либо 401 на подписочном маршруте проверка останавливается; локальный отказ побочного `/disabled/…` не считается отказом подписки. Kimi в этой проверке не участвует; локальный результат не подтверждает удалённый `egress-1` и канал из России, не закрывает P3.0 или P3. Решением владельца от 04.10.2026 продукт переходит на одну оболочку и одну модель: OpenCode с GLM по подписке GLM Coding Plan на Z.ai; Codex, Kimi и всё, что обслуживает только их, убирается. Данные клиентов и production-секреты запрещены; в репозиторий попадают только проверенные очищенные материалы. Данные клиентов уходят провайдеру только после гейта 152-ФЗ (§18): `issue` не выдаёт ключ хода рабочему пространству с реальными данными без записи в `cross_border_clearances` для этой оболочки. Никаких других зарубежных API с данными клиентов.
2. **Секреты — только в Vault.** С G8 (11.10.2026) код Codex и Kimi и обновление токенов удалены: секрет подписки — ключ плана, роль `llm` его только читает (её политика в `subs/` — одно чтение), а пишет команда входа оператора; слова «читает и обновляет» и исключения для разведки P3.0 ниже переписываются в G9. В базе — `credential_refs` (путь в Vault), в коде, логах, S3 и Git — никогда. Форма доступов пишет в Vault и не умеет читать обратно. Сервисы входят по AppRole со своими политиками (§15). Токены подписок — только в Vault mount `subs/` (`max_versions=1`, `cas_required`). Читает и обновляет их только роль `llm`, импорт пишет и не читает обратно, удаляет — только политика admin. В песочницу, на песочную ВМ и `egress-1`, в `turn_assignments.plan`, логи и метрики они не попадают. Локально ключи сервисов можно держать в `.env`; тестовые подписки живут в OpenBao (`subscriptions:login`), не в `.env`. Узкие исключения для штатной разведки P3.0 и разрешённой 29.09.2026 локальной проверки — правило 1; они не распространяются на обычный dev, прод и проверку владельца P3 со своим OpenBao. Ещё одно узкое исключение — допущение стадии MVP по решению владельца от 05.10.2026 (правило 1): тестовый локальный ключ плана GLM на Z.ai лежит в корневом `.env` как `ZAI_API_KEY`, и у образов сервисов платформы один набор переменных окружения. В песочницу, логи и репозиторий этот ключ не попадает никогда.
3. **Прод один.** Код попадает на сайт только после «Применить»: бэкап → выкладка → проверка → автооткат. Контент меняется сразу, но перед правкой — снимок в `raditi-artifacts`; «Отменить» работает 7 дней (§7, §10, §11).
4. **Опасное — только через `request_approval`.** Удаление страниц, смена темы, плагины, настройки оплаты, массовые правки (больше 20 объектов). Пользователи и заказы сайта агенту недоступны.
5. **Песочница.** Задача — логическая сессия, контейнер — на один ход; в `awaiting_user` и `awaiting_approval` контейнера нет, сессия лежит в `raditi-sessions`. Docker + gVisor (`runsc`, systrap): dockerd от root, в контейнере uid 10001, read-only rootfs, cap-drop ALL, no-new-privileges, 2 vCPU, 4 ГБ, 512 процессов, 20 минут на ход; граница изоляции — gVisor. Сеть — internal без DNS и интернета, единственный выход — `sandbox-gw` с белым списком путей к шлюзу подписок (роль `llm`) и MCP-шлюзу. Долгоживущих секретов внутри нет, presigned-ссылок S3 тоже: файлы кладёт и забирает хост, коммит и push делает доверенная сторона (§8, §14).
6. **Пайплайн агент не меняет.** Выкладка — только обязательным пайплайном (в Gitea — workflow из `platform/ci`; для GitHub и GitLab клиента — открытый вопрос §20). Дифф агента отклоняется, если трогает пути CI (`.gitea/`, `.github/`, `.gitlab-ci.yml`, `.gitlab/`, `.forgejo/`, `.woodpecker*`, `.drone.yml`, `Jenkinsfile`, `bitbucket-pipelines.yml`, `.circleci/`), `.gitmodules` или `SiteAdapter.protectedPaths()` (§10).
7. **Квоты и кошелёк — через `credit_ledger`.** Резерв в `credit_holds` при постановке в очередь: на тарифе с квотой — одна правка, на «Оплате за действие» — сумма резерва по классу модели. Списание при `done` (на «Оплате за действие» — цена по `pricing_rules` из `token_usage` шлюза подписок по опубликованным учётным ставкам, не больше резерва; оценки по вине платформы не выставляются), возврат резерва при `failed` и `cancelled`. На тарифе с квотой порог допуска новых запросов попытки по учётным ставкам — 135, 285 и 735 ₽ для `light`, `standard` и `heavy`; шлюз учитывает оценочные резервы. Пока порог держит бюджет ключа хода: `issue` сверяет его с потолком класса или с резервом «Оплаты за действие» и с резервом первого вызова, а расход прежних ключей той же попытки считает нулём — общий расход попытки появится в P12. Перерасход уже допущенных запросов берёт платформа (§17). У каждой записи — ключ идемпотентности. Уточнение и «Изменить» — не новая задача, «Отменить» бесплатно (§17).
8. **Агент-агностичность.** Ядро знает только порты из `packages/domain`: `AgentDriver` и общие события (`started`, `message`, `command`, `file_change`, `tool_call`, `question`, `usage`, `completed`, `failed`), `SandboxProvider`, `TurnExecutor`, `TurnCredentialSource`, `TurnAssignmentStore`, `SiteLeaseStore`, `LlmBackend`, `GitProvider`, `SiteAdapter`, `SecretStore`, `ObjectStorage`, `JobQueue`. Никаких `if (driver === 'opencode')`, `if (backend === 'zai-coding')`, `if (provider === 'github')` или `if (cms === 'wordpress')` вне адаптера (§8, §13).
9. **Деньги — Decimal.** Цены показываем в ₽ с НДС. Суммы клиента — `Decimal(12,2)` и `Decimal(14,2)`; учётные ставки моделей — ₽ за 1 млн токенов с НДС, `Decimal(14,6)`, с историей (`effective_from`) и ставкой НДС `Decimal(5,4)`, утверждаются раз в квартал; стоимость аккаунта подписки — ₽ в месяц, `Decimal(12,2)`, с историей; себестоимость — `Decimal(18,10)`; наценка — `Decimal(8,4)`. Округление HALF_UP до копеек — один раз на действие. В DTO и API деньги — строки.
10. **Клиенту — по-русски и на «вы».** Без жаргона и английских терминов; `client_message` уходит клиенту как есть и проходит zod-схему итога хода (§8).

## Как писать код

- **Порты и адаптеры.** `packages/domain` — ядро: `DomainError`, порты и zod-схемы общих событий и итога хода; бизнес-логика со временем переезжает сюда. domain не зависит ни от одного пакета репозитория.
- Адаптеры реализуют порты и зависят только от domain: `db`, `storage`, `vault`, `git-providers`, `sandbox-providers`, `agent-drivers`, `llm-backends` (с P3), `site-adapters`, `yookassa`, `mail`, `telegram`. Реализации одного порта — в одном пакете: `git-providers` — gitea, github, gitlab; `sandbox-providers` — docker; `agent-drivers` — opencode, единственный драйвер пакета и продукта с G8 (codex, kimi и qwen удалены); `llm-backends` — zai-coding (openai-chatgpt и kimi-code удалены в G8); `site-adapters` — wordpress, bitrix.
- Выше адаптеров — сервисы (`auth`, `notifications`), транспорт (`trpc`) и `ui`. Приложения (`web`, `orchestrator`, `e2e`) — точка сборки: создают адаптеры и подставляют их в порты. Зависимости только вниз, пакеты не импортируют приложения; слои проверяет dependency-cruiser.
- `observability` — сбоку от слоёв, только серверный код приложений: health, метрики, bearer-токен, `errorMessage` и `throttledLogger`. Зависит только от domain и `@prometheus-io/client`; импортируют его только приложения. Чистые помощники без ввода-вывода, нужные и доверенному коду (`withTimeout`, разбор env: `parseEnv`, `envVar`, `envProblems`, `Env`), — в domain.
- Пакеты называются `@repo/<имя>`.
- zod на всех границах: вебхуки, tRPC, итог хода агента, события драйверов.
- Деньги в коде — Decimal (decimal.js), не `number`. В DTO и API — строки с фиксированным числом знаков (`toFixed`), их проверяют zod-схемы.
- Новая переменная окружения — сразу в `.env.example` и в `globalEnv` в `turbo.json`. Переменные, которые подставляет только compose app-ВМ (`APP_DOMAIN`, `ACME_*`, образы и т. п.), — в `infra/app/env.example`: приложения их не читают.
- Ошибки домена — `DomainError`, как в AnyNote.
- Статусы задачи — только из §7: `queued`, `preparing`, `running`, `awaiting_user`, `awaiting_approval`, `deploying`, `verifying`, `done`, `failed`, `rolled_back`, `cancelled`.
- Бакеты — `raditi-inbox`, `raditi-sessions`, `raditi-logs`, `raditi-artifacts`, `raditi-backups`, `raditi-platform` (§14).
- Метрики — `@prometheus-io/client`. В метки не кладём `task_id`, `user_id` и другие идентификаторы; Prometheus — не источник для биллинга.
- Тесты рядом с кодом (Vitest). Всё, что трогает деньги, квоты, Vault, выкладку и откат, — только с тестами.
- Тест или стенд `apps/orchestrator`, которому всё равно, чей драйвер и чей бэкенд, берёт id из `apps/orchestrator/src/testing/ids.ts` (`sampleDriverId`, `sampleBackendId`, `sampleProviderSlug`, `sampleProviderModelId`, `sampleModelSlug`, `sampleRoutePath`); тест поведения одного адаптера называет адаптер сам. В пакетах и `infra` образцовые id — литералы `opencode`, `zai-coding`, `glm-5.3`. Паре, которой нужны два разных id драйвера, второй — `otherDriverId` из того же файла: id вне списка, который место со схемой отклоняет. Тесту роли `llm`, которому нужен второй адаптер (чужой маршрут, повтор заголовка, узел выхода), его даёт синтетический адаптер самого теста, а не второй настоящий. Продуктовый код `src/testing` не импортирует — это держит правило dependency-cruiser `orchestrator-product-no-testing`.
- Id драйвера или бэкенда, ушедший из списков `agentDriverIds` и `llmBackendIds`, отвергается схемой там, где сохранённая строка читается обратно как работа, — протокол раннера, план хода, политика выдачи ключа, ссылка на снимок и его манифест, — и читатель такой строки отвечает постоянной ошибкой домена (`BAD_REQUEST` или `CONFLICT`), а не необработанным `ZodError`. Строки с таким id остаются историей: читатель истории (доверенный возврат правок, сборщики, здоровье пула) на них не падает, сиды их не создают и не трогают.
- Применённые миграции не редактируем: изменения схемы и CHECK-ограничений — следующей миграцией с сохранением данных.
- Миграция, команды которой должны примениться вместе (например, `DROP` и `ADD` одного ограничения), оборачивается в `BEGIN` и `COMMIT`. Остановку (`RAISE EXCEPTION`) ставят перед `BEGIN`: Prisma 7.10 шлёт файл миграции одним запросом и после сбоя пишет ошибку в `_prisma_migrations` тем же соединением — исключение внутри открытой транзакции оставляет соединение в оборванной транзакции, запись Prisma падает, и оператор видит «current transaction is aborted» вместо сообщения миграции (измерено 11.10.2026 на файле с `BEGIN`; по замеру ревью G8 одним запросом уходит и файл без `BEGIN` — `docs/plan/48-removal.md`, «Миграция»). Прежняя фраза этого правила — «`prisma migrate deploy` отправляет файл по одной команде, каждую в своей транзакции» — с этой версией Prisma не воспроизводится. Остановки применённых миграций B6 и биллинга подняты внутри `BEGIN`: по устройству файлов (прогона не было) их сообщение останется только в логе PostgreSQL; применённые миграции не правятся (П50).
- Коммиты — Conventional Commits на английском (релизы собирает semantic-release), по одной задаче из roadmap.
- Язык: общение и документы — русский; код, идентификаторы и комментарии — английский; тексты интерфейса — русский.

## Как работать в этом репозитории

Решение владельца от 30.09.2026: всю реализацию и проверки вести локально. До выкладки на облачные серверы пройти полный локальный e2e с настоящим WordPress: задание → агент → правка → «Применить» → бэкап → выкладка → проверка → откат; для контента — снимок и «Отменить». Критерии — `infra/dev/site-verify/README.md`. Подготовительный `pnpm verify:site` проверяет страницу и её восстановление, полный продуктовый гейт остаётся открытым до подключения платформы. Облачные проверки P3.0/P14 и M10 отложены до успешного полного прохода.

1. Перед задачей прочитай её строку в `docs/plan/roadmap.md` и указанные разделы spec.
2. Задача трогает больше трёх файлов — сначала план, потом код.
3. Похожий код сначала ищи в `../AnyNote` (агент `anynote-scout`) и адаптируй под правила выше, а не копируй вслепую.
4. В конце — `pnpm typecheck && pnpm lint && pnpm test` для затронутых пакетов и `pnpm check-architecture`.
5. Перед коммитом — `/spec-check`.
6. Если решение меняется — обнови `docs/spec.md` и скажи об этом в ответе.

## Локальная разработка на macOS

gVisor работает только на Linux. На Mac песочница запускается с `SANDBOX_RUNTIME=runc`; изоляцию под `runsc` проверяй в Linux-ВМ (OrbStack, Colima, Lima) или на dev-сервере. Код раннера не должен зависеть от runtime — он приходит из конфигурации.
