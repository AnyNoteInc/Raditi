# browser

Процесс облачного браузера задач без кодовой базы ([план 57](../../docs/plan/57-browser-tasks.md), Б10–Б28): держит браузерные сессии задач — Chromium каждой сессии в своём контейнере (`@repo/sandbox-providers`, `createDockerBrowserSessionRuntime`: своя internal-сеть без адреса хоста, единственный выход — прокси выхода со списком хостов сайта, управляющий порт — через пересыльщик на loopback хоста) — и управляет им через Playwright (`@repo/browser-providers`, `createPlaywrightCloudBrowser`). Жизненным циклом задач не владеет: сессию открывает и закрывает `core`, процесс `browser` записывает, что в ней происходит. Порт 8086 (`BROWSER_WORKER_PORT`), всё — за токеном `BROWSER_WORKER_TOKEN`.


## Устройство

Приложение Nest из модулей по разделам, как остальные приложения после [плана 56](../../docs/plan/56-nest-modules.md) (§3). Вход — `src/main.ts` (`.env`, разбор конфигурации до Nest, предел остановки) → `src/start.ts`: `startBrowser` создаёт приложение `AppModule.forRoot(config)` без парсера тел Nest (`browserAppOptions`), а `serveBrowser` ставит фильтр отказов API, остановку по сигналам и поток на HTTP-сервер и открывает порт. Корень — `src/app.module.ts`; база — глобальный `DatabaseModule` из `@repo/service-runtime`, поэтому Prisma отключается после того, как процесс закрыл все сессии. Каталоги `src`:

- `config` — `loadBrowserConfig` и глобальный `BrowserConfigModule` (`BROWSER_CONFIG`); модули разделов читают свои настройки через него;
- `metrics` — реестр процесса (`MetricsRegistryModule`, глобальный, метка `app="browser"`), `/metrics` с `METRICS_TOKEN` (`MetricsModule`) и метрики сессий и потока (`worker-metrics.ts`); `health` — `/health` (`HealthModule` из `@repo/service-runtime`: база и Docker, подробности — с `METRICS_TOKEN`);
- `store` — записи `browser_sessions` и `browser_checkpoints` и чтение задач (`WORKER_STORE`); `attachments` — вложения задач из `raditi-inbox` (`INBOX_STORAGE`); `sessions` — менеджер сессий и сессия (`SessionManager`, `WorkerSession`) и то, на чём сессия работает: контейнеры (`SESSION_RUNTIME`) и Playwright (`CLOUD_BROWSERS`);
- `stream` — WebSocket потока (`BrowserStreamServer`); `worker` — `BrowserWorker`: сессии, поток и метрики одним целым, сборщик простаивающих сессий, уборка остатков прежнего процесса при запуске и закрытие сессий при остановке (`WorkerModule` экспортирует только `SessionManager`); `api` — `/v1/sessions` за `BROWSER_WORKER_TOKEN` (`WORKER_TOKEN`), его фильтр отказов и чтение тел; `common` — фиксированные коды действий и имена ошибок для журнала;
- `testing` — только тестам: поддельные база, контейнеры, браузер и inbox (`fakes.ts`), менеджер сессий на них (`harness.ts`) и приложение `startTestBrowser` — тот же `AppModule` и `serveBrowser`, где подделки подставлены вместо провайдеров (`app.ts`).

## Что умеет

- **API для `core` и `mcp`** (план 57, §3.5; HTTP JSON, `Authorization: Bearer`, токен сравнивается за постоянное время, отказ — 401 без подробностей): `POST /v1/sessions/ensure` (создать или найти живую сессию; в теле — только id и `takeControl` — управление агенту, эпоха +1; адрес и стек сайта процесс читает из базы по `siteId`, и разрешённые хосты, политика стека и стартовая страница строятся только из них), `POST /v1/sessions/:id/close`, `POST /v1/sessions/:id/verify` (перечитать все сохранённые объекты задачи на сайте и записать факты), `GET /v1/sessions` (для сборщика `core`), `POST /v1/sessions/:id/actions` (действие агента `web_*`). Тела проверяются схемами домена (`browser/worker-api.ts`); отказ — `{ code }` со статусом кода (§3.7: `BROWSER_USER_IN_CONTROL` — 409 и т. д.), без адреса, значения поля и текста страницы. Тела читает сам API (до 64 КиБ), парсера Nest нет.
- **Поток для шлюза трансляции** (`apps/preview`, §3.6): `WS /v1/sessions/:id/stream?viewer=<uuid>&user=<uuid>` на том же порту и с тем же токеном; членство пользователя проверяется ещё раз (`browserViewerAllowed`). Зрителю сразу — состояние и последний кадр, дальше кадры через `FrameFlow` домена: не больше `BROWSER_STREAM_MAX_FPS` в секунду, окно неподтверждённых `BROWSER_STREAM_WINDOW`, один самый свежий ожидающий, предел `bufferedAmount` 1 МиБ; место в окне освобождает только подтверждение — зрителя или шлюза за кадр, который он выбросил, — а не время (медленная связь кадры не теряет, отступление от Б13 от 23.10.2026), и подтверждение, освобождающее место, предел сообщений в секунду не отбрасывает; кадр другой страницы или размера окна — отбрасывается; заголовок кадра — 48 байт. Подтверждение кадра Chromium задерживается до следующего слота, так что Chromium не снимает чаще. Ping каждые 10 с; зритель, не ответивший с прошлого ping, отключается. Ввод — только держателя управления, с его эпохой, страницей и версией окна (`admitBrowserInput`); «Взять управление» ждёт текущего действия агента не дольше его таймаута (10 с); при отключении зрителя зажатые клавиши отпускаются, пауза остаётся (Б17); когда зрителей нет, трансляция останавливается.
- **Менеджер сессий**: одна сессия — один контекст Chromium на задачу; управление — чистая машина домена (`browser/control.ts`), передачи пишутся в `browser_sessions`; действия агента — по одному; наблюдения нумеруются (`o1`, `o2`, …), действие по ссылке не последнего наблюдения — `BROWSER_STALE_OBSERVATION`. Checkpoint: адрес редактора объекта (`SiteAdapter.browserCheckpointOf`) — `seen`; нажатие кнопки сохранения или публикации (`browserCommitAction` по роли и имени элемента из наблюдения) — `unverified`, пока его не прочтёт проверка; пока есть неподтверждённое, агенту закрыты новая публикация и переход к новому объекту (`BROWSER_CHECKPOINT_UNVERIFIED`). Сохранением считаются и Control/Command+S, и Enter или пробел без ссылки на кнопке сохранения в фокусе — её роль и имя worker читает из свежего дерева (`CloudBrowserSession.focused`), а фокус, который не прочитался, отменяет нажатие. За задачу агент сохраняет не больше 20 разных объектов (`browserCheckpointLimits.changedObjects`, Б34): 21-й и новый объект — `BROWSER_ACTION_DENIED`, ручное управление клиента предел не ограничивает. Вложения для `web_upload` и окна выбора файла — только привязанные к задаче сессии (`taskAttachment`), из `raditi-inbox`, с проверкой ключа и размера. Сессия закрывается по сроку простоя (`BROWSER_SESSION_IDLE_MINUTES`; просмотр считается активностью) и по жёсткому сроку (`expires_at` строки и `BROWSER_SESSION_MAX_HOURS`); при остановке процесса все сессии закрываются как `lost` (`shutdown`) — вход нужен заново (Б18, Б19). Ничего из сессии не переживает перезапуск: при старте процесс удаляет контейнеры, оставшиеся от прежнего, а `ensure` сессии, которую запускал прежний процесс, закрывает её `lost` и отвечает `BROWSER_SESSION_UNAVAILABLE`.
- **Health и метрики** (`src/health`, `src/metrics`): `/health` — база и Docker (список контейнеров сессий), подробности — с `METRICS_TOKEN`; `/metrics` — с `METRICS_TOKEN`: `raditi_browser_sessions`, `raditi_browser_viewers`, `raditi_browser_frames_sent_total`, `raditi_browser_frames_dropped_total{reason}`, `raditi_browser_actions_total{tool,result}`; идентификаторов в метках нет. Логгер — `browser`. В журнал не попадают ввод, адреса, кадры, токен и управляющий путь Chromium.

## Что читает

`APP_ENV`; `DATABASE_URL`; S3 — `S3_ENDPOINT`, `S3_REGION`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_FORCE_PATH_STYLE` и только `S3_BUCKET_INBOX`; `METRICS_TOKEN`; `BROWSER_WORKER_HOST` (IP; пусто — 127.0.0.1 вне production, все адреса в production), `BROWSER_WORKER_PORT` (8086), `BROWSER_WORKER_TOKEN` (обязателен, от 32 до 4096 видимых знаков ASCII без пробелов — то же правило, что у `core`, `mcp` и `preview`); `BROWSER_RUNTIME` (`runc` или `runsc`, в production только `runsc`), `BROWSER_DOCKER_SOCKET`, `BROWSER_IMAGE`, `BROWSER_FORWARDER_IMAGE`, `BROWSER_EGRESS_IMAGE` (по digest, все три или ни одного; без них вне production процесс стартует, но сессий не даёт), `SANDBOX_NETWORK_GUARD_IMAGE` (под `runsc`), `SANDBOX_EGRESS_REFUSED_SUBNETS` (в production обязателен); `BROWSER_EXTRA_HOSTS`, `BROWSER_LOCAL_SITES` (только вне production: JSON `{"http://<имя>[:порт]": "<хост>:<порт>"}`); `BROWSER_SESSION_IDLE_MINUTES` (30), `BROWSER_SESSION_MAX_HOURS` (4), `BROWSER_MAX_SESSIONS` (8), `BROWSER_STREAM_MAX_FPS` (12), `BROWSER_STREAM_QUALITY` (70), `BROWSER_STREAM_WINDOW` (2). Vault, Redis, git и настройки ходов не читает.

## Команды

- `pnpm --filter browser dev` (в `pnpm dev` запускается сам: `turbo run dev`), `build` (сначала собирает `@repo/service-runtime`), `start`, `typecheck`, `lint`, `test`. Стендов одного этого приложения нет: `pnpm verify:browser-task` ведёт несколько приложений и лежит в `infra/dev/browser-task-verify`.
- Тест с настоящими Docker и Chromium: `RADITI_BROWSER_DOCKER_TESTS=1 pnpm --filter browser exec vitest run src/browser-worker.docker.test.ts` — сессия на крошечном локальном сайте через `BROWSER_LOCAL_SITES`, кадры по потоку, клик вводом, уборка. Образы — те же, что у `verify:preview-network` (`raditi-preview-browser:local`, `raditi-preview-tools:local`, `raditi-client-egress:local`); недостающие тест собирает сам.
- Образ — `apps/browser/Dockerfile`, цель `runtime`; его собирает и проверяет снаружи `pnpm verify:images` (`images.yml`): `node dist/main.js` от uid 10001 отказывает в пустой конфигурации под логгером `[browser]`, нет `git`, `gitleaks`, `.env`, стендов и запрещённых пакетов (`browser-link` в образе есть только как зависимость тестов). Процессу нужен доступ к сокету Docker сессий (группа сокета) и loopback того же хоста: управляющие порты Chromium публикуются на `127.0.0.1`.

## Размещение

В production процесс должен работать рядом с Docker под `runsc` (песочная ВМ), а app-ВМ ходит к нему по частной сети; это и канал app-ВМ ↔ `browser` — задача M10 (Б30). До неё `apps/browser` работает локально и на стендах; в compose app-ВМ его нет.

## Чего не должно достигать

- Vault, git, агента, модели, платежей, почты, кода ходов и содержимого сайта (`browser-minimal-packages`, даже транзитивно), `@repo/trpc` и `@repo/ui` (`llm-no-trpc-ui`), других приложений (`apps-are-isolated`); свой код импортирует только Nest, типы express, `ws`, `zod` и клиент Prometheus (`browser-npm`) — Playwright и Docker только через адаптеры.
- Профиля, cookies и `storageState` браузера: вход живёт только в эфемерном контексте (Б19).
