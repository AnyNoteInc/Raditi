# Образы предпросмотра

Предпросмотр диалога ([план 53](../../docs/plan/53-chat-preview-release.md), Р18, Р21) запускает среда `createDockerPreviewRuntime` из `@repo/sandbox-providers` (`packages/sandbox-providers/src/preview`). С 26.10.2026 предпросмотр — один контейнер образа `site` ([план 58](../../docs/plan/58-preview-single-container.md)): PHP, его база и шлюз входа. Публичный образ остался один — MariaDB временной базы дампа (`PREVIEW_DB_IMAGE`), по digest, его значение для разработки — в `.env.example`. Три образа собираются из этой папки (`Dockerfile`, контекст — сама папка):

| Цель | Переменная | Что внутри |
| --- | --- | --- |
| `tools` | `PREVIEW_FORWARDER_IMAGE` | Node 26.10 и tini; `forward.mjs` — пересыльщик браузера агента (шлюз входа — тот же скрипт в образе `site`), `files.mjs` — запись дерева в том docroot; метка срока предпросмотра |
| `browser` | `PREVIEW_BROWSER_IMAGE` | Chromium образа Playwright 1.63.0, `playwright-core` 1.63.0 из `browser/package-lock.json` (`npm ci`, без скриптов установки), `browser-server.mjs` |
| `site` | `PREVIEW_SITE_IMAGES` (по версии PHP) | Предпросмотр одним контейнером ([план 58](../../docs/plan/58-preview-single-container.md), §10): PHP и Apache образа `BASE` (WordPress одной версии PHP по digest), MariaDB 11.8.9, WP-CLI 2.12.0, Node 26.10 из цели `tools`, tini; `init.sh`, `run-as.sh`, `forward.mjs`, `dns.mjs` |

Образ `site` собирается на версию PHP: `--build-arg BASE=wordpress@sha256:…` (по умолчанию — PHP 8.3, тот же digest, что в `.env.example`):

```sh
docker build -f infra/preview/Dockerfile --target site \
  --build-arg BASE=wordpress@sha256:8ae73d594a154e30b112e8d085afbc0895acf7651d8f53ef63aefb42e30822d5 \
  -t "raditi-preview-site:8.3-local" infra/preview
```

MariaDB — из архива mariadb.org по точной версии, ключ проверяется отпечатком `177F 4010 FE56 CA33 3630 0305 F165 6F24 C74C D1D8` (`mariadb-release-signing-key.asc`, проверку держит `site.test.mjs`). Версия 11.8, а не 11.4, как у `PREVIEW_DB_IMAGE`: 11.4 для Debian 13 (trixie), на котором стоят образы PHP 8.2 и новее, не собирается, а 11.8.9 есть и для bullseye, и для bookworm, и для trixie. Временная база дампа (`PREVIEW_DB_IMAGE`, `StagingDatabaseRuntime`) остаётся на 11.4: копия переносит данные запросами SQL, версии не обязаны совпадать.

```sh
for target in tools browser; do
  docker build -f infra/preview/Dockerfile --target "$target" -t "raditi-preview-${target}:local" infra/preview
done
docker image inspect --format '{{index .RepoDigests 0}}' raditi-preview-tools:local raditi-preview-browser:local
```

Digest локальной сборки есть только в хранилище образов containerd (Docker Desktop — по умолчанию, на Linux — `"features": {"containerd-snapshotter": true}`); на каждой машине он свой, поэтому в `.env.example` эти три переменные пусты (`PREVIEW_SITE_IMAGES=8.3=<digest raditi-preview-site:8.3-local>`). Предпросмотру нужен ещё образ правил хоста `SANDBOX_NETWORK_GUARD_IMAGE` (цель `network-guard` из `infra/sandbox/Dockerfile`) — при любом `PREVIEW_RUNTIME`, без него предпросмотр не настроен. В переменные пишется вывод последней команды — `raditi-preview-tools@sha256:…`; ссылка с тегом (`имя:тег@sha256:…`) схемой не принимается. После правки скриптов образ пересобирается и digest переписывается: среда проверяет только digest, не содержимое. В zsh имя пишется `"raditi-preview-${target}:local"` — без скобок `$target:l` читается как модификатор.

## Контейнер `site`

Среда запускает его от `0:0` только с `SETUID`, `SETGID` и `SETPCAP`, `no-new-privileges`, read-only корнем и sysctl `net.ipv4.ip_unprivileged_port_start=0`; tmpfs — `/run/raditi/preview` (33), `/run/raditi/db` (999), `/run/mysqld` (999, 0755), `/run/raditi-forward` (10001), `/run/raditi/ready` (0:0, 0755), `/tmp` (1777); тома — `/var/www/html` и `/var/lib/mysql`; окружение — `RADITI_HTTP_HOST`, `RADITI_WEB_PORT`, `RADITI_DATABASE`, `RADITI_DNS_SERVERS` и `env` рецепта; `Cmd` — команда веб-сервера рецепта.

- `init.sh` (под tini, PID 1): проверяет окружение (DNS — код 70, остальное — 64) и запускает `dns.mjs`. При `RADITI_DATABASE=1` ждёт файлы паролей, при первом старте создаёт базу — `mariadb-install-db` от 999, пользователь `preview` с `127.0.0.1` и `localhost`, root — `unix_socket` или пароль, только `localhost`; SQL первого старта — файл `--init-file` на tmpfs 999, он удаляется, как только сервер ответил; данные без метки `.raditi-ready` создаются заново — и запускает `mariadbd` (только `127.0.0.1:3306`, `skip-name-resolve`, `innodb_use_native_aio=0`, `max_allowed_packet=64M`). Затем ждёт файл настроек и запускает команду веб-сервера от 33 — её вывод идёт через трубу того же uid, иначе Apache не откроет `/proc/self/fd/2` заново, — и `forward.mjs` от 10001 (`0.0.0.0:8080` → `127.0.0.1:$RADITI_WEB_PORT`, `--http-host`). Каждая служба — через `setpriv` с пустым набором возможностей и `no-new-privs`; файлы готовности — `/run/raditi/ready/db`, `/run/raditi-forward/ready`, `/run/raditi-forward/dns.ready`. После этого init сам отказывается от возможностей и следит: служба кончилась — init выходит с кодом 1, и контейнер останавливается со всем, что в нём было; на SIGTERM (`STOPSIGNAL` образа — SIGTERM, у базового образа — SIGWINCH) init останавливает базу (`SHUTDOWN` от root через сокет) и выходит с 0. Пароли не попадают ни в аргументы, ни в окружение, ни в журнал. Сам tini (PID 1) остаётся root с теми тремя возможностями: он только собирает процессы.
- `run-as.sh <uid:gid> <секунды> -- <argv…>` (`docker exec -u 0:0`): команда платформы от `uid:gid` без возможностей, в своей сессии; по её концу или по сроку вся её группа процессов убивается (тот же uid — `KILL` не нужен); код — команды, по сроку — 124. stdin, stdout и stderr проходят насквозь.
- `dns.mjs <IPv4>[,…]`: Docker даёт контейнеру пользовательской сети `nameserver 127.0.0.11` — свой DNS, до которого сетевой стек gVisor не доходит, а read-only корень не даёт заменить `/etc/resolv.conf` ни под `runc`, ни под `runsc` (замер 26.10.2026). Пересыльщик слушает `127.0.0.11:53` (UDP и TCP) внутри контейнера и передаёт запросы как есть серверам `RADITI_DNS_SERVERS` по очереди (2 с на сервер, не больше 256 запросов сразу); под `runc` раньше него там отвечает DNAT Docker.

## Что делает каждый скрипт

- `forward.mjs [--http-host=<имя>] <IPv4>:<порт>=<цель>:<порт> …` — до четырёх маршрутов, у каждого одна неизменная цель; не больше 256 соединений на маршрут, простой 10 минут. После того как слушают все маршруты, пишет `/run/raditi-forward/ready`. Пересыльщик браузера передаёт только байты. Пересыльщик входа (`--http-host=<hostname предпросмотра>`) читает ещё заголовок первого запроса соединения — он приходит от платформы (шлюз, роль `mcp`), не от предпросмотра: запрос к другому `Host` получает `421 Misdirected Request` и до PHP не доходит, искажённый — `400`; прошедший уходит с `Connection: close` вместо заголовков соединения, так что следующий запрос из пула шлюза приходит новым соединением и тоже проверяется (запрос `Upgrade` идёт как есть — туннель один). Ответ PHP не разбирается. Зачем: опубликованный порт принадлежит предпросмотру, только пока жив его контейнер; у остановленного — и после перезапуска dockerd — Docker отдаёт порт следующему, и вызывающий со старой строкой `upstream` получил бы чужой сайт.
- `files.mjs init <uid>:<gid>` — отдаёт том docroot пользователю PHP (запуск от root только с `CAP_CHOWN`). Среда зовёт его при каждой сборке: том этого пользователя остаётся как есть (владелец смотрится `lstat`, без открытия — PHP мог закрыть каталог и от root без `DAC_OVERRIDE`), пустой том root — отдаётся, том другого пользователя или с файлами — отказ `root_owner` (среда отвечает `CONFLICT`: предпросмотр уничтожают и собирают заново). Так сборка, упавшая между созданием тома и `init`, чинится следующей. `files.mjs write` — кадр `<u32 длина><JSON {replace, deletes}>` и tar на stdin: только обычные файлы и каталоги (ustar, pax `path`, GNU long name), отказ ссылкам, устройствам, `..`, абсолютным путям, не-UTF-8 и записи через существующую ссылку на любом участке пути (каждый каталог открыт без перехода по ссылкам, следующее имя — под его дескриптором). Права корня docroot, которые PHP отнял у себя же, возвращаются (`u+rwx`). Причина отказа — слово из фиксированного списка в stderr (`refused: path_conflict`), код 3; пути не печатаются.
- `browser-server.mjs` (в образе — `/usr/local/lib/raditi/browser/server.mjs`) — ждёт секретный путь в `/run/raditi/browser/ws-path` (его пишет среда после старта), запускает `chromium.launchServer` на адресе сети браузера, с `--proxy-server=<пересыльщик>`, `--proxy-bypass-list=<-loopback>`, `--force-webrtc-ip-handling-policy=disable_non_proxied_udp`, без `--remote-debugging-port`; затем пишет `/run/raditi/browser/ready`.

## Хост предпросмотров

- **Пулы адресов Docker.** Каждый предпросмотр занимает свою сеть `rpv…`, а пока работает браузер — ещё `rpb…`; живут они до 72 часов. Пулы Docker по умолчанию (пятнадцать `/16` в 172.17–31 и шестнадцать `/20` в 192.168) общие с compose и сетями попыток песочницы, и на них хост упирается примерно в 15–25 предпросмотров с браузером — дальше `ensure` падает общей ошибкой Docker. На машине, где работают предпросмотры (в облаке — песочная ВМ), в `/etc/docker/daemon.json` задаются мелкие подсети, как для сетей попыток (spec §8): `"default-address-pools": [{"base": "10.200.0.0/16", "size": 28}]` — 4096 сетей; `/28` — самая мелкая сеть, которую принимает среда (`subnetAddress`), браузеру нужны `.2`–`.3`, предпросмотру — один адрес. Проверку этого в preflight песочной ВМ добавит M10.
- **gVisor и `PidsLimit`.** Под `runsc` предел pids хоста считает потоки ядра песочницы (sentry), а не процессы предпросмотра: среда поднимает его до 128 (`RUNSC_MIN_PIDS`). Замер 17.10.2026 (Colima, 4 vCPU): при 32 пять из восьми запусков Node в новом контейнере кончились `WaitPID failed: EOF`.
- **Где шлюз для браузера.** Пересыльщик браузера шлёт прокси-трафик на `host.docker.internal:PREVIEW_GATEWAY_PORT` (`host-gateway` демона — исполнитель `local`). Если `host-gateway` указывает на другую машину (Colima указывает на Mac) — и для исполнителя `runner` (M10) — среде передаётся адрес шлюза (`gatewayHost`, IPv4).
- **Свой мост и правила хоста** (план 58). Контейнер предпросмотра стоит на своём мосту `rpv…` — не internal (с internal-сети Docker порт не публикует), без IPv6 и ICC; его интернет открыт. Что PHP не достаёт хост, мост по умолчанию с пересыльщиками браузера, частные, link-local и прочие непубличные адреса, подсети платформы (`SANDBOX_EGRESS_REFUSED_SUBNETS`) и чужие предпросмотры, держат правила хоста на этом мосту (`infra/sandbox/host-firewall.mjs`: `INPUT` — только ответы на соединения хоста, своя цепочка из `DOCKER-USER`), которые среда ставит и проверяет до старта контейнера при любом runtime, а сборщик `core` перепроверяет у работающих предпросмотров раз в 2 минуты (`checkBoundary`: не целы — контейнер останавливается и собирается заново). Порт шлюза опубликован на `PREVIEW_UPSTREAM_HOST`; шлюз входа внутри пускает только `Host` своего предпросмотра. Пересыльщик браузера стоит на мосту Docker по умолчанию и в сети браузера `rpb…`.

## Проверки

- `pnpm test:infra` — разбор маршрутов, проверка `Host` и пересылка, разбор tar и кадра, подготовка тома, аргументы браузера; запись дерева проверяется только на Linux (`/proc/self/fd`).
- `RADITI_PREVIEW_DOCKER_TESTS=1 pnpm --filter @repo/sandbox-providers exec vitest run src/preview/runtime.integration.test.ts` — среда на настоящем Docker с образами `raditi-preview-site:8.3-local`, `raditi-preview-tools:local`, `raditi-preview-browser:local` и `raditi-network-guard:local` (или `SANDBOX_NETWORK_GUARD_IMAGE`); `PREVIEW_RUNTIME=runsc` — под gVisor, `SANDBOX_DOCKER_SOCKET` — другой демон (например, Colima: `~/.colima/<профиль>/docker.sock`).
- `pnpm verify:preview-network` — сеть предпросмотра со всех сторон ([README стенда](../dev/preview-verify/README.md)).
- В CI — `.github/workflows/preview.yml`.
