# Стенд сети предпросмотра

`pnpm verify:preview-network` ([план 53](../../../docs/plan/53-chat-preview-release.md), Р18, Р21) строит настоящей средой `createDockerPreviewRuntime` два предпросмотра (A и B) и браузер предпросмотра A и проверяет пути: с хоста, из контейнера PHP, из контейнера браузера и из самого Chromium. Шлюз предпросмотров играет маленький HTTP-сервер стенда на `PREVIEW_GATEWAY_PORT` (8090, если порт свободен); службы хоста на 5432, 8200, 8085 и 8090, которых нет, стенд поднимает сам на время проверки.

Прогон проходит, только если прошла каждая строка (`PASS`), иначе код 1:

- у каждой строки «закрыто» есть контроль — та же цель из контейнера на мосту по умолчанию, а для опубликованного на loopback — с самого хоста; цель, которую не достал и контроль, ничего не доказывает (`VACUOUS` — провал);
- имя (`host.docker.internal`, `example.com`) должно не разрешаться вовсе (`dns`): разрешённое внутри имя — путь наружу через DNS, даже при закрытом порте; контролю достаточно имя разрешить;
- проба, которая не выполнилась (`error`: контейнер упал, нет `php` или `node`), — провал, а не «закрыто»;
- из PHP и из браузера есть строки «доступно» (свой сервер, свой пересыльщик входа, пересыльщик браузера): сломанная проба видна сразу;
- у предпросмотра A есть прокси выхода переменных клиента (Р13, `infra/sandbox/README.md`): строка через прокси засчитывается «закрытой», только если прокси отказал по ожидаемой причине (`forbidden_host` — не из списка, `forbidden_address` — имя из списка разрешилось в непубличный адрес); отказ по другой причине (имя не разрешилось, срок) — провал.

Нужны Docker, образы `wordpress:7.1.2-php8.3-apache`, `wordpress:cli-php8.3` (оба — по digest из стенда) и базовые образы `infra/preview/Dockerfile` и `infra/sandbox/Dockerfile`; стенд собирает `raditi-preview-tools:local`, `raditi-preview-browser:local` и `raditi-client-egress:local` (цель `client-egress`; `--no-build` — взять собранные). Строки прокси выхода ходят в интернет и к публичному DNS: `example.com`, `localtest.me` (127.0.0.1) и `*.nip.io` (имя — запись адреса); `.env` не читает, ничего не тянет, по окончании удаляет всё своё (`--keep` — оставить). `--runtime=runsc` — то же под gVisor на Linux, с `SANDBOX_NETWORK_GUARD_IMAGE` (образ `network-guard` из `infra/sandbox/Dockerfile`, по digest): среда ставит правило `INPUT -i rpv…/rpb… -j DROP` на хосте.

Службы стенда слушают там, куда контейнеры ходят как на хост (`host-gateway`): на macOS — loopback (Docker Desktop ведёт туда `host.docker.internal`), на Linux — сам адрес `host-gateway`. Если он не принадлежит этой машине (Colima ведёт `host-gateway` на Mac), службы и шлюз слушают адрес моста `docker0`, а пересыльщику браузера среда передаёт этот адрес (`gatewayHost`) — стенд печатает об этом строку.

  -v "${R}:${R}:ro" -w "${R}" --entrypoint /usr/local/bin/node raditi-preview-tools:local \
