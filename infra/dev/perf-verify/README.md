# Замеры чата: от базы до экрана

`pnpm perf:chat [-- --out <файл.json>] [--label <метка>] [--keep]` — замеры ленты чата на одноразовой
PostgreSQL 17 с `pg_stat_statements` (`perf.mjs`). Скрипт поднимает базу на случайном порту `127.0.0.1`
(`--pull=never`, образ закреплён по digest), применяет миграции и сиды, генерирует клиент Prisma и
запускает набор `packages/trpc/src/routers/chat-feed.perf.test.ts` с `RADITI_PERF_BENCH=1`. `.env`,
dev-инфраструктура и модель не используются; данные только синтетические.

Набор засевает чаты без проекта тем объёмом, который оставляют настоящие ходы: на ход — слова клиента, шаг
`work`, журнал хода (8 строк `turn.lifecycle` и 200 строк `turn.output` с растущим черновиком) и
ответ. Чаты: короткий (3 хода), длинный (120 ходов, около 25 тысяч строк `task_events`) и восемь
работающих (40 ходов и идущий ход с 600 строками вывода). Вызываются настоящие процедуры
`task.feed` и `task.activity` через `createCaller` — то, что делает страница:

| Сценарий | Что это на экране |
| --- | --- |
| `openShort`, `openLong`, `openRunning` | открыть чат: до последних сообщений на экране |
| `pollRunning`, `pollWaiting` | пустой опрос открытого чата: агент работает или чат ждёт клиента |
| `activityReload` | перезагрузка во время хода: «Ход работы» с начала |
| `activityPoll` | пустой опрос «Хода работы» (раз в секунду) |
| `concurrentRound` | восемь открытых чатов опрашивают ленту и работу хода одновременно |

На каждый сценарий — p50 и p95 времени вызова, число вызовов, число операторов SQL (всех и только
обращений к данным), время БД по `pg_stat_statements`, строки и CPU процесса. В `sql` отчёта — тексты
операторов одного вызова (`pollRunning`, `pollWaiting`, `openLong`). Сеть, авторизация better-auth и
отрисовка в браузере в замер не входят: это время сервера ленты.

Как сравнивать: прогнать на коммите до и после изменения на одной машине, без других стендов
Docker рядом, и сравнить `summary` двух отчётов. В CI набор идёт в `perf.yml` — только на правки
стенда и чтения ленты (`feed.ts`, `dialog-facts.ts`, `dialog-state.ts`, `activity.ts`), а не на каждую
правку tRPC и базы, и вручную (`workflow_dispatch`): числа — в артефакте `perf-chat-feed`, красным job
делает только сбой самих замеров. Перенос ускорений — [план 86](../../../docs/plan/86-speedups.md).
