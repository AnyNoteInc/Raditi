# Стенд браузера чата: чат без проекта, открытый интернет, страницы агента

```sh
pnpm verify:browser-task                     # сборка копии дерева и образов, затем сценарии S, P, K, L, Q, R, M
pnpm verify:browser-task -- --no-build       # те же сборки ещё раз; отказ, если дерево изменилось после них
pnpm verify:browser-task -- --keep           # оставить стенд поднятым после сценариев (и после провала) до Ctrl-C
pnpm verify:browser-task -- --only P,K       # только названные сценарии и те, без которых они не идут
pnpm verify:browser-task -- --web-dev        # web — `next dev` копии вместо `next build`
pnpm verify:browser-task -- --stream-only    # без кабинета: клиент действует только по потоку шлюза
```

Стенд проходит браузер чата ([план 57](../../../docs/plan/57-browser-tasks.md), §5; [план 61](../../../docs/plan/61-chats-first.md), §8) на этой машине — macOS, Docker Desktop, `runc` — только на одноразовых сервисах. С [плана 83](../../../docs/plan/83-remove-projects.md) проектов нет: синтетического WordPress, сценариев сайта (A–J), `/undo` и `/redo` с черновиком на сайте (N, O) и проверок входа на сайт у стенда больше нет — остались чаты без проекта. Агент — настоящий OpenCode CLI в песочнице на сценарной модели (`programs.mjs`), браузер — настоящий Chromium в контейнерах процесса `browser`. Каждая строка `PASS` — факт, прочитанный из состояния продукта (база, лента, API процесса `browser`, поток шлюза, страница кабинета, слушатель страниц) или того, что держат S3 и Docker. Строка `NOTE` — не проверка. В конце печатается таблица сценариев с числом проверок.

## Что поднимается

Всё одноразовое, со своим именем `raditi-browser-task-verify-<run>-…` и меткой `io.raditi.browser-task-verify=<run>`:

- PostgreSQL 17 (данные в памяти), Redis 8, SeaweedFS с бакетами `raditi-*`, OpenBao с mounts и политиками `infra/vault/bootstrap.mjs` и AppRole на процесс (`core` — `core-turns`, `core-transit`, `core-workspace-env`, `core-git`; `mcp` — `mcp-content`; `llm`; web — `sites-writer`, `workspace-provisioner`) — `services.mjs`; общие части времени выполнения — `runtime.mjs` (оба пришли из стенда выпуска, удалённого вместе с проектами).
- Процессы платформы из сборки приватной копии дерева (`$TMPDIR/raditi-browser-task-verify-build`): `llm`, `browser`, `mcp` (семейство `web` и страницы агента), `preview` (шлюз трансляции и слушатель страниц), `core` — `node dist/main.js`, каждый своим процессом, `TURN_EXECUTOR=local` под `runc`; web — `next build` (standalone) или `next dev` копии (`--web-dev`). `NODE_ENV=production` у всех: ни один процесс не ищет `.env`.
- Образы этого дерева под своими именами, по digest: песочница хода, её шлюз и сторож (`infra/sandbox/Dockerfile`), прокси выхода `client-egress`, инструменты и браузер (`infra/preview/Dockerfile`) — три контейнера браузерной сессии.
- Синтетический Z.ai (`model.mjs`) в процессе стенда за TLS сертификатом стенда; аккаунт плана импортирует настоящая команда оператора `subscriptions:login`, ставки и курс кредита пишет `billing:rates`.
- Кабинет — Chromium Playwright копии с cookie сессии владельца, окно 1440×1000 (`cabinet.mjs`).

## Что нужно

Docker Desktop с хранилищем образов containerd (ссылки на собранные образы — по digest), Node 26.10, pnpm, `git`, `rsync`, `openssl`, интернет (`example.com:443`) и уже загруженные образы — стенд ничего не тянет: `chrislusf/seaweedfs:4.47`, `postgres:17.11-alpine3.24`, `redis:8.10.2-alpine`, `ghcr.io/openbao/openbao:2.7.0` (digest — в `stand.mjs` и `../billing-verify`). Не рядом с другим стендом Docker, `pnpm dev` или `pnpm e2e`: другой `core` с `TURN_EXECUTOR=local` удаляет песочницы ходов стенда при одинаковой метке развёртывания `SANDBOX_DEPLOYMENT`, а другой процесс `browser` при старте снимает браузерные сессии стенда. `.env` и dev-инфраструктура не используются; workflow CI нет.

`BROWSER_TASK_VERIFY_STALE_COPY=allow` вместе с `--no-build` пускает прогон на копии, собранной из другого состояния дерева: такой прогон печатает `NOTE` и ничего не доказывает о дереве.

## Что не проверено

- Linux и gVisor (`runsc`): стенд идёт только на Docker Desktop; путь `runsc` облачного браузера проверяют тесты `@repo/sandbox-providers` и `browser.yml`.
- Настоящая модель: ходы — программы сценарной модели.
- `web_upload` файла чата на страницу: на публичных сайтах стенда поля файла нет, а локальных сайтов у браузера больше нет (`BROWSER_LOCAL_SITES` удалён с планом 83); путь закрывают тесты `apps/browser` и `@repo/browser-providers`.
- Узкий экран (ниже `lg`), сроки простоя и жизни сессии, потеря процесса `browser` — тесты `apps/browser`, `@repo/browser-providers` и компонентов web.
