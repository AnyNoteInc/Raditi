# Стенд группы ВКонтакте — `pnpm verify:vk`

План — [docs/plan/99-vk-community.md](../../../docs/plan/99-vk-community.md), срез 99.8.

Стенд проверяет путь группы ВКонтакте целиком на настоящих классах и настоящих хранилищах:

- одноразовая PostgreSQL со всеми миграциями и сидами;
- одноразовый OpenBao с монтированиями, политиками и AppRole платформы (`infra/vault/bootstrap.mjs`);
- подделка `api.vk.com` в процессе стенда (`fake-vk.mjs`): методы, которые зовёт Радити, с теми видами ключей, что принимает VK по своей схеме.

Классы `core` и `mcp` берутся из их `dist` (скрипт сначала собирает оба), пакеты — из исходников. Каждая сторона держит токен Vault только своей политики, как в production: `web` — `sites-writer`, `core` — `core-vk`, `mcp` — `mcp-content`. Рабочий `.env` стенд не читает; ключи VK, секрет карточек и пароли — случайные, в выводе их нет.

## Сценарии

| | Что проверяется |
| --- | --- |
| V1 | Подключение группы по ключу: ключ только в Vault, строка без ключа, `sites-writer`, `mcp-content` и `llm-subscriptions` его не читают; сервер Callback API Радити зарегистрирован с выведенным секретом |
| V2 | Агент читает стену, комментарии и сводку сервисным ключом из Vault; автор комментария — «reader 1», не id ВКонтакте; `llm-subscriptions` сервисный ключ не читает |
| V3 | Предложение поста ничего не публикует; карточка после хода; нажатие пишет строку и задание; `core` публикует правленый текст ключом из Vault; карточка публикуется один раз; строку без нажатия (чужая подпись) `core` отклоняет, во ВКонтакте ничего не уходит |
| V4 | Ответ на комментарий уходит под комментарий своей карточки, от группы |
| V5 | Новый комментарий: одно задание на владельца в окне 10 минут, одна строка `chat_notifications` без письма |
| V6 | Выключатель: выключенный сервер не предлагается, включается без нового ключа; отключение стирает ключ, последняя группа выключает сервер, нажатия остаются |

Вебхук `web` (`apps/web/src/server/vk-callback.ts`) — код Next с `server-only`; его закрывают unit-тесты, а не стенд.

## Запуск

```sh
docker pull postgres:17.11-alpine3.24@sha256:b0f9560a2de083e2cc7382e75f808c7381a32852a7ec49117deedb300e552b24
docker pull ghcr.io/openbao/openbao:2.7.0@sha256:71156a1c6623a5fa3f5e61b0c6a8ead0faf0df29a778339188443551995d1315
pnpm verify:vk
```

Стенд образы не скачивает. Контейнеры помечены `io.raditi.vk-verify=<run>` и удаляются в конце, в том числе после сбоя; последняя строка — `PASS disposable PostgreSQL, OpenBao and the fake of VK removed`. Около минуты после сборки.

`fake-vk.test.mjs` — тесты подделки, они идут в `pnpm test:infra`.
