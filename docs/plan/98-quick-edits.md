# 98. Быстрая правка по заметке артефакта

Запрос владельца от 27.11.2026 (дословно):

> изучи проект, давай подумаем над тем, как можно сделать выполнение в режиме чат, не создавай и не запуская харнес на opencode, а сделать сразу вывод информации из чата, с ограниченными возможностями, конечно же, однако для чего это нужно / внутри артефактов есть правки и там хочется нажать на правку и быстро ее сделать с помощью агента затратив на это минимальное количество ресурсов, давай подумаем и прежложи варианты реализации

Ответ владельца на предложенные варианты (27.11.2026): «оформляй и вперед». Решения без слов владельца помечены «По умолчанию» — по его указанию от 09.10.2026 («принимай все решения по умолчанию»); они ждут его ответа в §9.

**Статус.** План принят, реализация — ветка `feat/quick-edits`, отчёт — §10.

## 0. Коротко

1. На открытой заметке «Документа» есть кнопка **«Исправить»**. Она не запускает ход OpenCode: `core` сам собирает раздел с заметкой (~1,5–2,6 тыс. токенов), **один раз** вызывает модель через роль `llm` на бэкенде `zai-api`, применяет ответ как запись агента и проверяет её до показа тем же `ArtifactChecks.settle`.
2. Песочницы, раннера, снимков S3, записи в Vault, аренды хода нет. Задержка — секунды вместо минуты-двух, модель стоит платформе ≈0,25–0,4 ₽ вместо 1,1–5,4 ₽ за проход.
3. Правка — **попытка служебной задачи «Быстрые правки»** нажавшего (`tasks.kind = 'quick_edits'`, одна на человека и пространство). В этой задаче никогда не бывает ходов OpenCode, поэтому цепочка снимков чатов не затрагивается по построению.
4. Актор записи — `agent{taskId: быстрая задача, turnNo: attempt}`. «Отменить правки агента», история версий и проверка до показа работают без изменений.
5. Деньги — через тот же `credit_holds`/`chargeTask` (правило 7). Первый этап: 1 кредит за правку. Второй: сквозное округление по задаче (≈14–25 правок на кредит).

## 1. Зачем

Сейчас «Отправить агенту» по одной заметке — полный проход: очередь, контейнер 2 CPU / 4 ГиБ, снимок из S3, ключ хода в Vault, OpenCode с ~18 КБ инструкций, 3–5 вызовов модели по ~35 тыс. токенов, живая проверка, сохранение снимка. Это ~40 с – 2 мин и 1–2 кредита за «сократи абзац».

| | Сейчас | Быстрая правка |
|---|---|---|
| Задержка | ~40 с – 2 мин | p50 ≈ 4–8 с, p95 ≈ 12–20 с (оценка, этап 0 измеряет) |
| Вызовы модели | 3–5 × ~35 тыс. входа | 1 (повтор ≤ 1): ~1,5–2,6 тыс. входа, 250–450 выхода |
| Песочница, S3, Vault (запись) | да | нет |
| Платформе | ≈1,1–1,4 ₽ на плане, 3,4–5,4 ₽ на API | ≈0,25–0,4 ₽ на API |
| Клиенту | 1–2 кредита | 1 кредит (этап 1), ≈1/14–1/25 кредита (этап 2) |

## 3. Решения

- **БПр1. Прямой вызов модели из `core` — только как действие артефакта, только на `zai-api`.** Это частично возвращает П13 (spec §20) как действие, а не режим; К1 плана 61 остаётся. Условия плана GLM Coding Plan запрещают вызывать его из своих приложений (Ар32, план 88:603), поэтому ключ быстрой правки привязан к аккаунту драйвера `quick`, который есть только у `zai-api`, а шлюз пускает клиента платформы только к `zaiApiOffer`. По умолчанию.
- **БПр2. Служебная задача.** `tasks.kind` (`chat` | `quick_edits`), частичный уникальный индекс — одна живая задача «Быстрые правки» на (пространство, автор). CHECK: у `quick_edits` нет `chat_session_id`, `project_id`, браузера и `reverts_task_id`, задача платная. Статусы — только `queued → preparing → running → awaiting_user` (§7), никогда не терминальна.
- **БПр3. Охранник во всех путях хода.** Ход OpenCode в задаче `quick_edits` не ставится никогда: отказ в `underDialogLock` (postDialogMessage, continueDialog, resumeDialog, agentCommandDialog, undo/redo), в `claimQueuedPass`/`PassRunner.run` (задание отбрасывается), в `queue-drain`, Telegram; `TaskSweep.settleOrphans` и `requeueLost` выбирают только `kind = 'chat'`. Задача не входит в `WORKSPACE_TURN_LIMIT` и не попадает в список чатов для «Отправить агенту».
- **БПр4. Профиль модели с флагом.** `llm_models.quick boolean` (CHECK `NOT (quick AND vision)`). `classProfile`, выбор профиля по зрению, `firstCallReserve` и цены класса берут только `quick = false` — иначе профиль с резервом 2 000 (сортировка по slug, class-profile.ts:25-41) достался бы ходу OpenCode. Профиль `glm-5.3-quick`: `zai-api`, `glm-5.3`, класс `light`, `reasoning_effort = low`, `reserve_output_tokens = 2000`.
- **БПр5. Ключ быстрой правки.** Строка `llm_keys` с `task_id` быстрой задачи, `turn_no = attempt`, `session_id = 'quick-<id>'`, `driver_id = 'quick'`, срок 90 с; секрет — только в памяти `core` (в базе хэш), в Vault не пишется (правило 2 соблюдено: секрета вне Vault нет, кроме памяти процесса на время вызова — как у шлюза). Без аренды и назначения хода. Бюджет — 2 × резерв вызова по оценке промпта, не больше бюджета резерва попытки. После вызова ключ отзывается.
- **БПр6. Шлюз.** Клиент `platform` (UA `raditi-platform/1`) для драйверов `quick`; провайдеру уходит честный UA. `max_tokens` режется до резерва профиля ключа (порт `LlmBackend.normalizeBody` получает `reserveOutputTokens`); ключам OpenCode это ничего не меняет (32 000).
- **БПр7. Протокол модели.** Постоянный системный текст (англ.) + одна функция `apply_edit {outcome: edited|no_change|needs_agent, edits[≤20]: {part, p, find?, to}, reply ≤ 500}`; `tool_choice: auto`, поток. Разбор — zod strict, не больше одного повтора с tool-сообщением об ошибке. Контекст: исходник Markdown раздела с пронумерованными абзацами, номер абзаца, где найдена цитата, текст заметки и ответы. Нормализатор цитаты переносится из `trpc` в `domain`.
- **БПр8. Что можно менять.** Только блоки якорей выбранных заметок, только абзацы внутри них; неизменённые абзацы совпадают побайтно. Код отказывает, если в правке появились URL, адреса почты или телефоны, которых нет ни в исходнике, ни в заметке. Запись — `applyArtifactOps` с актором агента в `pending_*`, затем `ArtifactChecks.settle` с `textRefusal([ключ], значения переменных)`; при сбое чтения значений из Vault запись сбрасывается (как в проходе). Итог проверки читается по блоку, а не по возвращаемому значению `settle`.
- **БПр9. Заметки и просьба (Ар53).** «Исправить» без слов — для заметок, автор которых нажавший: просьба — его собственный текст. Для чужой заметки — подтверждение «Сделать, как просит <имя>?»; нажатие подтверждения записывается в `feed.request` как просьба нажавшего. Системный текст разделяет: просьба — выбранные клиентом заметки; данные — текст раздела и ответы. По умолчанию.
- **БПр10. Блок до вызова модели.** Перед ключом `core` проверяет, что блок не держит агент и другой человек; аренду самого нажавшего на этот блок снимает (он нажал «Исправить» — значит, закончил). Держит другой — отказ `held` без вызова модели, резерв возвращается.
- **БПр11. Закрытие заметки.** Ответ «Агент» пишется всегда; заметка закрывается, только если нажавший — её автор или владелец артефакта (artifact-comments.ts:675).
- **БПр12. Показ.** Правка применяется сразу; Snackbar «Правка внесена.» с [Показать] и [Отменить] (`artifact.undoTurn` по `(taskId, attempt)`). В истории версий — подпись «Быстрая правка агента». По умолчанию; «Принять» для общих артефактов — этап 2.
- **БПр13. Цена, этап 1.** Резерв 1 кредита (`placeCreditHold`: первая попытка без `follows`, следующие — `follows: 'message'`), списание `ceil(работа попытки)` = 1 кредит, упавшая правка списывается за сделанную работу (план 90), оборванный платформой вызов (`billable = false`) — нет. По умолчанию.
- **БПр14. Цена, этап 2 — сквозное округление.** `due = max(0, ceil(Σ работы задачи) − покрыто)`, где «покрыто» — сумма `credit_holds.charged` плюс долг, отнесённый к задаче (долг не в журнале, holds.ts:1162). Ротация задачи, когда Σ работы ровно покрыта или раз в месяц, — чтобы не читать тысячи строк резервов. По умолчанию.
- **БПр15. Очередь и сборщик.** Отдельная очередь BullMQ `artifact-edits` (concurrency 32, attempts 1). Сборщик раз в 60 с: правка в `running` старше 2 мин — отзыв ключа, сброс `pending_*`, `feed.failure`, `running|preparing → awaiting_user`, списание за сделанное; в `queued` — сначала захват `queued → preparing`, затем то же (перехода `queued → awaiting_user` нет).
- **БПр16. Аккаунт `quick`.** Тот же ключ Z.ai API импортируется второй строкой `subscription_accounts` с драйвером `quick` и своим пределом одновременных запросов; сумма пределов двух строк не больше предела ключа у Z.ai (по умолчанию 16 = 12 ходам + 4 быстрым правкам), иначе провайдер ответит 429 обоим. По умолчанию.
- **БПр17. Чат «Быстрые правки».** Виден в списке чатов как журнал: запросы, итоги и что списано. Поля ввода нет — строка «Здесь собраны быстрые правки в артефактах. Чтобы поручить агенту новую работу, начните новый чат.» и [Новый чат]. По умолчанию.
- **БПр18. Отказ по содержанию** у провайдера приостанавливает быстрые правки этого человека в пространстве до решения оператора; обычные чаты работают. По умолчанию.
- **БПр19. Общий «быстрый вопрос» в чате — не сейчас.** Если владелец решит, он строится на том же движке отдельной задачей `quick_chat`; «Передать агенту» создаёт новый обычный чат с пересказом. По умолчанию.

## 4. Поток

1. **web.** Кнопка «Исправить» в карточке заметки (artifact-comments.tsx:523-530) и «Исправить (N)» в строке фильтров (до 8 заметок). Видна при роли «Правит» и выше.
2. **trpc `artifact.quickEdit`.** Одна транзакция: замок по `(userId, requestId)`; роль edit; вид `document`; `dispatchableThreads`; `findOrCreateQuickTask`; задача `awaiting_user → queued`, `attempt + 1`; `placeCreditHold`; `feed.request` «Исправить по заметке: «…»»; снимок заметок `artifact_comment_dispatches`; строка `artifact_quick_edits (queued)`; outbox `artifact.quick_edit` (только id).
3. **core `QuickEditRunner`.** Захват (строка → `running`, задача → `preparing`, `turn_no = attempt`) → проверка блоков и места заметки → промпт → ключ (задача → `running`) → вызов шлюза ‖ чтение значений переменных из Vault → разбор, ≤ 1 повтор → отзыв ключа → `applyArtifactOps` (агент) и ответ в заметку → `ArtifactChecks.settle` → `settleTurn(running → awaiting_user)` + списание → строка → `applied|unchanged|refused|failed`.
4. **Сигнал.** `artifact_ops` и триггер на `artifact_quick_edits.finished_at` → `pg_notify('raditi_artifact')` → SSE `artifact.signals`; web перечитывает и показывает итог.

## 7. Риски

- Качество одного вызова без других разделов: метрика доли `applied`; ниже 80 % — добавить оглавление артефакта.
- GLM может ответить текстом вместо вызова: запасной разбор JSON и один повтор.
- Задержка шага модели при `low` и коротком промпте не измерена (этап 0).
- Баланс Z.ai API (код 1113) — оповещение оператору и понятный текст клиенту.
- Изменение порта `LlmBackend` затрагивает шлюз ходов — регрессионные тесты на прежний UA и `max_tokens` 32 000.
- Разбиение Markdown на абзацы: свойство `join(split(x)) === x` на шаблонах и реальных разделах.
- Два аккаунта на один ключ API: при ротации ключа менять оба.

Проверка на соответствие spec (агент `spec-reviewer`, 27.11.2026) нашла шесть дыр, все исправлены:
- сборщик истечения резерва мог отменить задачу «Быстрые правки», после чего человек навсегда получал «занято». Теперь сборщик её не трогает, а завершённая задача уступает место новой;

- оценка места в пуле для хода считала аккаунты драйвера `quick`. Теперь фильтр по драйверу;
- `/compact` читал «первый включённый драйвер». Теперь драйверы платформы исключены;
- после `billing.charge_later` следующий резерв отказывал. Теперь перед резервом списывается отложенное, а если ещё нельзя — «Подождите…».

Независимое ревью (5 направлений, каждая находка проверена скептиком; 12 подтверждено, 7 отклонено) — исправлено:
- итог «Правка внесена.» показывался и при отказе проверки: отказ тоже поднимает ревизию блока. Теперь итог читается по `refusal` блока и по ответу `settle`, а проверка ключа, значений переменных, токенов и формы пароля идёт до записи — отклонённый текст не пишется и заметки не закрываются;
- карточка с «Отменить» пропадала вместе с заметкой, которую правка закрыла. Теперь слежение за правкой и Snackbar живут на уровне панели заметок;
- сборщик мерил «потерянность» от нажатия и мог убить правку, которая ждала в очереди и ещё работала. Теперь от захвата; исполнитель перед записью проверяет, что правка всё ещё его;
- сборщик не сбрасывал `pending_*` потерянной попытки, и следующая попытка могла опубликовать её текст. Теперь сбрасывает (`ArtifactChecks.fail`); ключи быстрых правок, которые не удалось отозвать, он тоже закрывает;
- отказ таймера сборщика мог уронить `core`. Теперь он ловится и пишется в лог;
- ответ модели шёл в ленту без очистки слов агента (`agentWords`);
- при «не нужно менять» и «нужен агент» ответ не попадал в заметку. Теперь попадает, заметка остаётся открытой;
- цены, даты и артикулы считались телефонами, а домен без схемы из заметки — новой ссылкой. Теперь телефон — это 10–12 цифр, ссылки сравниваются без схемы и `www.`, учитываются `t.me` и домены распространённых зон, адрес почты не считается ссылкой, а слова клиента в ответах заметки тоже разрешают контакты;
- ограда кода с отступом (в пункте списка) резалась по пустым строкам;
- правка, которая не легла на абзацы (`find` не найден или не единственный), сразу падала. Теперь это повод для единственного повтора.
