# 100. Артефакт — только когда он действительно нужен

Запрос владельца от 28.11.2026 (дословно):

> есть некоторая проблема, которая заключается в том, что opencode всегда формирует документ, когда это нужно и не нужно, исправь и не давай никакх указаий по созданию докумнтов, делай это тогда, когда действительно нужно

Решения без слов владельца помечены «По умолчанию» — по его указанию от 09.10.2026 («принимай все решения по умолчанию»).

**Статус.** Тексты и тесты сделаны, ветка `fix/artifacts-on-demand`, отчёт — §4. Живой ход с моделью не проверялся.

---

## 0. Коротко

1. Ответ клиенту — `client_message` в чате. Ответ на вопрос, объяснение, совет, короткий текст или список идут туда, в пределах 2 000 символов.
2. Артефакт агент создаёт, только когда клиент просит то, для чего есть вид (документ, страница или макет, презентация, картинка), или ему нужен текст длиннее предела сообщения.
3. Из инструкций хода и описаний инструментов убраны все указания делать документ по умолчанию. Перечень видов и то, как пишется документ, остались — для случая, когда он действительно нужен.

## 1. Откуда бралось «всегда документ»

Пять текстов, которые модель читает в каждом ходе, усиливали друг друга, а за ними стояло решение Ар4 плана 88:

| Где | Что говорило |
| --- | --- |
| `packages/domain/src/artifacts/section.ts`, раздел `## Artifacts` | «Your result for the client is an artifact of the kind that fits it»; «Create it with `raditi_artifact_create` before you research»; «put the findings there, not in the chat»; «In `client_message` name the artifact in one or two lines» |
| `packages/domain/src/artifacts/kinds.ts`, `document.forAgent` | под «Документ» попадали «a summary», «notes», «a post» — почти любой ответ |
| `apps/core/src/tasks/turn-instructions.ts`, «Files for the client» | «any other text is a document artifact»; «A file is for a result no kind of artifact fits» |
| `apps/mcp/src/artifacts/mcp-artifacts.controller.ts`, `artifact_create` | «kind document for text … Call it before you research» |
| там же, `artifact_import` | «a long .md (a document)» |
| решение: `docs/plan/88-artifacts.md`, Ар4 | «Результат для клиента — артефакт» — значение по умолчанию из ревью, владелец его не принимал |

Ответ модели в чате при этом нигде не назывался как вариант: выбор был только «артефакт или файл».

## 2. Решения

| № | Решение |
| --- | --- |
| АЗ1 | Ответ — `client_message`, в пределах его 2 000 символов (`agentOutputLimits.clientMessage`; число стоит в самом правиле): длиннее схема итога не примет, и ход кончится `TURN_OUTPUT_REJECTED` — поэтому «сократите». Артефакт — только когда клиент просит то, для чего есть вид, или ему нужен текст длиннее предела. Меняет Ар4 плана 88 и слова «выбор вида агентом» в строке АТ1 spec §20 |
| АЗ2 | Убраны «Your result for the client is an artifact», «before you research», «put the findings there, not in the chat», «any other text is a document artifact», «A file is for a result no kind of artifact fits», «Call it before you research», «a long .md (a document)». Строка «одна-две строки в ответе» действует, только когда артефакт сделан |
| АЗ3 | `document.forAgent` — длинный текст, который хранят, правят или передают: статья, инструкция, отчёт, аудит, план работ. «Сводка», «заметки», «пост» убраны |
| АЗ4 | Описание `artifact_create` говорит, когда создавать, и что ответ, совет или короткий текст идут в `client_message`. По умолчанию |
| АЗ5 | Порядок письма документа (постановка владельца от 13.11.2026, план 69: скелет, по разделу на глазах у клиента, «Источники») остаётся — для документа, который делается. Он больше не стоит в инструкциях как первый шаг любой работы. По умолчанию |
| АЗ6 | Файл в `/workspace/out` — когда клиент просит файл или называет формат, или для данных, которые клиент просил собрать для скачивания; картинка как файл — «PNG or JPEG», чтобы не спорить с видом «Изображение»; несколько документов — когда клиент просит несколько документов. Данные из кабинета клиента (браузер) — по-прежнему файлом: ДС1 spec §20 — слова владельца, а `client_message` чата Telegram уходит через Telegram, где файлы агента нарочно не отправляются (открытый вопрос владельца). По умолчанию |

Не меняется:
- предел `client_message` — 2 000 символов;
- навыки каталога (`commercial-offer`, `social-posts`, `product-cards`) — клиент включает их сам, и коммерческое предложение — документ по существу;
- порядок разделов инструкций, семейство `artifacts` в каждом ходе, проверки и пределы артефактов.

## 3. Что меняется

- `packages/domain/src/artifacts/kinds.ts` — `document.forAgent`.
- `apps/core/src/tasks/turn-instructions.ts` — «Files for the client».

- `docs/spec.md` §8 (п. 7) и §20 (Ар1–Ар5, Э3, АТ1, новый блок «Артефакт только по необходимости»), план 88 (§0, Ар4), roadmap — P39.

## 4. Отчёт

**Сделано.**
- Тексты из §1 переписаны по §2. Новые тесты держат: правило «ответ в `client_message`, в пределах 2 000 символов», условие создания артефакта, формат картинки-файла и описание `artifact_create`; старые слова (`before you research`, `not in the chat`, `Your result for the client is an artifact`, `a summary`, `a long .md` и другие) проверяются на отсутствие.
- Проверки: `typecheck`, `lint`, `test` для `@repo/domain`, `core`, `mcp` — зелёные; `pnpm check-architecture` — без нарушений. Сумма описаний семейства `artifact_*` осталась в пределе 2 379 символов.
- Ревью тремя независимыми проверяющими с перепроверкой каждой находки: подтверждены риск длинного ответа сверх 2 000 символов (исправлен — число и «сократите» в правиле, АЗ1), спор «картинки» с видом «Изображение» (АЗ6), неточности этого плана — всё исправлено. Проверка по spec (`spec-reviewer`): правка абзаца браузера («данные кабинета — в ответе») меняла ДС1 без владельца и пускала данные людей в Telegram — абзац возвращён как был.

**Не сделано.**
- Живой ход OpenCode с GLM не запускался (`verify:opencode` и ручная проверка в чате): насколько реже модель делает документ, видно только на ходах. Проверить: обычный вопрос → ответ в чате без артефакта; «напишите статью / сделайте презентацию» → артефакт.
