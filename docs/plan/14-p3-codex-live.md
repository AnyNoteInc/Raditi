# B7 — реальная локальная проверка текущей подписки Codex

30.09.2026, по явному запросу владельца. **Адаптер Codex работает на текущей подписке ChatGPT Pro:** настоящий CLI создал файл инструментом, продолжил ту же сессию, прочитал и дополнил файл. Проверены нормализация запросов, upstream-заголовки, потоковый учёт и лимиты. Выявленные расхождения исправлены до итогового прохода.

## Итоговый проход

Начало: 30.09.2026 01:55:21 МСК, 29.09.2026 22:55:21 UTC. Установленный CLI — **0.159.1**, модель — `gpt-6.1-sol`, reasoning — `low`. CLI не устанавливался и не обновлялся этой проверкой.

```sh
node infra/dev/llm-verify/local-spike.mjs --model gpt-6.1-sol --local-egress --backend-adapter
```

Так команда выглядела 30.09.2026. После ревью 02–04.10.2026 пути к файлу входа по умолчанию нет, флага `--auth-file` тоже. Живой проход требует абсолютного пути в `RECORD_CODEX_AUTH` и флага `--confirm-live-subscription`; без них скрипт завершается до чтения файла. CLI и его команды получают временный `HOME`. Повтор возможен только с новым разрешением владельца (CLAUDE.md, правило 1):

```sh
RECORD_CODEX_AUTH=/абсолютный/путь/к/auth.json \
  node infra/dev/llm-verify/local-spike.mjs --model gpt-6.1-sol --local-egress --backend-adapter --confirm-live-subscription
```

После ревью живой проход не повторялся: все проверки второго и третьего дня шли на фейках подписок.

## Исправления по реальным данным

1. **Responses Lite.** CLI переносит инструменты в `input.additional_tools` и отправляет `reasoning.context=all_turns`. Добавлены точные формы `additional_tools` с ролью `developer`, три допустимых значения context и заголовок `x-openai-internal-codex-responses-lite` только со значением `true`. Строгая проверка инструментов применяется и в новом месте; `custom` допускается внутри `namespace`. Вложенные namespace и встроенные инструменты провайдера остаются запрещены. Внутренняя метаинформация истории удаляется.
2. **Планы без окна 5h.** Текущий Pro сообщает только недельное окно. Выбор аккаунта больше не требует обязательного `5h`: проверяет реально полученные окна. Пустые, просроченные и повреждённые снимки по-прежнему требуют probe; проверки запаса и времени сброса сохранены.
3. **Отсутствующее окно в заголовках.** Провайдер присылает второй слот как `used-percent=0`, `window-minutes=0`, `reset-after-seconds=0`, `reset-at=""`. Раньше это обнуляло весь снимок лимитов. Теперь пропускается только эта форма с отсутствующим/пустым reset-at. Некорректные или ненулевые сочетания по-прежнему отклоняются, действующие окна с нулевым расходом сохраняются.

Формы Responses Lite сверены с локальным закреплённым исходником Codex `064c6b8`: `codex-api/src/common.rs`, `protocol/src/models.rs`, `core/tests/suite/responses_lite.rs`. Фактическая форма запроса CLI сначала проверена без обращения к подписке на локальном перехватчике; после исправления выполнен реальный проход.

- `@repo/llm-backends`: **446 тестов прошли**.
- `@repo/domain`: **589 тестов прошли**.
- `pnpm test:infra`: **139 прошли**, 1 Linux watchdog-тест пропущен без тестового Docker-образа.
- Typecheck и lint обоих изменённых пакетов, архитектурная проверка — прошли.
- Независимое ревью подтвердило поддержку Responses Lite и недельных планов. В тестовом прокси исправлена обработка исключений SSE-декодера, чтобы повреждённый поток не прерывал уборку ресурсов.

Обычные тесты используют синтетические credentials и локальные ответы, подписку не расходуют. Live-запуск требует отдельной команды. Режим `--backend-adapter` не может незаметно вернуться к простому проходному прокси: отказ нормализации завершает запрос, успех требует полного terminal, совпадения usage и разбора объявленных окон.

## Границы результата

Вход владельца читает только host-стенд. CLI получает временный локальный ключ и отдельный `CODEX_HOME`; login, refresh, revoke и logout не выполнялись. Использованы только синтетические задания и файлы. В отчёте нет токенов, идентификаторов, содержимого запросов или произвольных значений заголовков; из заголовков квот сохраняются только разрешённые числовые поля.

Это проверка реализованного адаптера, **не завершение всей платформы**. Основной шлюз, ключи хода, сохранение расхода в БД, пул и бюджеты в работающем приложении ещё предстоит подключить. Настоящий Kimi, удалённый egress и облачные серверы не проверялись. Перед облачной выкладкой остаётся обязательным полный локальный e2e с настоящим WordPress. Следующий шаг плана — B8, маршруты и заголовки `sandbox-gw`.
