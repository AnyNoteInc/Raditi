## 0. Коротко

1. **Артефакт — рабочий объект, страница — публикация.** Артефакт — документ, макет, таблица, холст макетов сайта и другие виды. Клиент и агенты меняют его вместе, правки видны сразу, есть история версий и комментарии. По умолчанию его видит только владелец, он может поделиться им с пользователями Радити. Страница (планы 69, 73) — снимок для всех в интернете, и она не меняется. Мост один: «Опубликовать как страницу» и «Обновить страницу». Публикует только владелец.
2. **Документ агента становится первым видом артефакта — на месте.** Таблицы `chat_documents*` расширяются в два выпуска.
   - Вкладки «Документы» больше нет: каждый артефакт и каждый файл чата открываются своей вкладкой, файлы — с нынешним просмотром, список — в меню «+» (ответ владельца, Ар44).
   - Семейство MCP `artifacts` заменяет `docs`: описания инструментов уходят модели в каждом запросе.
   - Результат для клиента агент делает артефактом. Файл — только когда клиент назвал формат (Ар4).
3. **Виды.**
   - Первая очередь: «Документ», затем «Макет» и «Таблица», затем «Холст» (несколько макетов сайта рядом) и «Фирменный стиль».
   - Вторая: «Схема», «Презентация», «Изображение», «Структура сайта», «Отчёт».
   - Холст рисует экран одним адаптивным кадром в двух видах — компьютер и телефон. Варианты А и Б — отдельные кадры.
4. **Совместная работа.** Артефакт — набор блоков с номерами правок, сервер решает, что принять.
   - Агент правит по цитате или по прочитанному номеру. Правки разных блоков не мешают друг другу.
   - Человек важнее агента: блок, который он правит, занят.
   - Запись агента до проверки держит блок за его ходом. Поэтому два агента не затирают друг друга, пока `core` проверяет текст.
   - CRDT не нужен (разбор — §8).
5. **Проверка до показа.** Любой текст агента, который увидит кто-то кроме пишущего чата, сначала проверяет `core`. Это блоки, названия, намерения, ячейки, ответы и метки; проверяются секреты, ключи хода и значения переменных, раз в 1,5 с, как разделы плана 74. Правку человека с формой секрета платформа не сохраняет. Изменения расходятся каналом сигналов плана 86, присутствие — через Redis.
6. **Несколько агентов.**
   - Каждый чат действует с правами того, кто его ведёт.
   - Ответ инструмента говорит, какие блоки изменили другие.
   - Названия чатов видит только их хозяин, другим показывается «Агент <Имя>».
   - Проход, прочитавший текст других людей, не пишет в общие артефакты сверх названных клиентом. Не публикует и не меняет расписание без карточки клиента.
7. **Справа от чата** — каждый открытый артефакт своей вкладкой с названием (ответ владельца). Список артефактов и файлов чата — в меню «+» и в «Результатах». Целиком артефакт открывается в `/artifacts/<id>`, справа — чат этого артефакта у текущего пользователя. В рейке появляется пункт «Артефакты».
8. **Проект или пользователь.** Артефакт принадлежит владельцу, по желанию — его проекту. Тогда он лежит группой внутри «Контекста» проекта (колонка остаётся из четырёх строк), попадает в инструкции каждого хода проекта списком, без содержимого, и уходит в корзину вместе с проектом.
9. **Поделиться — только пользователям Радити, после входа.**
   - Ссылка `raditi.ru/a#…` или приглашение по почте. Приглашение ждёт принятия, письмо уходит на любой адрес с общим текстом.
   - Делится только владелец, агент — никогда. Получатель не становится участником пространства. Права — «Смотрит», «Комментирует», «Правит», хранятся грантами по источнику; отзыв ссылки снимает только её гранты.
   - Агенты получателей читают прикреплённый к их чату артефакт, с правом «Правит» — пишут, за кредиты получателя.
   - **Правка и комментарии других людей — да** (ответ владельца). По 149-ФЗ, ст. 10.1, Радити, вероятно, становится организатором распространения информации, и обязанности принимаются (отчёт f3, Ар56):
     - журнал фактов — 3 года, скрытое хранение удалённого в общих артефактах — 6 месяцев, всё в России;
     - ответы на запросы органов;
     - уведомление Роскомнадзора — по его требованию.
   - Хранение строится раньше, чем другим людям откроются правка и комментарии (Э10).
10. **Безопасность показа.**
    - HTML показывается только в рамке с корня домена страниц: своя песочница без всплывающих окон, ссылки — через кабинет с подтверждением, роль зрителя проверяется на каждый запрос.
    - Фото и шрифты — подписанными адресами по правилам общих файлов сайта (Дер34), у шрифтов — ещё с `Access-Control-Allow-Origin: *` (Спайк 2 (Э0а)).
    - Сообщения из рамки — данные, а не слова клиента.
11. **Деньги.**
    - Работа агента — обычный проход, всегда в чате того, кто попросил, и за его кредиты.
    - Ручные правки, комментарии, версии, доступ и выгрузка в браузере бесплатны.
    - Пределы — константы, в том числе 1 ГиБ на пространство.
12. **Этапы Э0–Э12** (§10):
    - перед кодом — семь спайков и проверка журнала Traefik (Э0а): рамка правки без скриптов, шрифты в рамке, серверный рендер, схемы, Markdown в редакторе, доска кадров, таблица. Сделаны 19.11.2026, итоги — §10;
    - первая польза — после Э4: документ руками и агентом, с историей, «Вернуть» и публикацией;
    - холст — после Э6;
    - доступ и правка другими людьми — после новой редакции документов и хранения ОРИ (Э9–Э10), комментарии между людьми — следом (Э10а).
13. **Библиотеки** — только со свободной лицензией и без внешних CDN (§7.13):
    - документ — Tiptap с `mui-tiptap` и своим мостом Markdown на remark, без `@tiptap/markdown` (Спайк 4 (Э0а));
    - таблица — TanStack Table;
    - доска — своя, на CSS-трансформе (Спайк 6 (Э0а));
    - схема рисуется на сервере одним движком — Mermaid 12 (Спайк 7 (Э0а));
    - PDF, миниатюры и отчёт вёрстки — Chromium из `apps/browser`.
14. **Зрение агента — да** (ответ владельца). Холст, макеты и изображения агент проверяет сам: помощник `look` на GLM-5.3-Flash по плану смотрит на отрисованный кадр. Дешёвый текстовый отчёт вёрстки идёт после каждой записи кадра (Ар32).

## 1. Как это сделано у других

Подробности, сценарии по шагам, источники и даты — в отчётах `docs/research/2026-11-artifacts/r1…r7` и `f1…f3`. Здесь — то, на чём стоят решения.

### 1.1. Anthropic: Claude.ai, Claude Code, Claude Docs, Claude Design

- **Один объект для всех продуктов.** С 16.09.2026 артефакт — объект с адресом `claude.ai/artifact/<id>`. Он приватный по умолчанию, открывается в панели справа от разговора и во вкладке «Artifacts» с поиском, фильтром и закреплением. Его делают чат, Cowork, Claude Code, Claude в Slack и Meetings. Отчёт r1.
- **Два слоя.** Первый — свободная HTML- или Markdown-страница, бывает многофайловой. Второй — экземпляр типа: Docs, Slides, Design, Design System, Data, Sheets, Whiteboard, Motion. Тип состоит из редактора только для чтения, инструкции агенту (`SKILL.md`) и версионированного контракта runtime. Содержимое лежит в файлах `project/*`, в собственной базе артефакта или в сервисе Docs.
- **Возможности страницы.** Страница может:
  - сохранять себя новой версией;
  - держать общую базу с правилами доступа;
  - вести присутствие и события («room»);
  - хранить комментарии и файлы, отдавать выгрузки;
  - звать Claude за счёт зрителя и брать коннекторы зрителя.
- **Совместная правка — оптимистичные версии.**
  - Публикация поверх непрочитанной версии отклоняется и возвращает новую для слияния.
  - В Docs у каждого блока защита `ifHash+ifRev`, при конфликте «их правка побеждает».
  - В Sheets — ревизия `base`.
  - В Whiteboard — `if_version` и рамка-заявка, которую видят все, пока Claude работает.
  - В базе страницы — короткие аренды.
- **Агент видит, на что смотрит человек.** Сообщение несёт блок `artifact-view-context`: выделение, видимые доски, несохранённые правки. Правку можно попросить прямо со страницы: «Edit with Claude» по выделению, `@Claude` в документе.
- **Комментарий — запрос агенту.** Тред с «Send to Claude» уходит агенту, а ставит его только человек с правом правки. Сессия-автор следит за артефактом: не больше 60 ответов в час, до 25 артефактов на сессию.
- **Шеринг.**
  - Права: Can view, Commenter, Can edit, а также Contributor — пользоваться и сохранять данные без правки.
  - Доступ: только вы, все со ссылкой, организация, группы, приглашённые по почте (до 50 внешних, приглашение живёт 30 дней).
  - Отзыв мгновенный. Делиться артефактом агент не может. Артефакты с внешними данными закрыты внутри организации.
- **Рабочее и опубликованное разведены.** Зрителям можно отдавать «последнюю версию» или «версию N». Сайт делают выгрузкой: «одна самодостаточная страница без бэкенда не может обслуживать несколько адресов».
- **Безопасность.** Рендер на `*.claudeusercontent.com` в sandbox-iframe со строгим CSP. Чужой артефакт агент читает изолированной сводкой как данные.
- **Слабые места.** В Claude Design совместная правка «basic and may not work reliably», истории версий нет. За год Anthropic трижды переносил артефакты между форматами.

### 1.2. OpenAI, Google, Microsoft, GitHub

- **Рабочий объект вынесен из ленты у всех.** У OpenAI — ChatGPT Space (Pages, Slides, Spreadsheets), у Microsoft — Copilot Pages и Workspaces (17.11.2026), у Google — студия Gemini Notebook, у GitHub — issue artifacts (28.10.2026). OpenAI убрала Canvas из GPT-5.5 (28.05.2026): блок в ленте не заменяет постоянный документ. Отчёт r2.
- **Публикация — отдельный шаг.** ChatGPT Sites — «Save a version» и «Deploy a version», у Copilot публикация отдельно от Pages, у Gemini — снимок по публичной ссылке.
- **Правка выделенного силами ИИ — у всех**: «Ask for change», «Select & ask», «Ask Copilot».
- **Правка ИИ в общем объекте сначала видна одному автору**, пока он её не примет. Так в Google Docs, Copilot Pages и «Ask for change».
- **Комментарий — канал к агенту**: `@ChatGPT` в Pages; в Microsoft Workspaces «you leave a comment, and an agent picks it up».
- **Одновременную правку несколькими агентами системно не решил никто.** ChatGPT просит людей договориться, Microsoft признаёт, что ИИ не видит одновременных правок. Заготовки: запись с `ifMatch`/ETag и исходами saved, conflict, too-large; правка поиском и заменой без перегенерации.
- **Права и рендер.** Права — View, Comment, Edit; есть ссылка, организация, копия без данных («Remix», «Copy Canvas»). Рендер — свой origin, iframe-песочница, `connect-src 'none'`.

### 1.3. Чат-агенты: Perplexity, Mistral, Grok, Qwen, DeepSeek, Kimi, Manus, Genspark, Z.ai, MiniMax

- **«Артефакт»** — результат задачи, отдельный от ответа. Есть библиотеки: Manus Library, MiniMax Assets, Grok Library. Отчёт r3.
- **Рабочее и публикацию разводят почти все**: Perplexity — «Publishing and visibility are separate», у Kimi — превью до «Publish», у Genspark — Design → Build it → Hosting.
- **Одновременную правку несколькими людьми с курсорами не документирует никто из десяти.** Лучший образец «нескольких агентов на одном объекте» — Manus: общая история версий, у каждой версии — задача-автор, автоматическое слияние, баннер «старая версия — Sync».
- **Пометки пачкой — общий приём**: Perplexity «Submit N edits», Genspark «Send N edits», комментарии к элементам слайдов у Mistral.
- **Версия появляется на каждую правку агента**, а ручные правки склеиваются (у Genspark — не чаще раза в 5 минут). Опасный пример — откат в Genspark AI Docs стирает последующие версии.
- **У DeepSeek в чате артефактов нет.**

### 1.4. Агенты для кода и протоколы

- **Артефакт — объект рядом с чатом**: вкладка справа, список, карточка в ленте (Antigravity, Cursor, Devin, Amp, Kiro). С ноября 2026 панель сама не открывается: у Devin рейка стартует закрытой (13.11.2026), у Cursor панель открывается пилюлей. Это совпадает с планом 59. Отчёт r4.
- **Ближе всего к запросу владельца — Amp (02.11.2026).**
  - Документ треда правят человек и агент, каждое сохранение — ревизия.
  - Правки агента, которые ещё совпадают, применяются; иначе — отказ и слияние.
  - Агенты других тредов тоже правят и пишут в тред артефакта, что и зачем изменили.
  - Предел — 2 МБ.
- **Комментарий к месту — управление агентом**: Antigravity, Kiro («Send N to Kiro»), Cursor Design Mode. Русская модель того же — комментарии Яндекс Документов («Решённые / Нерешённые») и «Режим рецензирования» с «Принять / Отклонить».
- **Инструменты агента** названы у OpenCode V2 (`artifact_create/read/update/delete`, эксперимент 30.10.2026) и Hermes (`artifact_publish/list/get/share/revoke_share`).
- **Протоколы.**
  - A2A: версия артефакта — то же имя и новый id, части идут через `append`/`lastChunk`.

### 1.7. Закон: организатор распространения информации

Отчёт f3 — это не юридическое заключение. Нормы сверены по pravo.gov.ru: 149-ФЗ, ст. 10.1, в редакции с 01.09.2026.

- **Определение.** Организатор распространения информации (ОРИ) — тот, чья система «принимает, передаёт, доставляет или обрабатывает» электронные сообщения пользователей. Неопределённого круга и обмена между людьми закон не требует: мессенджер с выбранными получателями назван ОРИ прямо (ч. 4.2). Поэтому различие 152-ФЗ «предоставление / распространение» от этого статуса не защищает.
- **Как попадают в реестр.** Роскомнадзор присылает требование по обращению органа оперативно-розыскной деятельности или безопасности, на уведомление даётся 10 рабочих дней. Подать можно и самому. После повторного неуведомления Роскомнадзор вносит запись сам, удалить её нельзя.
- **Обязанности:**
  - хранить в России журнал фактов (IP и порт, точное время, адресаты, удаление учётной записи) 3 года, а содержимое сообщений, включая удалённое, — 6 месяцев;
  - отвечать на запросы органов за 30 дней, срочные — за 3 рабочих дня;
  - после уведомления ФСБ — план программно-технических средств за 2 месяца и круглосуточный удалённый доступ за 3 месяца.

  Порога по размеру сервиса нет.
- **Санкции.** Штрафы для исполнителя-гражданки малы (ст. 13.31 КоАП). Главный риск — ограничение доступа к сервису через суд «до исполнения», как с Telegram в 2018 году.
- **Практика 2024–2026.** Принудительно внесены 12 мессенджеров, Cloudflare, Google Meet, Apple и Microsoft. Облачных редакторов, досок, конструкторов сайтов и ИИ-чатов в найденных материалах нет.
- **Функции артефактов** (оценки отчёта):

  | Функция | Подпадает ли |
  | --- | --- |
  | Комментарий, который видит другой человек | вероятно |
  | Совместная правка людьми | вероятно, по букве закона |
  | Ответы агента в общем треде | вероятно |
  | Просмотр по ссылке со входом | неясно |
  | Чат «пользователь ↔ агент» | неясно (по букве — да, по практике — скорее нет) |
  | Письма и push без текста пользователя | вероятно нет |

  Отложить одни комментарии риск не снимает: право «Правит» в той же категории. Риск ниже только без канала «человек → человек».
- **Попутно, ко всему продукту.** 149-ФЗ, ст. 8, ч. 10 требует авторизовать пользователей в России одним из перечисленных способов, с 07.07.2026 за нарушение есть штраф (ст. 13.55 КоАП). Подходит ли вход по почте и паролю — неясно. Это вопрос не только к артефактам (§12, «К сведению»).

### 1.8. Что из этого следует

1. **Артефакт и публикация — разные сущности.** Это подтверждено десятками продуктов и совпадает со словами владельца.
2. **Объект живёт отдельно от чата**, в библиотеке пользователя или проекта.
3. **Агенту — точечная правка по id блока или по цитате с проверкой номера правки, сервер решает.** CRDT для агентов не используют: сервер не может проверить правку до показа.
4. **Ручная правка человека никогда не перезаписывается молча.**
5. **Комментарий и выделение — главный способ показать агенту место.** Пометки отправляют пачкой.
6. **Делиться может только человек.** Публичное — через публикацию.
7. **HTML агента — только в изолированном источнике.**
8. **На телефоне — просмотр, комментарии и правка текста.**
9. **Чего нет ни у кого.** Никто не сделал нескольких агентов разных чатов и людей в одном объекте, с видимостью «кто где пишет» и честным правилом конфликтов. Никто не сделал и холст дизайна, который одной кнопкой становится сайтом из страниц.
10. **Канал «человек → человек» юридически самый дорогой.** Он ведёт к статусу ОРИ (§1.7). Владелец этот статус принял (Ар56), поэтому хранение ОРИ строится раньше, чем другим людям откроются правка и комментарии.

## 3. Понятия и как они связаны

| Понятие | Что это | Кто видит | Кто меняет | Где |
| --- | --- | --- | --- | --- |
| **Артефакт** | Рабочий объект: документ, макет, таблица, холст… Живой, с историей версий, комментариями и присутствием | Владелец; те, с кем он поделился (после входа); агенты их чатов | Владелец и «Правит» — руками и через агентов; агенты — инструментами `artifact_*` | `/artifacts`, своя вкладка справа от чата, «Контекст» проекта |
| **Страница** | Опубликованный снимок для всех: страница или сайт из страниц | Любой в интернете (по желанию — с паролем) | Новой публикацией владельца: «Опубликовать», «Обновить страницу» | `<метка>.pages.raditi.ru`, раздел «Страницы» |
| **Документ агента** (сегодня) | Становится артефактом вида «Документ» на месте | — | — | — |
| **Файл** | Байты: вложение клиента или файл из `/workspace/out` (Word, Excel, PDF, PNG и то, что клиент назвал) | Участник чата | Не правится: скачать или заменить. `.html` и `.md` — «Открыть как артефакт» | Своя вкладка справа от чата, группа «Файлы чата» меню «+», «Результаты» |
| **Контекст проекта** | Исходные материалы клиента: инструкции, файлы, тексты, репозиторий и (новое) группа «Артефакты проекта» | Автор проекта | Клиент | Колонка проекта |
| **Память** | Короткие записки о клиенте и деле | Агент как фон | Агент (`memory_*`) и клиент | «Память» |

Связи:
- **Артефакт → страница.** Владелец нажимает «Опубликовать как страницу» (у холста — «как сайт»), и выбранная версия копируется в страницу. Это может быть новая страница, новая версия выбранной или страница сайта по пути; правила — страниц, страница создаётся в пространстве владельца. Использованные фото копируются в общие файлы сайта. Артефакт помнит публикации и показывает «Опубликовано: v3 · есть изменения после публикации». Страница меняется только новым «Обновить страницу» (F-publish, C-mockup).
- **Страница → артефакт.** «Править вместе с агентом» в «Страницах» делает артефакт из исходника страницы. Публикация из него — следующая версия той же страницы с `expectedVersion`.
- **Артефакт ↔ контекст и память.** Артефакт проекта виден всем чатам проекта списком (§7.6). «Фирменный стиль» проекта закреплён в каждом ходе проекта. Память хранит ссылку на артефакт, а не копию.
- **Файл → артефакт.** «Открыть как артефакт» у `.html`, `.md`, `.csv` и `.svg`. Агент делает то же инструментом `artifact_import`.
- **Слово «страница»** в артефактах не используется: HTML-артефакт — «Макет». Кнопки «Поделиться» (пользователи Радити) и «Опубликовать» (все) разные, у каждой своя подсказка (E-share).

## 4. Виды артефактов

Владелец назвал два вида: «текст» и «html страница или канвас… чтобы рисовать дизайны сайтов». Остальное — предложение по разбору r7. Ценность для малого бизнеса — от 1 до 5, сложность для нас — S, M или L.

| Очередь | Вид | Что это | Агент делает | Клиент руками | Наружу | Ценность / сложность |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | **Документ** | Текст по разделам (Markdown): тексты сайта, инструкции, бриф, договор, ответы на вопросы, коммерческое предложение | Пишет по разделам, правит по цитате и комментариям | Правит раздел в редакторе, комментирует | Страница, PDF (печать), `.md`, Word (агентом) | 5 / S |

**Шаблоны первой очереди** (Ар10). Восемь штук; нажатие кладёт просьбу в черновик нового чата (как Дер6 у пустых «Страниц») и выбирает вид:
- документы: «Тексты для сайта», «Ответы на частые вопросы», «Коммерческое предложение»;
- таблицы: «Прайс-лист», «Контент-план на месяц»;
- макет: «Калькулятор стоимости»;
- холст: «Холст для нового сайта» — главная, услуги, контакты;
- «Фирменный стиль» — по сайту клиента.

**Что не артефакт.**
- Анкета со сбором ответов: сбор данных посетителей — работа страниц. В артефакте её можно только спроектировать и пройти пробно.
- Живые данные сервисов клиента (CRM, Метрика). Запуск без надзора в них не войдёт.
- Встраивание макета на сайт клиента: это решение страниц, вопрос 20.

## 5. Способы применения

По ценности для владельца малого бизнеса (r7, r1–r5).

1. **Правка руками и агентом в одном объекте.** Цена или опечатка — за секунды и бесплатно: в документе — в редакторе, в макете и холсте — правкой текста на месте и «Настройками» (Ар9). Агент видит «изменено вами» и продолжает от этой правки.
2. **«Опубликовать» и «Обновить страницу».** Прайс, меню или акция по ссылке, плюс QR. Карточка честно говорит «есть изменения после публикации».
3. **Правка по выделению.** Выделенный отрывок, ячейки или элемент кадра уходят агенту якорем, и он меняет только это.
4. **История и метки версий**: «Отправлено клиенту», «Согласовано», «Опубликовано v3». К ним — «Вернуть», «Сравнить» и «Отменить правки этого хода». Это снимает страх «агент всё испортил»; поэтому история входит в первую пользу (Э4).
5. **Холст для сайта.** Два-три варианта главной, каждый экран сразу на компьютере и телефоне. Клиент выбирает вариант и нажимает «Опубликовать как сайт».
6. **Шаблоны** (§4): первый результат за подарочные 50 кредитов.
7. **Согласование с людьми.** Дизайнер, бухгалтер или партнёр открывают артефакт по ссылке, комментируют или правят, а их агенты читают и правят в их чатах.
8. **Фирменный стиль ко всему новому**: макетам, картинкам, письмам, страницам.
9. **Живой артефакт по расписанию.** Каждый понедельник задача обновляет прайс по ценам поставщиков, отчёт по отзывам или черновики постов. Каждый запуск — новая версия с меткой «Запуск задачи «…»».
10. **Комментарии, на которые отвечает агент.** Пометки «для агента» копятся, а «Отправить агенту (N)» уходит одной просьбой в чат того, кто нажал. Агент отвечает в тредах и закрывает сделанное.
11. **Несколько чатов над одним артефактом.** Один чат пишет тексты, другой рисует макеты из них, третий сверяет цены.
12. **Пачка из таблицы**: 10 предложений, 50 ценников, 30 карточек за один ход.
13. **«Сохранить как артефакт»** из ответа агента, файла, страницы или открытого сайта.
14. **Проверка вторым агентом**: опечатки, ошибки в смете, расхождения с фирменным стилем. Такой агент только комментирует.
15. **Варианты и голосование**: «Вариант А/Б/В», голоса приглашённых.
16. **Связи между артефактами.** Таблица питает меню и ценники; при правке источника — «обновить связанные».
17. **Telegram.** «Артефакт «…» обновлён» со ссылкой — только о своих артефактах.
18. **«Сделать копию себе»**, если владелец разрешил.
19. **Сколько кредитов ушло на артефакт** — по проходам, которые его меняли.

## 6. Решения

### Понятия и границы

- **Ар1. Артефакт.** Рабочий объект клиента и агентов (виды — Ар6).
  - Приватный по умолчанию и живой: правки видны всем, кто его открыл, через мгновение.
  - Есть история версий, комментарии и присутствие.
  - Принадлежит пространству владельца, по желанию — его проекту (Ар42).
  - Делится с пользователями Радити после входа (Ар33–Ар41). Посетителям интернета не виден никогда.

  По умолчанию по словам владельца.
- **Ар2. Страница остаётся публикацией** (планы 69, 73 не меняются).
  - Мост — «Опубликовать как страницу» (у холста — «как сайт»), «Обновить страницу», «Править вместе с агентом».
  - Публикует только владелец артефакта, страница создаётся в его пространстве (Ар23). Ревью.
- **Ар3. Документ агента становится видом «Документ» на месте** (Ар11).
  - Вкладка «Документы» уходит: документ открывается вкладкой артефакта, файлы `.html` и `.md` — своими вкладками с нынешним просмотром (Ар44).
  - Семейство `docs` → `artifacts`. Синонимы `doc_*` принимает охранник, но не объявляет в `tools/list`: они нужны только ходам, начатым до выкладки. Отображены все шесть: `doc_section_write` = `replace` по последней `rev`, которую видел чат; `doc_finish` = версия в конце хода; `doc_section_remove` и `doc_section_move` = `delete` и `move`.
  - Наставление агенту (`turn-instructions.ts:26-49, 137`) и сценарий Q `verify:browser-task` переписываются, а не переименовываются.

  По умолчанию по c1, c3, ревью.
- **Ар4. Куда агент кладёт результат.**
  - Результат для клиента — артефакт: текст → «Документ», вёрстка, прототип, калькулятор → «Макет», строки и столбцы → «Таблица».
  - Файл в `/workspace/out` — только Word, Excel, PDF, PNG или формат, который клиент назвал (как сегодня `requestedFileFormats`).
  - `page_publish` — только по «опубликуй», «дай ссылку».

  Так у модели один канал вывода вместо трёх. Это меняет Д1 плана 67 (страница или документ в outbox по умолчанию) — вопрос 3. Ревью.
- **Ар5. Имена.**
  - Раздел — «Артефакты», слово владельца. Ответ владельца 19.11.2026 на вопрос о жаргоне: «оставь Артефакты».
  - В spec §8 «артефакты хода» → «файлы для клиента», строка spec §14 о бакете обновляется.
  - Бакет `raditi-artifacts` не переименовывается, двоичные части лежат под `artifacts/<wsId>/<artifactId>/<fileId>`.

### Виды

- **Ар6. Очереди видов** (§4).
  - Первая: «Документ» → «Макет» и «Таблица» → «Холст» и «Фирменный стиль».
  - Вторая: «Схема», «Презентация», «Изображение», «Структура сайта», «Отчёт».
  - Дальше — остальные.

  «Таблица» стоит в первой очереди: её ценность — 5, а цены — главная задача одиночки. «Фирменный стиль» нужен холсту. Ревью; ответ владельца 19.11.2026: «первая очередь норм».
- **Ар7. Реестр видов** по правилу 8: `artifactKinds` и `artifactKindSpecs` в `@repo/domain/artifacts`. В записи вида:
  - виды блоков и их схемы;
  - пределы;
  - отрисовка;
  - публикация и выгрузки;
  - очередь `wave`.

  `artifact_create` принимает только виды, у которых уже вышла отрисовка. Выбор — в одном месте. Ушедший вид читается через `known()`. Ревью.
- **Ар8. Холст.**
  - Экран — один адаптивный кадр, холст показывает его двумя видами рядом: компьютер (1440) и телефон (390).
  - Варианты А и Б — отдельные кадры.
  - При «Опубликовать как сайт» кадр экрана становится одной страницей.
  - На холсте оба вида по умолчанию — миниатюры с сервера, живыми становятся по правилу §7.7. Высоту вида кабинет берёт из серверного рендера при высоте окна устройства (900 и 844), мост (Ар29) уточняет её у видимых кадров вместе с шириной. Рамку по высоте из моста кабинет не растит: страница с `100vh` иначе растёт без конца. В Chromium высоты моста и рендера совпали до пикселя, в WebKit — до 42 px иначе. Спайк 6 (Э0а).

  Посетитель с телефона увидит тот же HTML, что и согласованный телефонный вид. Ревью: два отдельных кадра на компьютер и телефон опубликовать одной страницей нельзя.
- **Ар9. Ручная правка HTML-видов** (макет, холст, презентация, изображение). Ревью: владелец просил холст «как сейчас в claude code», где человек сам перепечатывает текст.
  - **«Править текст»** — режим кабинета.
    - Кадр открывается в рамке правки без скриптов — маршруте кабинета `/api/artifact-frame/<токен>` вне `headers()` `next.config.ts`. `sandbox="allow-same-origin"` без `allow-scripts` стоит и в атрибуте, и в CSP; ещё `script-src 'none'`, `default-src 'none'`, `frame-ancestors 'self'` (заголовки — §7.9). Скрипты артефакта в ней не выполняются ни в одном движке, подделать правку скриптом артефакта нельзя. Спайк 1 (Э0а): 0 из 31 вектора артефакта и 0 из 22 новых векторов проверки в Chromium, WebKit и Firefox.
    - Кабинет не опирается на обработчики событий внутри рамки: WebKit (Safari и все браузеры iPhone) их на узлах такой рамки не вызывает. Мышь и касания кабинет берёт на своём слое над рамкой (у рамки `pointer-events: none`), элемент находит `elementFromPoint`, обводку рисует сам и пересчитывает на своём `requestAnimationFrame`. Спайк 1 (Э0а).
    - Правка — родной `contenteditable="plaintext-only"` на одном элементе. Каретка — из точки клика (`caretPositionFromPoint`), изменения читает MutationObserver кабинета, конец правки — клик по узлу кабинета или «Готово». Перевод строки (`<br>` в WebKit и Firefox, `\n` в Chromium) кабинет приводит к тексту при фиксации; спайк этого не проверял, проверка — в Э5. На телефоне — своё поле кабинета поверх элемента (Ар49). Спайк 1 (Э0а).
    - Сервер заранее ставит элементам id и правит исходник по смещениям разбора `parse5` (`sourceCodeLocationInfo`, `scriptingEnabled: false` — как разбирает браузер без скриптов): заменяет «щели текста» элемента между его дочерними элементами. Повторный id (клон adoption agency), текст не на своих смещениях (foster parenting) или изменённый состав элемента — отказ. Живой DOM не сериализуется — так устроены Dyad и lovable-tagger (f2). Спайк 1 (Э0а).
    - Копия для правки отличается от хранимой только ссылками: они ведут на фрагмент без цели, без `target`, `ping` и `download`, в ней нет `<base>` и `<meta http-equiv="refresh">`, обезврежены и `xlink:href` у `<a>` в SVG, и `href` у MathML. Отменить переход по ссылке в WebKit нечем. Спайк 1 (Э0а).
    - Маршрут отвечает только запросу рамки своего origin (`Sec-Fetch-Dest: iframe`, `Sec-Fetch-Site: same-origin`). Открытый вкладкой, он и так ничего не выполняет, но тогда обе оставшиеся линии сидят в одном заголовке. Спайк 1 (Э0а), предложение проверки.
    - В рамке правки скрипты макета не работают: нет того, что строит JS, виден `<noscript>`. Подпись в кабинете — «В режиме правки скрипты макета выключены».
    - Правка уходит операцией `edit` в этот блок, только простым текстом: разметка экранируется. Работает с арендой человека, бесплатно.
    - Запасной путь (миниатюра и карта рамок с сервера) не нужен: рамка правки работает в трёх движках. Спайк 1 (Э0а).
  - **Блок «Настройки»** — JSON: цены, коэффициенты, цвета, тексты кнопок, с формой в кабинете. Платформа кладёт его в собранный документ как `<script type="application/json" id="raditi-settings">`, скрипт макета читает оттуда. Агенту дано указание выносить числа туда.
- **Ар10. Шаблоны первой очереди** — восемь штук (§4). Шаблон — просьба в черновик нового чата и вид. «Сделать шаблоном» — вторая очередь. Ревью.

### Хранение и модель

- **Ар11. Модель — расширение `chat_documents*` на месте, в два выпуска** (§7.1). Ревью: миграция применяется, пока работает старый код (`infra/server/deploy.sh:157-167`).
  - **Первый выпуск — только новые столбцы:**
    - `rank` рядом с `position`: новый код пишет оба, читает `rank`;
    - `owner_user_id NULL` с повторяемым заполнением от владельца пространства;
    - `content` и `pending_*` с заполнением `content` из Markdown проверенных разделов;
    - CHECK ослабляется: запись сделал ход или человек;
    - CHECK версий поднимается до 2 МиБ.

    Код окна выкладки понимает обе формы строки.
  - **Второй выпуск:** `NOT NULL` у владельца, затем `@ignore` и `DROP` у `position` и `markdown`.
  - **Без переименований.** Id блока — нынешний `section_key`, ключи не переписываются. Модели Prisma — `Artifact*` с `@@map`, таблицы не переименовываются (В7 плана 73).
- **Ар12. Где что лежит и как попадают фото.** Ревью: фото — главное у владельца-одиночки, а у `artifact_files` не было писателя.
  - **Хранилище.** Текст и HTML — в PostgreSQL. Двоичное — в S3 по Ар5.
  - **Ссылка и показ.** В содержимом лежит ссылка `artifact-file:<id>`, а не адрес. Рамка получает подписанный адрес: 5 минут, привязан к зрителю, роль перепроверяется при каждой отдаче. Отдача — только с корня домена страниц по правилам общих файлов сайта (Дер34): список типов, сверка сигнатуры, SVG только с `sandbox`, HTML никогда, `nosniff`, `CORP: cross-origin`, у шрифтов — ещё `Access-Control-Allow-Origin: *`: Chromium и Firefox просят их CORS-запросом с `Origin: null`, картинкам ACAO не нужен (Спайк 2 (Э0а)). С origin кабинета — никогда.

  - **Публикация.** Использованные файлы копируются в `page_files` (`/_files/…`), ссылки переписываются: превью и страница грузят одни и те же байты. Шрифты из `page_files` грузятся только после `Access-Control-Allow-Origin: *` в `pageFileHeaders` (ошибка production, план 73). На сайте с паролем, пока Дер35 держится на cookie, шрифты и модули из `/_files/` не грузятся, а в Firefox по умолчанию и в Chromium без сторонних cookie — ни один файл. До исправления мост кладёт шрифт `data:` во встроенный `<style>` страницы, а фото на таком сайте в этих браузерах не покажутся (Спайк 2 (Э0а), вопрос 25).

- **Ар13. Версии.** Ревью.
  - **Как хранится.** Версия — список пар «id блока, `rev`», а содержимое ревизий хранится один раз (`artifact_block_revisions` по хешу): неизменённые блоки не копируются.

    - после хода;
    - после серии ручных правок (склейка 5 минут);
    - по «Сохранить версию» с меткой до 60 знаков;
    - перед «Вернуть».
  - **Сколько хранится.** Названных — до 100 на артефакт, названные агентом считаются автоматическими. Автоматических — последние 50.

  - **«Отменить правки этого хода»** — отмена операций хода по чату и номеру хода, только у блоков, не изменённых с тех пор. `/undo` предлагает её или говорит «правки в артефакте остались — отмените их в истории».
  - **Страницы не меняются:** у них возврата версии нет (Ст16), у артефакта он есть — вопрос 7.

### Совместная работа

- **Ар14. Сервер — власть.** Ревью: `opId` придумывает модель и может повторить.
  - Блоки с номером правки `rev`, у артефакта — `seq` последней операции.
  - Формат операции один у кабинета и у агента (§7.2).
  - Повтор пакета узнаётся по таблице пакетов «`opId`, SHA-256 канонического пакета, ответ». Тот же `opId` с другим хешем — отказ `ARTIFACT_OP_REUSED`.
  - `insert` может нести свой id блока по правилу `section_key`, иначе id даёт сервер. Внутри пакета блоки ссылаются друг на друга по этим id.
- **Ар15. Правило конфликтов.**
  - `replace`, `move` и `delete` требуют `ifRev`. При несовпадении ничего не меняется, отказ `ARTIFACT_STALE` возвращает текущий блок.
  - `edit` — правка по цитате, ровно одно вхождение, на текущий текст. Нет вхождения — `ARTIFACT_FIND_NONE`, несколько — `ARTIFACT_FIND_MANY`.
  - Свойства, которые решаются по правилу «последняя побеждает», — только числа и перечисления: место, размер, цвет заметки. Строки идут через проверку (Ар19).
  - Правки разных блоков не конфликтуют.
- **Ар16. Запись агента держит блок до проверки.** Ревью: иначе в окне между записью и проверкой второй агент затирает первого, а записи упавших ходов висят до 24 ч.
  - Запись сразу даёт блоку новую `rev` в состоянии «проверяется» и держит блок за пишущим ходом. Другие агенты получают `ARTIFACT_BLOCK_HELD` с причиной `checking`.
  - Человек может «Забрать правку»: тогда запись агента отклоняется.
  - Упавший или отменённый ход сразу проверяет свои записи (`recoveredTextRefusal` по значениям из Vault) или сбрасывает их и снимает аренды. `TaskSweep` проверяет блоки восстановленного хода так же. Сборщик ищет «проверяется» по времени записи блока, а не по `updated_at` артефакта.
- **Ар17. Человек важнее агента.**
  - **Аренда человека.** Блок, который правит человек, держит аренда `human` на 30 с, продлевается при наборе. Запись агента туда — `ARTIFACT_BLOCK_HELD`.
  - **Аренда агента.** Агент держит блок на время записи и проверки, `artifact_claim` — до 2 минут с намерением. Человек видит «Пишет агент» и может «Забрать правку» (D-conflict, слева).
  - **Если аренда человека истекла.** 30 с без набора — и агент успел изменить блок. Тогда следующая запись человека сливается тремя сторонами, а при пересечении открывается окно «Разошлись» с текстом агента (D-conflict, справа). Ревью.
- **Ар18. Два человека в одном блоке** — трёхстороннее слияние (diff3). Пересеклись — «Разошлись»: «Оставить мой», «Взять другой», «Совместить вручную»; обе версии в истории. Посимвольная совместная печать (CRDT) — не сейчас (§8).
- **Ар19. Что видно до проверки.** Ревью: правило 2, Ст19.
  - **Текст агента.** Всё, что увидит кто-то кроме пишущего чата, идёт через «проверяется» и проверку `core`: содержимое блоков, название, намерения, `lease_intent`, строки свойств, ячейки таблицы, ответы в тредах, метки версий. До проверки другие видят «Пишет агент…» и прежнее значение. `artifact.changes`, чтение другими чатами и версии берут только проверенное, журнал непроверенного не хранит.
  - **Правка человека с формой секрета** отклоняется (`ARTIFACT_SECRET_SHAPE`: «Похоже на пароль или ключ — храните его в «Настройки → Переменные»»). В блок, версии и журнал она не попадает — как у файлов проекта (ПР8) и памяти.
- **Ар20. Канал изменений.** Ревью: одинаковая нагрузка склеивается в транзакции, `seq` в нагрузке — нет.
  - Нагрузка `NOTIFY raditi_artifact` — только `<artifactId>`, триггер на уровне оператора, `relay` склеивает за 50 мс. Подписка tRPC `artifact.signals` по SSE — одна на страницу, доступ перепроверяется раз в 15 с. Затем `artifact.changes({ sinceSeq })`, запасной опрос — 15/20 с.
  - Аренды и присутствие идут без NOTIFY. Присутствие и курсоры — эфемерный канал Redis из web, отметка раз в 15 с, срок 30 с.
  - Условие этапа Э2 — замер времени фиксации под 8 ходами и набором текста (план 86, §4).
- **Ар21. Несколько агентов.** Ревью.
  - Каждый чат действует с правами того, кто его ведёт.
  - Ответ инструмента несёт `seq` и `changedSinceYourRead`: число изменённых другими блоков и первые 50 id с `more` (`artifact_chats.read_seq`).
  - Название чата видит только его хозяин, другие — «Агент <Имя>». Правка другого человека или его агента не пишет строку в чужую ленту, а даёт владельцу уведомление «<Имя> изменил(а) «…»» и строку в «Все изменения».
  - За ход — не больше 120 записей, 20 разных артефактов и 10 созданий.

### Показ и безопасность

- **Ар28. Рамка.** Ревью: HTML теперь пишут и другие люди.
  - Своя константа `ARTIFACT_SANDBOX = 'allow-scripts'`, без `allow-popups` и `allow-popups-to-escape-sandbox`, — в атрибуте и в CSP.
  - Ссылки из макета открывает кабинет методом моста «открыть ссылку»: показывает адрес и спрашивает подтверждение.
  - Роль зрителя проверяется на каждый GET `/v/`, как сегодня у файлов чата.
  - Шрифты и библиотеки — отдельным путём `/v/<метка>.<хеш>` (его уже пропускает `PAGES_PATHS`, своих заголовков на `/v/` `next.config.ts` не ставит) с `Cross-Origin-Resource-Policy: cross-origin` и `Access-Control-Allow-Origin: *`. `same-origin` и `same-site` нельзя ни одному ответу: непрозрачная рамка всем чужая (`Sec-Fetch-Site: cross-site`). Шрифтам в Chromium и Firefox, модулям и `import()` везде нужен ACAO, остальному — CORP не `same-origin`. Метка библиотеки отличается от токена кадра: оба вида `a.b` и попадают в один маршрут `v/[token]`. Спайк 2 (Э0а).
  - CSP рамки называет точные адреса файлов, включая то, что библиотека тянет сама (модули её `import`, шрифты её CSS): 64 адреса — 3 612 байт заголовка, работает во всех движках. `'self'` тоже работает, но шире. Спайк 2 (Э0а).
  - Ответ библиотеки: тип из реестра файлов платформы, `nosniff`, CORP `cross-origin`, ACAO `*`, `Cache-Control: public, max-age=31536000, immutable`, `Content-Security-Policy: default-src 'none'; sandbox; frame-ancestors 'none'`, `Referrer-Policy: no-referrer`. На HTML-ответах `/v/<token>` ACAO не ставится никогда. Спайк 2 (Э0а).
  - Рамка правки (Ар9) — отдельный элемент `<iframe>` с постоянным `sandbox`. «Просмотр» и «Править текст» — разные элементы (в React — `key` по режиму): если источник поменять раньше `sandbox`, Chromium и Firefox грузят новый документ со старыми флагами. Спайк 1 (Э0а).
  - Никогда — `srcdoc` со скриптами и origin кабинета.

- **Ар29. Мост postMessage** (режим просмотра).   - **Взгляд — помощник `look`.** Это подагент OpenCode на `glm-5.3-flash` через ту же роль `llm`, уровень `low`. Главная модель хода остаётся `glm-5.3`, ключ провайдера в песочнице не появляется.
    - **Откуда снимок.** Помощник вызывает `artifact_render`: `mcp` просит `apps/browser` нарисовать сохранённый кадр и возвращает картинку результатом инструмента (`type: "image"`). Видит её только `look`: у главной модели входа `image` нет. Полосы JPEG q70 по 2 000 px — 47–334 КиБ на ширину, четыре картинки — до 1,3 МиБ (Спайк 3 (Э0а)).
    - **Когда.** Один раз в конце хода холста, макета или изображения и по просьбе клиента. Не больше 3 проверок за ход и 4 картинок за проверку. Около 0,08–0,26 кредита и 20–60 с.
    - **Что нужно:**
      - вход `image` у `glm-5.3-flash` в драйвере, агент `look` и `task: look` в настройках OpenCode;
      - блок `image_url` в политике тела `llm` — только для этой модели;
      - профиль `glm-5.3-flash-low` и его ставка по П3: 16,306 / 3,261 / 54,352 ₽ за 1 млн токенов, записывается командой `billing:rates`;
      - живая проверка на синтетике: адрес плана принимает `image_url`, а OpenCode 1.18.34 доносит картинку.
  - **Данные.** Пиксели фото клиента внутри макета уходят модели только там, где ход и так получает его данные: под гейтом 152-ФЗ, класс `client` — с записью `cross_border_clearances`. Это меняет N22 для артефактов. Б20 (скриншоты облачного браузера модели не отдаются) и «фото отложим» для фото в чате не меняются: зрение — только для проверки своих артефактов.
  - **Платформа сама** зовёт Z.ai в обход OpenCode только на `zai-api`: на плане это запрещают условия.

### Доступ

- **Ар33. Ссылка — только для вошедших, и для просмотра тоже.** По словам «шеринг на пользователей» и Ст2. Ревью.
  - **Адрес** — только `https://raditi.ru/a#<token>`, токен во фрагменте; запасного адреса нет. Фрагмент не уходит на сервер ни из одного браузера, ни через перенаправления края, ни в `Referer`. Спайк 8 (Э0а).
  - Страница `/a` отвечает 200 на любой GET и не перенаправляет, пока скрипт не прочитал фрагмент и не стёр его (`history.replaceState`): перенаправление уносит фрагмент в адрес следующей страницы. Ссылка выдаётся только с `https://` (HSTS web): WebKit на macOS отдаёт фрагмент адреса `http://` HTTP-прокси клиента. У `sw.js` нет обработчика `fetch`, который пишет или отправляет `request.url`: сервис-воркер видит фрагмент. Спайк 8 (Э0а).
  - **Токен** — 32 случайных байта, в базе хранится только SHA-256. Роль — на ссылке.
  - **Срок** по умолчанию — без срока, на выбор 7 или 30 дней. «Новая ссылка» отзывает прежнюю.
  - **Страница `/a`** — без скриптов третьих лиц, `no-store`, `noindex`, `Referrer-Policy: no-referrer`. Доступ записывается только POST «Открыть» после входа и согласий. `Referrer-Policy` ставится более поздней записью `headers()` в `next.config.ts` с `source: '/a'` или в `proxy.ts`: заголовок обработчика маршрута общий `Referrer-Policy` не перебивает (Спайк 8 (Э0а)).
  - **Без входа** токен на час уходит в cookie `__Host-raditi_share; Secure; HttpOnly; SameSite=Lax; Path=/`, вход идёт на `/sign-in`, а после регистрации кабинет предлагает «Открыть то, чем с вами поделились» (E-signin).

### 7.2. Операции

Один формат у агента (`artifact_edit`) и у кабинета (tRPC `artifact.apply`):

```ts
type ArtifactOps = {
  artifactId: string
  opId: string                 // повтор: тот же opId и тот же хеш пакета — тот же ответ; другой хеш — ARTIFACT_OP_REUSED
  ops: Array<
    | { op: 'insert'; block?: string; after: string | null; parent?: string; kind: BlockKind; content?: string; props?: Props; intent?: string }
    | { op: 'replace'; block: string; ifRev: number; content: string; props?: Props }   // props — только тексты блока (88.0)
    | { op: 'edit'; block: string; find: string; replace: string }          // ровно одно вхождение find
    | { op: 'move'; block: string; ifRev: number; after: string | null; parent?: string }
    | { op: 'delete'; block: string; ifRev: number }
    | { op: 'props'; block: string; props: Partial<Props> }                 // числа и перечисления — «последняя побеждает»
    | { op: 'title'; title: string }
    | { op: 'cells'; block: string; cells: Record<string, Cell> }
  >
}
// отказы: STALE | FIND_NONE | FIND_MANY | BLOCK_HELD (human | checking | claim) | LEASE_LOST | TOO_LARGE | KIND_REFUSED |
//         SECRET_SHAPE | LIMIT | FORBIDDEN | OP_REUSED | DATA_CLASS
//         NOT_FOUND | OP_INVALID (88.0)
```

- **Применение.** Одна короткая транзакция. Строка артефакта берётся `FOR NO KEY UPDATE` (ради `seq`), операции трогают только названные блоки по индексу. Перенумерации нет (`rank`), `bytes` считается приращением, замка на весь ход нет.
- **Пакет атомарен.** Пределы:
  - JSON — до 90 КиБ, узлов — до 4 000; узел — значение JSON, ключи не считаются;
  - операций — до 50;
  - блок — до 32 КиБ; у кадра — по исходнику с id, которые ставит сервер: они добавляют 13–29 % объёма (Спайк 3 (Э0а)).

  Спайк 5 (Э0а): предел 50 операций делит вставку 300 строк таблицы на 6 неатомарных пакетов, и отмена тоже идёт шестью. Поэтому `cells` таблицы в `artifact.apply` кабинета предела 50 операций не считают, пакет держат 90 КиБ и 4 000 узлов: 300 строк × 6 столбцов (64 КиБ, около 3 000 узлов) идут одним пакетом. Длинные строки (300 строк с примечаниями по 1 000 знаков — 743 КиБ) — через `artifact_import`. Агенту остаются 120 записей за ход (Ар21). Если в пакете есть строка, которую держит агент (`BLOCK_HELD`), кабинет вставляет остальное вторым пакетом и называет пропущенные строки. По умолчанию.
- **Кадр** — это контейнер `frame` (свойства: экран, вариант, место) и упорядоченные дети: `html`-части, каждая до 32 КиБ, а также `style` и `script`. Документ кадра собирает платформа при отдаче `/v/`. Импорт режет большой HTML по верхним элементам.
- **`outline`** отдаётся страницами по 200 блоков.

### 7.4. Канал изменений

- **Триггер:** `AFTER INSERT ON artifact_ops REFERENCING NEW TABLE … FOR EACH STATEMENT` → `pg_notify('raditi_artifact', <id>)` по разу на артефакт. `TaskSignalRelay` получает второй канал.
- **Подписка** `artifact.signals({ artifactIds })` — одна на страницу: на странице чата темы артефактов идут тем же EventSource, что и сигналы чата.
- **Присутствие** web пишет в Redis раз в 15 с и рассылает через Redis pub/sub, без PostgreSQL.
- **Агенты** подписок не ждут: каждый ответ несёт `seq` и `changedSinceYourRead`.

### 7.7. Показ в кабинете

- **Документ** — блоки рисует `DocumentMarkdown` (`rehypeDocumentRules`).
  - Ручная правка раздела — редактор на раздел: Tiptap 3 (`StarterKit` без `underline`, таблицы, список задач, `Image` с `inline: true`, метка `code` без `excludes`, заголовки 3–6, `extension-unique-id`) и `mui-tiptap` (MIT, под MUI 9). Markdown в редактор и обратно переводит не `@tiptap/markdown`, а свой мост mdast ↔ документ Tiptap на том же remark, что рисует `@repo/doc-render`; мост — один модуль у кабинета и сервера. В схеме редактора — признак `spread` у списков и пунктов и узлы сносок; заголовок без переносов строк, в ячейке один абзац, у таблицы всегда есть строка заголовка. Спайк 4 (Э0а): `@tiptap/markdown` 3.34.0 меняет видимые слова в 15 из 30 документов (неразрывные пробелы в таблицах, сноски, экранирование, ссылки), а правка одного слова переписывает чужие строки в 17 из 29.
  - Сервер приводит каждую запись агента и человека к тому, что отдаёт мост: `toMarkdown(toDocument(md))`. Сериализатор: `bullet: '-'`, `bulletOther: '*'`, `rule: '-'`, `emphasis` и `strong: '*'`, `` fence: '`' ``, `listItemIndent: 'one'`, `setext: false`, `tablePipeAlign: false` (без выравнивания пробелами; выравнивание столбцов `:-` и `-:` остаётся). Правила дерева: сырой HTML уходит, `<br>` — перенос строки, ссылки по номеру — обычными, смешанный список задач делится, у кода уходит `meta`, выделения вкладываются в одном порядке; заголовки 1–2 уровня внутри раздела, и подчёркнутые тоже, становятся 3-м (по умолчанию). Версии `remark-*` и `mdast-util-*` закрепляются точно — прямой зависимостью пакета моста или `overrides`; обновление канона — миграцией. Спайк 4 (Э0а).
  - Поэтому круг «редактор → Markdown → редактор» ничего не портит: на 30 документах, 129 разделах и 109 конструкциях спайка и 52 новых конструкциях проверки текст возвращается байт в байт. Кавычки «», „“, тире, неразрывный пробел (и в таблицах), «ё» и сноски сохраняются, правка слова меняет одну строку. Спайк 4 (Э0а).
  - `<br>` в ячейке таблицы канон делает пробелом, и строки внутри ячейки сливаются. По умолчанию — так; другой путь — держать `<br>` и научить doc-render его рисовать.
  - Мосту и канонизатору нужен свой пакет слоя сервисов: `doc-render` по правилу `doc-render-npm` своего конвейера unified не держит, у `mcp` `doc-render` нет, в `domain` — только `zod` и `decimal.js`. Пакет и место канонизации записи агента (`mcp` при записи или `core` при проверке) решает срез 88.10 (88.0 его не решил: `@repo/domain` remark не несёт). Спайк 4 (Э0а).
  - Цитаты агента в `edit` ищутся сначала в исходнике блока, затем в видимом тексте (текст узлов mdast без разметки и сносок, замена — в найденном текстовом узле). Канон меняет около 4 % строк агента: по исходнику находятся 480 из 498 цитат, по видимому тексту — 497. Спайк 4 (Э0а).
  - `extension-unique-id` — для работы редактора, не для якорей: id узлов живут одну сессию, Markdown их не несёт. Якоря комментариев — цитаты и ячейки (Ар53). Спайк 4 (Э0а).
  - Вставка из Google Docs работает (проверен один случай: жирный из стиля и список). Импорт Word — `mammoth` и `turndown`, во второй очереди.
- **Макет** — рамка `/v/<token>` с `ARTIFACT_SANDBOX`. Переключатели:

Живой вид — у кадров в поле зрения при масштабе от 30 %, не больше 4 одновременно, и в окне «Открыть». На телефоне холста нет, кадры — списком миниатюр (Ар49). Спайк 6 (Э0а): 20 живых рамок в настольном Chrome — 1 286 МБ всего браузера против 602 МБ у доски из миниатюр, а правило «видимые от 30 %, не больше 4» стоит столько же, сколько миниатюры. Когда рамки живут в процессе кабинета (Safari, телефоны), непрерывный масштаб при 6–20 живых рамках проседает до 53–23 кадров/с, при 4 — держит 60.
  - Рамка на холсте никогда не принимает указатель: у `<iframe>` — `pointer-events: none`, поверх — прозрачная крышка. Без крышки WebKit на macOS отдаёт рамке колёсико и щипок даже с `pointer-events: none`. Панорама, масштаб, выбор и двойной щелчок идут кабинету, перетаскивание — с захватом указателя. С содержимым кадра работают только в «Открыть»: рамка во всю высоту окна со своей прокруткой и кнопкой «Закрыть» — Esc изнутри рамки до кабинета не доходит. Спайк 6 (Э0а).
  - Пока холст масштабируется, живые рамки скрыты (`visibility: hidden`), видна миниатюра под ними: иначе тяжёлый скрипт одной рамки роняет масштаб до 36–43 кадров/с. Спайк 6 (Э0а).
  - Миниатюры кэшируются по хешу собранного документа кадра (части, «Настройки», «Фирменный стиль», файлы, версии шрифтов и рендера) и ширине и рисуются в фоне после ревизии, а не при открытии доски: доска из 10 экранов в двух видах — около 13 с работы одного контейнера на 1 CPU. Спайк 3 (Э0а).
  - Кабинет проверяет отклик живых кадров и заменяет миниатюрой тот, что не ответил. В WebKit и Firefox кадры живут в процессе кабинета, и зависший скрипт подвешивает кабинет; в Chromium — все живые кадры. Спайк 2 (Э0а), спайк 6 (Э0а); проверку отклика предложила проверка спайка 2.
  - Панель: «Выбор», «Рука», «Новый экран», «Заметка», «Комментарий».
  - У выбранного кадра: «Изменить в чате», «Сделать вариант», «Открыть», «Править текст».
  - В шапке — «Опубликовать как сайт» (C-canvas).
- **Таблица** — TanStack Table 9 с TanStack Virtual (MIT) и компонентами MUI. Спайк 5 (Э0а): 127 из 127 проверок в Chromium, WebKit и Firefox, 5 000 строк — 60 кадров/с и на телефоне с процессором в 4 раза медленнее, нового для кабинета — 40,2 КиБ gzip.
  - Вид — по ширине своей области, как у «Документов» (600 px): шире — сетка, уже — карточки. Карточка: название, цена, категория и единица, переключатель «В наличии»; остальное — в листе снизу, цена с цифровой клавиатурой (`inputmode="decimal"`). Панель рядом с чатом уже 600 px (на ноутбуке 1 280 px — 589 px) получает карточки. На телефоне сетка показала бы целиком только «№» и «Название».
  - Сетка: виртуальная прокрутка, липкие шапка и столбец названия, роли ARIA `grid` с `aria-rowcount` и `aria-rowindex`, «Столбцы» (скрыть, переставить, закрепить). Клавиатура — как в Excel: стрелки и Tab, правку начинают Enter, F2, двойной щелчок или набор, Esc отменяет, Delete очищает, пробел переключает флажок, Ctrl+Z отменяет свою правку. Сочетания — по `KeyboardEvent.code`.
  - Правки — свои и чужие — строк не двигают: сортировка и фильтр применяются по просьбе, после правки — «Порядок не обновлён — обновить». Порядок держит кабинет, TanStack получает готовый. Ключи сортировки считаются один раз на строку: иначе сортировка по цене 5 000 строк на медленном телефоне идёт до кадра 126–148 мс, с ключами — в 10 раз быстрее.
  - Вставка из Excel и Google Таблиц: блок от выбранной ячейки вправо и вниз, строки за концом — новые строки до предела, одно значение заполняет выделение. Что не подходит столбцу, остаётся прежним, сообщение называет причину. Копирование и вставка слушаются на документе: Firefox выбирает их цель по выделению, и сетка без выделения текста получает их в `<body>`.
  - Итоги считает сервер на `decimal.js`, формул в первой очереди нет.
  - «Скачать»: CSV — в браузере, через «;», с BOM, ячейки с «=», «+», «-», «@» в начале получают апостроф. Excel — §7.13 и вопрос 26 (C-table).
  - MUI X Data Grid в MIT-версии не берём: страница до 100 строк, вставка и выгрузка в Excel — только в платной.
- **Схема** (Э11) — итоговый SVG как `<img>` с `width` и `height` из `viewBox` и `max-width: 100%`. Если разбор не прошёл — «Схема не нарисована: ошибка в строке N» (или без номера, когда Mermaid его не дал) и текст схемы. Mermaid в кабинете и в рамке не исполняется. Спайк 7 (Э0а).
- **Присутствие** — аватары людей, пилюли агентов: свои — «Чат: …», чужие — «Агент <Имя>». У блока — рамка цвета участника и ярлык «Пишет агент». Курсоры людей — через Redis (D-together).
- **История** — «Версии / Все изменения», сравнение, «Вернуть эту версию» (с перечнем, чьи правки будут перезаписаны), «Отменить правки этого хода», «Сохранить текущую как версию…» (D-history).

### 7.8. Доступ

- **Функция доступа** `artifactRole(db, { artifactId, userId })` возвращает `owner`, `edit`, `comment`, `view` или `null`:
  - `owner` — владелец, если он жив и участник своего пространства (у артефакта проекта — ещё и автор проекта);
  - иначе — наибольшее право из живых грантов (грант ссылки — при живой ссылке);
  - удалённый, снятый или оставшийся без владельца артефакт доступа не даёт.

  Для агента и копии функция сверяет и класс данных: `client` → только `client`.
- **Кто её зовёт** — Ар37. Тест-матрица «право × путь» входит в срез 88.16 и в стенд.
- **Процедуры:** `artifact.share.create`, `.rotate`, `.revoke`, `.invite`, `.setRole`, `.remove`, `.closeAll`, `.open` (POST по токену), `.acceptInvite`, `.leave`, `.setCopy`. Предел открытий — по HMAC адреса (`admitInWindow`).
- **Страница `/a`** живёт вне `(protected)`: «Вам открыли доступ в Радити» без имени и названия, кнопки входа и регистрации (E-signin). После входа и согласий — экран «<Имя> открыл(а) вам документ «…» · Ваше имя увидят владелец и все, у кого есть доступ; почту — владелец · [Открыть]».

### 7.10. Мост к страницам

- **Кнопкой.** `pages.publishArtifact({ artifactId, versionNo, target })`, только при `artifactRole = 'owner'`. Страница создаётся в пространстве владельца. Это обобщение `publishDocumentPage` и `publishChatFilePage`.
- **Агентом.** `page_publish({ artifactId, … })` — резерв того же действия, проверка роли в `mcp` и в `core`.
- **Что публикуется** — выбранная версия-снимок. Снимок рисуется по виду:
  - документ — `readingPage`;
  - макет — собранный HTML;
  - холст — сайт: экран становится страницей по своему пути, общий стиль — `/_files/style.css`.

  Использованные файлы копируются в `page_files`, ссылки переписываются. Связи «кадр → страница» и опубликованная версия пишутся в `artifact_publications`.

Стенд проверяет это настоящим HTTP-сервером: `route.fulfill` Playwright сам ставит ACAO и прячет его отсутствие. Спайк 2 (Э0а), спайк 3 (Э0а).
- **Сломано и сейчас** (Спайк 2 (Э0а), план 73). Шрифты и модули из `/_files/` опубликованных страниц не грузятся в Chromium и Firefox: у ответа нет `ACAO`. На сайте с паролем в Firefox по умолчанию и в Chromium без сторонних cookie не грузится ни один файл `/_files/`, а где сторонние cookie разрешены, чужой сайт вставляет файлы закрытого сайта и исполняет его скрипт. Исправление — `Access-Control-Allow-Origin: *` в `pageFileHeaders` и подписанные адреса файлов вместо cookie у сайтов с паролем (вопрос 25).
- **Схема** (Спайк 7 (Э0а)). Mermaid 12.3.0 нарисовал 22 из 30 схем корпуса, в том числе все 17 верных; каждый из 8 отказов исправился одной правкой. Тёплый рендер — около 25 мс, p95 — до 146 мс. Устройство:
  - маршрут рендера в `apps/browser` без сети: рабочая и запасная страницы с Mermaid (новая готовится 0,55 с), таймаут 10 с, по таймауту и после ошибки контекст закрывается. Страница — на рабочее пространство, а не общая на всех клиентов (по умолчанию): если разбор Mermaid когда-нибудь исполнит скрипт, он не дорисует чужие схемы. Схемы живут в пуле рендер-контейнеров (§7.12);
  - настройки: `securityLevel: 'strict'`, `htmlLabels: false`, `maxEdges: 200`, шрифт `Arial, "Liberation Sans", sans-serif` — сервер меряет Liberation Sans, у клиента рисуется Arial той же метрики, за рамку вышла 1 подпись из 205. Golos Text — только подмножеством: полный набор — +72 КБ к каждому SVG;
  - нормализация текста до рендера: `%%{init}%%` и `config` во frontmatter вырезаются (иначе директива меняет `htmlLabels`, `fontFamily`, `themeCSS`, `arrowMarkerAbsolute`), ограждение и неразрывный пробел убираются, теги оформления — только целые и внутри одной подписи;
  - DOMPurify в jsdom с SVG-профилем и `RETURN_DOM_FRAGMENT`, затем доводка: имена SVG с заглавными буквами (parse5 8.1.1 превращает `feDropShadow` в `fedropshadow`, и Chromium с Firefox теряют рамки всех узлов), вырезка `@import` с учётом `url()` и строк, внешних `url()` и ссылок, кроме `#…`, размер из `viewBox`; затем `XMLSerializer`. Строка из `sanitize()` — HTML, а не XML: `<br>` и `&nbsp;` ломают `<img>`;
  - замер времени и памяти — в образе `apps/browser` на x64 под `runsc`, до среза.
- **Готовых эталонов** под модель «блоки + ревизии» нет: Vercel Chatbot, LibreChat и Open WebUI хранят документ целиком. У Open WebUI в 2026 году серия CVE о рамках с `allow-scripts` и `allow-same-origin`. Берём у них приёмы — реестр видов, режим «разница», предложение с привязкой к версии, — а не код.

## 8. Варианты реализации, которые разобраны

### 8.1. Как совмещать правки

| Вариант | Как работает | Плюсы | Минусы | Решение |
| --- | --- | --- | --- | --- |
| A. Целый объект + версия (CAS) | Запись всего артефакта с `expectedVersion` | Просто, уже есть у страниц | Любая чужая правка ломает запись; переписывать весь объект дорого и опасно | Только для операций над целым: публикация, «Вернуть» |
| **B. Блоки + номер правки + аренды, сервер — власть** | §7.2; запись агента держит блок до проверки (Ар16) | Ложится на PostgreSQL, сигналы плана 86 и живую проверку плана 74; каждая правка проверяется до показа; понятные отказы агенту | Посимвольной печати двух людей в одном абзаце нет — их сливает diff3 | **Основа** |
| C. CRDT Yjs + Hocuspocus | Посимвольное слияние, WebSocket | Лучшая печать людей вместе, офлайн | Сервер не проверит правку агента до показа (правило 2); правки одного абзаца сливаются молча; нужен новый сервис | Не сейчас; позже — только внутри текстового блока по данным журнала |
| D. Automerge / Loro | CRDT без центра | Офлайн, P2P | Нет проверки до показа | Нет |
| E. OT (ShareDB, ProseMirror collab) | Центральная власть над текстом | Классика для текста | Для агентов не подходит | Только как ядро будущей живой печати |
| F. Облачные движки (Liveblocks, Tiptap Cloud, y-sweet, PartyKit) | SaaS | Быстро | Данные за рубежом (правило 1); AGPL или ключ | Нельзя; берём только приёмы |

«Черновик» для большой переделки (Lovable drafts, ветки Base44 и Framer) — добавка поверх B во второй очереди: агент делает редизайн в копии, клиент «Принимает» с диффом.

### 8.2. Где хранить и как обобщить документы

- **(а) Расширить `chat_documents*` на месте в два выпуска** (выбрано, Ар11). Нет переноса данных, документы сразу становятся артефактами, а старый код в окне выкладки не ломается.
- **(б) Новые таблицы и перенос.** Имена чище, но двойное чтение, правка `pages.document_id` и риск ради имени.
- **(в) Файлы в S3 с версиями** (как у Claude Code). Нет блочной правки и проверки по блокам.

### 8.3. Как хранить версии

- **(а) Ревизии блоков по хешу, версия — список ссылок** (выбрано, Ар13). Неизменённые блоки не копируются.
- **(б) Полный снимок на версию.** До 2 МиБ на версию — до ≈100 ГБ на пространство при пределах.

### 8.4. Как показывать HTML и фото

- **(а) `/v/<token>` с `ARTIFACT_SANDBOX` и подписанными файлами на корне страниц** (выбрано, Ар12, Ар28).
- **(б) `srcdoc` в кабинете.** Запрещено: у CSP кабинета нет `script-src`.
- **(в) Отдельный регистрируемый домен** с источником на каждый артефакт. Нужен только «живым» артефактам с сетью — их в плане нет. Ради отзывчивости он не нужен: в настольном Chrome рамки с хоста страниц и так живут в своём процессе, с другого сайта — те же процесс и память; в WebKit 26.6 и он не разводит кадры и кабинет. Спайк 2 (Э0а), спайк 6 (Э0а).
- **(г) Фото `data:` в блоке.** Не помещается в 32 КиБ.
- **(д) Внешние `https:`-картинки.** Утечка адреса зрителя: Ст9 принял её только для опубликованного.
- **(е) Рамка правки на origin кабинета без скриптов** — выбрана для «Выбрать элемент» и «Править текст» (Ар9). `srcdoc` для неё хуже маршрута: нужна meta CSP первой в `head`, иначе наружу уходят CSS, шрифты и GET к кабинету с cookie; якоря уводят рамку на адрес кабинета; meta CSP не умеет `sandbox`, и при случайном `allow-scripts` рамку уводит `meta refresh`; `srcdoc` наследует `img-src` и `frame-src` кабинета. Спайк 1 (Э0а).

### 8.5. Как делиться

- **(а) Ссылка-ключ для вошедших и ожидающие приглашения, гранты по источнику** (выбрано, Ар33–Ар35).
- **(б) Получатель в `members`.** Нельзя: он увидит всё пространство.
- **(в) Публичная ссылка на артефакт.** Это вторая система отзыва и злоупотреблений рядом со страницами, а по 152-ФЗ — «распространение».
- **(г) HMAC-ссылка без строки в базе.** Не отзывается по одной.
- **Адрес:** фрагмент `/a#…` (выбрано). `/a?k=…` — отклонён (Спайк 8 (Э0а)): край строку запроса не пишет (`--accesslog.fields.queryparameters.defaultmode=drop`, точное значение), но адрес держится на нескольких настройках Traefik — ровно один флаг `drop`, никакого `keep` для заголовков, `--log.level=INFO`. Токен доходит до процесса web, а без `Referrer-Policy: no-referrer` и при перенаправлении на вход уходит в `Referer`, `?next=` и `Location`. Выгоды такой адрес не даёт. Путь `/a/…` попадает в журнал.

### 8.6. Вкладка справа

- **(а) Одна вкладка «Артефакты» со списком и файлами чата.** Была значением по умолчанию: помещается при любой ширине.
- **(б) Вкладка на каждый артефакт** — выбрал владелец 19.11.2026 (Ар44). Три вкладки помещаются только от ≈550 px панели, поэтому тесноту держат обрезка названий и пилюля «Ещё N».

### 8.7. Что агент получает о чужих правках

- **(а) `changedSinceYourRead` в ответах** (выбрано). Дёшево, без подписок.
- **(б) Подписка MCP на ресурсы.** OpenCode 1.18.34 её не подтверждает, в 2026-07-28 механизм другой. Позже.
