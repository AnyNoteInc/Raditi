# 83. Без проектов: чаты, страницы и переменные в настройках

Запрос владельца от 15.11.2026:

> удаляй проекты и все, что связано с проектами
> - gitea
> - инстансы joomla & wordpress
> - vault нужно оставить, сделать доступным в настрйоках и для всех агентов
> - удали скачивание репозитория через ftp ssh и так далее
>
> должно остаться чаты, страницы, в настройках должен появиться vault переменные из которого доступны для любого агента, параметры подключения удали
>
> при выкатке нового релиза удаляй неиспользуемые контейнеры, а также из traefik raditi-preview.ru

Ответы владельца на вопросы того же дня:

- данные проектов в production — **удалить таблицы, чаты проектов остаются чатами без проекта** (история ленты сохраняется; откат — только из дампа);
- переменные — **всем чатам рабочего пространства, без флажка «передавать агенту»**; в пространствах `client` до гейта 152-ФЗ — как сейчас, не выдаются (с 17.11.2026 — выдаются и им, решение владельца, БП14 spec §20);
- главная — **убрать раздел платформ, заявку оставить**;
- навыки агента (MCP-серверы плана 81, слитого в `main` тем же днём) — **перенести в пространство**;
- работа — в отдельном дереве `raditi-noprojects`, ветка `feat/remove-projects` от `main` `cef48b03`.

## Решения

| № | Решение | Откуда |
| --- | --- | --- |
| БП1 | Проектов (сайтов) в продукте нет: ни мастера `/projects/new`, ни страниц `/projects/*`, ни выбора проекта у поля, ни параметров подключения (SSH, FTP, база, вход в админку) | владелец |
| БП2 | Удаляются Gitea и `git-providers`, git ходов и доверенная публикация, первоначальный импорт по SFTP и FTP (`site-provisioning`, `site-connections`), предпросмотры, `/release`, выпуски, API выпуска, `deploy-step`, `ci/`, адаптеры CMS (`site-adapters`: WordPress, Joomla, Битрикс), плагин «Радити», рецепты Joomla, образы `site` предпросмотра, контент MCP (`wp_rest`, `restore`) и браузер агента на предпросмотре (`browser_*`) | владелец |
| БП3 | Остаются: чаты (`/chats`), ход в песочнице без репозитория, облачный браузер чата на публичных `https://`-сайтах (`web_*`), страницы и сайты страниц (планы 67, 69, 73), биллинг, вход, Telegram (план 80), веб-поиск, Vault | владелец |
| БП4 | Переменные — раздел «Настройки → Переменные» (`/settings/variables`) рабочего пространства. Значение — в Vault `kv/workspaces/<workspaceId>/env/<NAME>` (одна версия, пишет web, обратно не читает); описание — строка `workspace_env_vars` (имя, версия ключа, кто и когда). Каждый ход любого чата пространства получает все переменные в командах `bash` агента (`BASH_ENV`), значения маскируются в событиях и архиве home, как прежде. Флажка `to_agent` и хостов нет: интернет хода открыт с 26.10.2026. С 17.11.2026 класс данных пространства не проверяется: переменные получает и пространство `client` (решение владельца, БП14 spec §20) | владелец; хосты — значение по умолчанию |
| БП5 | Переменные сайтов в новый раздел не переносятся: их значения лежат в Vault под путём сайта, который удаляется вместе с сайтом; клиент задаёт их заново | значение по умолчанию |
| БП6 | Миграция удаляет таблицы и типы проектов; у `tasks`, `browser_sessions`, `chat_sessions`, `attachments`, `channel_identities`, `credential_refs`, `mcp_calls`, `turn_assignments`, `task_turns` уходят колонки сайта, кандидата, предпросмотра и выпуска; чаты проектов остаются чатами без проекта (`site_id` → нет колонки, требования — без репозитория). Таблица аренды остаётся, ключ — id чата | владелец |
| БП7 | Команды чата, которым нужен репозиторий (`/release`, `/preview`, `/update`, `/reset`, `/rollback`, `/init`, `/retry`), удаляются; `/undo`, `/redo`, `/compact`, `/cancel`, `/thinking` и остальные остаются | следствие БП2 |
| БП8 | Главная: раздел «Пять систем. Один чат.» удаляется, форма заявки и её путь в Telegram остаются; строки тарифа о числе сайтов-проектов (`plans.max_sites`) уходят, сайты страниц (`page_sites`) остаются | владелец |
| БП9 | Сохранённый вход браузера (Б36, `SITE_ADMIN_*`) и политика стека уходят вместе с сайтами: браузер чата всегда в режиме открытого веба | следствие БП1 |
| БП10 | Выкладка (`infra/server/deploy.sh`) удаляет контейнеры, которых нет в compose (`--remove-orphans`), контейнеры удалённых служб (Gitea, раннер выкладки, предпросмотры по метке `raditi.preview.owner`) и их тома; Traefik больше не обслуживает `raditi-preview.ru` (маршрут `preview-apex`, резолвер `preview`), DNS-01 reg.ru остаётся резолверу `pages` | владелец |
| БП11 | Навыки агента — у рабочего пространства: «Настройки → Навыки агента» (`/settings/skills`), таблица `workspace_agent_skills` (миграции `20261116120000_credential_kind_mcp_server_workspace` и `20261116120100_workspace_agent_skills`), ключ MCP-сервера — Vault `kv/workspaces/<workspaceId>/mcp/<имя>` (пишет web политикой `sites-writer`, читает и обновляет `mcp` политикой `mcp-content`), роутер `agentSkills`; ретранслятор `mcp` находит сервер по пространству хода, планировщик даёт навыки пространства каждому чату. Навыки сайтов не переносятся | владелец, ответ от 15.11.2026 |
| БП12 | Главная — «ИИ-помощник на каждый день» (запрос владельца от 15.11.2026: «текста на главной странице давай уберем о подключении сайта, давай добавим текста о том, что это ии помощник на каждый день»): H1 «ИИ-помощник на каждый день для вас и вашего бизнеса», лозунг «Напишите в чат. Радити сделает.»; демо — та же вымышленная кофейня с повседневными задачами (сравнить цены поставщиков, письмо, страница по ссылке); «Что можно поручить» — шесть повседневных дел; раздел о контроле — «Вы видите, что делает Радити»; вопросы — что умеет, нужно ли устанавливать, сколько стоит задача, если результат не понравится, где данные; ни слова о подключении сайта и CMS. Заявка остаётся единственным входом гостя (решение владельца от 13.11.2026): «Начать бесплатно», «Поможем начать», поле «Сайт компании» (схема `leadInputSchema` по-прежнему ждёт имя хоста). «Небольшая правка — около N ₽» → «Небольшая задача — около N ₽», и на «Тарифах» в настройках | Владелец; слова — по умолчанию |

## Срезы

1. **web и tRPC.** Удалить маршруты и компоненты проектов, мастер, выбор проекта, панели кандидата, предпросмотра и выпуска, раздел платформ на главной; роутеры `project`, `siteConnection`, `siteFiles`, `siteEnv`, `siteHistory`, `siteDatabaseDump`, `siteAgentSkills`, `release`, `preview`, `candidate`; новый роутер `workspaceEnv` и страница `/settings/variables`.
2. **core.** Удалить разделы `deploy-step`, `git-workspace`, `previews`, `release-api`, `releases`, `site-provisioning`, `site-files`, `site-content`, кандидата в `tasks`; `site-env` → переменные пространства; ход только без репозитория; очереди `deploys`, `site-import`, `site-provisioning`, `previews`, `site-files`.
3. **mcp, preview, browser, runner, local-turns.** Удалить `content/`, `browser/` у `mcp`, шлюз предпросмотров у `preview` (остаются страницы и трансляция), политику стека и вход у `browser`, бандл репозитория у раннера.
4. **Пакеты и домен.** Удалить `git-providers`, `site-adapters`, `site-connections`, `site-content`, предпросмотр в `sandbox-providers`, `PageBrowser` в `browser-providers`, порты и схемы сайта в `domain`.
5. **База.** Миграция `20261115100000_remove_projects`; сиды; Vault-политики.
6. **Инфраструктура и CI.** `infra/server`, `infra/app`, `infra/dev`, `infra/wordpress`, `infra/joomla`, `infra/preview` (остаются цели `tools` и `browser`), workflow, правила dependency-cruiser, `turbo.json`, скрипты `verify:*`.
7. **Документы.** CLAUDE.md, spec (§20 — решения БП1–БП10), roadmap.

## Результат

### Срезы 1–3 (15.11.2026)

- **web, tRPC, e2e.** Нет `/projects/**`, мастера, выбора проекта, папок «По проектам», панелей кандидата, предпросмотра, выпуска и «Отменить выпуск», «Попробовать ещё», `/init`; инструменты чата — «Браузер» и «Документы». Роутеры проектов удалены, `task.create` всегда без сайта. Новый роутер `workspaceEnv` (`list`, `set`, `remove`; читать — участник, менять — владелец или администратор; до 64 переменных) и страница «Настройки → Переменные». Главная — без раздела платформ, форма заявки на месте; «Тарифы» и «Использование» — без числа сайтов и разбивки по проектам. Проверки: web — 2 209 тестов, tRPC — 476, e2e — `tsc` и eslint.
- **core.** Удалены `deploy-step`, `git-workspace`, `previews`, `release-api`, `releases`, `site-provisioning`, `site-files`, `site-content`, `site-env`, кандидат в `tasks`; ход — только чат без репозитория; переменные — `src/workspace-env` по строкам `workspace_env_vars` каждому ходу пространства; браузер не получает сохранённого входа. Проверки: 1 291 модульный тест, 223 интеграционных на PostgreSQL, 53 теста скриптов.
- **mcp, preview, browser.** У `mcp` нет `content/`, `browser/`, `storage/` и S3, допуск — по назначению и аренде чата, `web_open` — только полные адреса. У `preview` — только страницы и трансляция; здоровье — `GET /__raditi/health` на `:8092`. У `browser` — только открытый веб. Проверки: mcp 462 и 27 на PostgreSQL, preview 50 и 2, browser 80, `verify:pages` — 73 из 73.
- **Выкладка и инфраструктура.** `deploy.sh` после `up -d --remove-orphans` удаляет остановленные контейнеры проекта compose, контейнеры и сети предпросмотров (метка `io.raditi.preview.owner=raditi`), неиспользуемые сети проекта и тома Gitea и раннера выкладки; Traefik без маршрута `preview-apex`, перенаправления `to-cabinet` и резолвера `preview` (`raditi-preview.ru`); compose сервера без `gitea`, `gitea-runner`, `preview-out`, сокета Docker у `core` и переменных предпросмотров. Удалены `infra/wordpress`, `infra/joomla`, `ci/`, цели `site` образа предпросмотра, стенды выпуска, импорта, пайплайна, Gitea, сайта, стеков и сети предпросмотра и их workflow; `preview.yml` стал `browser.yml`.

Открыто: заголовок первого экрана и FAQ главной по-прежнему называют пять CMS, а текст заявки — «подключим ваш сайт»; раздел платформ удалён по слову владельца, остальные тексты ждут его. `verify:browser-task` строился на модулях стенда выпуска — его пересобирает отдельный срез.

### Срезы 4–7 (15.11.2026)

- **База.** Миграция `20261116100000_workspace_env_vars` (таблица переменных пространства) и `20261116110000_remove_projects`: чаты в `awaiting_approval` переходят в `awaiting_user`, таблицы и типы проектов, выпусков, предпросмотров, кандидатов, импорта, Gitea и снимков контента удалены, у оставшихся таблиц нет колонок сайта; аренда — по id чата. Тест миграции — `packages/db/prisma/remove-projects.test.ts`. Колонки `task_turns.base_sha` и `head_sha` остались — их удалит следующая миграция.
- **Пакеты.** Удалены `git-providers`, `site-adapters`, `site-connections`, `site-content`, предпросмотр в `sandbox-providers`, `PageBrowser` в `browser-providers`, `packages/domain/src/git` и порты сайта; правила dependency-cruiser, входы turbo, `.env.example`, `.sonarcloud.properties`.
- **Ход.** Без бандла репозитория, публикации и частей `patch`/`untracked` снимка; старые снимки чатов с проектом открываются по части `home`; образ `core` без `git` и `gitleaks`; лента хода без шага `code`.
- **Стенды.** `verify:billing` — подарок с первым файлом чата, без сайта; `verify:browser-task` пересобран под чаты без проекта (сценарии S, P, K, L, Q, R, M).
- **Тексты тарифов и письма.** «Чаты и страницы сохранятся» вместо «сайты и история правок».

### Открыто

- Поле заявки «Сайт компании» обязательно и принимает только имя хоста: схема `leadInputSchema` в домене не менялась. Сделать его необязательным или заменить на «Чем занимаетесь» — решение владельца.
- Оферта и соглашение о сайтах: поменяна только таблица приложения 1.
- Домен `raditi-preview.ru`, его записи DNS и сертификаты в `acme.json` больше не нужны; ключи `kv/platform/app/mcp`, `app/gitea`, `kv/platform/gitea-org-owner` и `kv/sites/*` в OpenBao сервера остаются, пока их не удалит оператор.
- Стенд браузера больше не проверяет `web_upload` файла чата на страницу: у публичных тестовых сайтов нет поля файла, а локальных сайтов нет.
- Выпуск с этой миграцией удаляет данные проектов: откат — только из дампа, который `deploy.sh` снимает перед миграциями.
