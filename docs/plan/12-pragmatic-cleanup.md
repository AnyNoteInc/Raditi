# Упрощение конфигурации и начало B7 — 30.09.2026

По решению владельца проверены лишние зависимости и дублирование настроек после перехода PostgreSQL на одного пользователя `raditi`. Работа выполнена локально; облачные ресурсы, DNS и рабочая база не менялись.

## Упрощения

- PostgreSQL сохраняет общего владельца `raditi`; переход и проверка старых ролей описаны в [предыдущем отчёте](11-postgres-single-user.md).
- Redis использует одного пользователя `default` и общий пароль для web, core и healthcheck. Удалены отдельные web/core/health логины и файл `health-password`; новый файл — `redis/password`. Аутентификация и запреты административных и массовых команд сохранены. Переход и ротация описаны в [runbook](../../infra/app/README.md).
- **Уточнение владельца:** подключения web к Redis, S3 и Vault сохраняются для предстоящих функций. Их конфигурация, health-пробы, клиентские зависимости и шаблоны секретов восстановлены после первоначального упрощения.
- Orchestrator проверяет настройки выбранных ролей. Неверные параметры выключенного runner или core больше не ломают запуск MCP. Проверки используемых параметров, коллизий портов и запрет секретов платформы на production runner сохранены.
- **Уточнение владельца:** Prisma снова загружает корневой `.env`, если файл существует, даже при явно заданном `DATABASE_URL`. Уже экспортированные переменные сохраняют приоритет.
- В инструкции выкладки CAA упрощён до `0 issue "letsencrypt.org"`: привязка к конкретному ACME-аккаунту и способу проверки не обязательна для MVP. Так потеря `acme.json` и переход на DNS-01 не требуют штатной смены CAA. Основание — [документация Let's Encrypt](https://letsencrypt.org/docs/caa/). Это изменение инструкции, DNS не редактировался.
- README приведён к фактическому состоянию P2 и B3–B6. В проекте P3 исправлены устаревшие упоминания разных PostgreSQL-прав и выдачи новых ходов аккаунту с неоднозначным обновлением токена.

AppRole Vault, CAS и разделение сетей сохранены: они обслуживают реальные границы доступа к токенам и доверия к прокси. Автоматизация релиза остаётся задачей M10.

## Основа B7: потоковый учёт

Создан `packages/llm-backends` с общим инкрементальным SSE-декодером и метрами Codex/Kimi. Декодер удерживает только текущее событие размером до 16 МиБ, обрабатывает границы UTF-8 и строк, многострочные `data` и незавершённый хвост. Полный ответ не накапливается.

Метры извлекают usage и считают только байты текстовых delta для будущей оценки расхода. Повтор текста в `done`/`completed` не учитывается. Отдельно различаются завершение, ошибка провайдера, оборванный поток, отсутствие usage и некорректные счётчики. Уже полученный terminal и usage сохраняются при последующем разрыве. В результат не попадают тексты ошибок или неизвестные коды провайдера.

Порт `LlmBackend` больше не дублирует метаданные токена в результатах входа и обновления: их разбирает `credentialMetadata`. `MeterResult` передаёт исход потока и причину отсутствия usage явно. Пакет включён в архитектурные правила адаптеров; web и runner его не импортируют.

Это часть B7. Транспорт запросов, полные адаптеры, probe, OAuth/device-flow, роль `llm` и сквозной шлюз ещё не реализованы. Фикстуры синтетические: этот проход не подтверждает реальный Kimi или полный P3.0.

## Проверка

- Настоящий Redis на отдельном локальном контейнере: 23 проверки аутентификации, рабочих команд очереди/Lua/pubsub, запретов, healthcheck и сохранения данных через AOF после перезапуска. Контейнер, временный том и файлы удалены.
- Domain: 584 теста; SSE и метры: 71 тест. Проверены разные размеры чанков, malformed usage, отказы провайдера и сохранение terminal при закрытии потока.
- Prisma: 3 регрессионных теста выбора окружения; тест не читает настоящий `.env`.
- Web: 107 тестов. Orchestrator: 843 теста, 5 интеграционных тестов БД пропущены без `DATABASE_URL`; схема и права БД в этом шаге не менялись.
- Инфраструктура: 114 тестов, 1 пропуск проверки watchdog без заданного тестового образа. Typecheck/lint затронутых пакетов и приложений, `check-env`, `check-architecture` и `git diff --check` прошли. Workspace установлен с актуальным lockfile без обновления версий.
- Независимое ревью конфигурации не выявило регрессий. В ревью SSE найден случай, когда лишняя ошибка Kimi после уже полученного terminal меняла завершённый исход; исправление закреплено регрессионным тестом.

После уточнения владельца восстановление проверено повторно: web — 109 тестов, Prisma config — 3 теста, Compose/Redis — 25 тестов; типы и линтер web/db/e2e, окружение и архитектурные границы проходят. Prisma config совпадает с поведением до упрощения; общий пользователь PostgreSQL `raditi` и общий пароль Redis сохранены.

Полный `verify:edge`, сборка приложений и продуктовый e2e в этом шаге не запускались.

Полный локальный продуктовый e2e с настоящим WordPress остаётся обязательным до облачной выкладки. Подготовительный проход сайта описан в [отчёте B5](09-p3-vault-and-local-site.md); текущий шаг его не заменяет.
