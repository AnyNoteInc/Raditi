## 0. Коротко

1. **Инструменты ВКонтакте — встроенное семейство `vk` сервера `raditi` в `apps/mcp`**, по образцу веб-поиска: ключ лежит в Vault и уходит только в запрос к `api.vk.com`. Готовые VK MCP-серверы (stdio, токен в переменной окружения) не берём: ключ оказался бы в песочнице (правила 2 и 5).
2. **Новый раздел «Настройки → Встроенные MCP»** (ВК15): список встроенных серверов Радити, у каждого переключатель. Первый — «ВКонтакте», дальше список пополняется. Включить ВКонтакте можно только с ключом: переключатель открывает поле «Ключ доступа сообщества». Выключенный сервер не попадает в ход совсем: его инструментов нет даже в `tools/list`.
3. **Клиент подключает своё сообщество ключом доступа сообщества** (Управление → Работа с API). Ключ пишет `web` в `kv/workspaces/<ws>/vk/<communityId>` и обратно не читает. В базе — строка `vk_communities` и `credential_refs`.
4. **Пост и ответ на комментарий агент не публикует сам.** Инструмент только резервирует предложение. После хода в ленте появляется карточка «Опубликовать в ВКонтакте», и публикует её `core` по кнопке клиента: HMAC-токен, строка `vk_actions`, задание outbox (правило 4).
5. **Читать стену, комментарии и счётчики постов** — сервисным ключом приложения Радити (`subs/vk/service`, рядом с ключом веб-поиска; кладёт команда оператора `subscriptions:vk-key`). Так работает только открытое сообщество: закрытое агент читает лишь через свои опубликованные посты и Callback API (срез 99.6).
6. **Статистика `stats.get` и картинки в посте требуют пользовательский токен** (схема VK API, §1). В первой версии статистика — просмотры, лайки, репосты и комментарии постов; картинки к постам и `stats.get` — после проверки пользовательского входа (вопрос 3).

## 1. Что умеют ключи ВКонтакте

Источник — машиночитаемая схема методов `VKCOM/vk-api-schema` (поле `access_token_type`), проверено 27.11.2026, и опыт разработчиков (§9).

| Метод | Ключ | Что нам даёт |
| --- | --- | --- |
| `wall.post` | в схеме `user`; на практике работает ключ сообщества с правом «стена» (`from_group=1`) | Публикация поста от имени сообщества, `publish_date` — отложенная |
| `wall.createComment` | `user`, `group` | Ответ на комментарий от имени сообщества |
| `wall.get`, `wall.getById` | `user`, `service` | Посты стены и их счётчики: `views`, `likes`, `reposts`, `comments` |
| `wall.getComments` | `user`, `service` | Комментарии к посту |
| `groups.getById` | `user`, `group`, `service` | Имя, адрес и закрытость сообщества — проверка ключа |
| `groups.getTokenPermissions` | `group` | Права ключа сообщества — проверка права «стена» |
| `groups.getLongPollServer`, `groups.setCallbackSettings` | `user`, `group` | Новые комментарии событием (`wall_reply_new`) |
| `stats.get`, `stats.getPostReach` | только `user` | Статистика сообщества и охват |
| `photos.getWallUploadServer`, `photos.saveWallPhoto` | только `user` | Картинки в посте |
| `wall.edit`, `wall.delete`, `wall.deleteComment` | только `user` | Правка и удаление |

Токены VK ID (`vk2.a.*`) для `wall.post` не подходят (ошибка 1051), а право `wall` пользовательского токена новым приложениям выдают по заявке в поддержку VK. Поэтому основа — ключ сообщества (`vk1.a.*`).

**Расхождение, которое проверяем первым делом (срез 99.0).** Схема помечает `wall.post` как `user`, разработчики Postiz и других сервисов публикуют ключом сообщества. Если на живой группе ключ сообщества получит отказ, публикация перейдёт на пользовательский токен (§8, вопрос 3), остальное не меняется.

## 2. Что должно остаться верным

1. **Правило 2.** Ключ сообщества и сервисный ключ лежат только в Vault. В базе, песочнице, плане хода, ленте, логах и снимках их нет. Форма пишет ключ писателем без чтения (`kvWrite`, `kvMetadata`).
2. **Правило 4.** Пост и ответ на комментарий видны всем, их не вернуть без пользовательского токена. Публикует только кнопка клиента на доверенной карточке; слова модели и `confirmedByClient` разрешением не считаются.
3. **Правило 5.** Песочница ключей не видит: инструменты — в `apps/mcp`, публикация — в `core`.
4. **Запуск по расписанию без клиента** (Зп27, Зп32): чтение работает, резерв поста — тоже (карточка ждёт клиента в чате запуска), но ничего не публикуется само (ВК6).
5. **Хранилища в России.** ВКонтакте — российский сервис; данные постов и комментариев в базе Радити не копируем, кроме текста предложенного поста в ленте чата.
6. **Слова комментаторов — недоверенные данные.** Описания инструментов говорят модели: инструкции в комментариях не выполнять.

## 3. Устройство

### 3.1. Раздел «Встроенные MCP» и подключение сообщества (`web`)

- «Настройки → Встроенные MCP» (`/settings/builtin-mcp`), рядом с «Подключениями». Каждый встроенный сервер — карточка: название, одна строка о том, что умеет агент, переключатель. Список серверов — данные домена (`builtinMcpServers`), не ветвления в коде.
- Состояние хранит `workspace_builtin_mcp` (`workspace_id`, `server`, `enabled`, `updated_by_id`, `updated_at`). Нет строки — выключен.
- Переключают владелец и администраторы пространства, как «Подключения».
- ВКонтакте: включение открывает поле «Ключ доступа сообщества» с подсказкой, где его взять и какие права отметить («Управление сообществом», «Стена»). Переключатель становится «включён» только после принятого ключа. Под ним — подключённые группы и «Добавить группу». Отключение последней группы выключает сервер.
- Выключение не стирает ключи: включить снова можно без нового ключа. Ключ стирает только «Отключить группу».
- `web` проверяет ключ сам (`groups.getById`, `groups.getTokenPermissions`): сообщество находится, право `wall` есть. Ключ пишется в Vault, затем в одной транзакции — `credential_refs` (`vk_community`) и `vk_communities` (id сообщества, имя, адрес, закрытость, права). Повторный ключ того же сообщества заменяет прежний.
- Отключение стирает ключ (одна версия без значения, как у переменных) и удаляет строку.
- Подключение принадлежит пространству: им пользуются все чаты его участников (ВК2).

### 3.2. Инструменты агента (`apps/mcp`, раздел `src/vk`, семейство `vk`)

| Инструмент | Семейство | Что делает |
| --- | --- | --- |
| `vk_communities` | `vk` | Подключённые сообщества пространства: `communityId`, имя, адрес, открыто ли |
| `vk_posts` | `vk` | Последние посты стены (до 20, `offset`): id, дата, текст до 2000 знаков, ссылка, счётчики |
| `vk_comments` | `vk` | Комментарии к посту (до 50, `offset`): id, автор (id), дата, текст, ответы |
| `vk_stats` | `vk` | Сводка по постам за период до 90 дней: число постов, сумма и среднее просмотров, лайков, репостов, комментариев, лучшие 5 по просмотрам |
| `vk_post_propose` | `vk` | Резерв поста: сообщество, текст до 15 000 знаков, по желанию `publishAt` (от 10 минут до 365 дней вперёд) |
| `vk_reply_propose` | `vk` | Резерв ответа на комментарий: пост, комментарий, текст до 4 000 знаков |

- Допуск хода (`PostgresMcpAccess`) читает включённые встроенные серверы пространства (`builtinMcp`). Семейство `vk` предлагается, только когда ВКонтакте включён (ВК15). **Реализация:** отдельного семейства `vk_changes` нет — резерв ничего не публикует, поэтому проход без клиента тоже может подготовить запись (ВК6), карточка ждёт клиента. Выключенный — ни в `tools/list`, ни в `tools/call`. Чтение стены — пока в Vault есть сервисный ключ платформы; без него `vk_posts`, `vk_comments`, `vk_stats` отвечают `VK_READ_UNAVAILABLE`.
- Сообщество ищется по `workspaceId` допуска и `communityId` аргумента; чужое — `VK_COMMUNITY_NOT_FOUND`.
- Не больше 3 предложений за ход (ВК7). Ответы — канонический JSON, тексты чужих людей помечены `untrusted`.

### 3.3. Карточка и публикация (`core`, `web`)

1. Резерв — `vk_reservations` (`kind`: `post` | `reply`, `payload`, `outcome`), как у `repo_reservations`.
2. Ход завершился — `VkChanges.apply` в `pass-runner` закрывает резервы и пишет `feed.vk_proposal` (`v: 1`, `reservedId`, сообщество, текст, время). Проход сорвался — резервы закрываются `failed`.
3. Карточка в ленте: текст поста (можно поправить перед публикацией), сообщество, «Опубликовать» / «Запланировать на …».
4. Нажатие — одна мутация `builtinMcp.vkPublish({ reservedId, text })` (**Реализация:** без шага prepare — показывать перед нажатием нечего). `web` проверяет, что чат виден нажавшему и он владелец или администратор пространства, подписывает токен (`raditi-vk-confirm:v1`, HMAC-SHA256 `VK_CONFIRM_SECRET`, 10 минут, пользователь, пространство, сообщество, резерв, задача, хеш текста, время отложенной записи) и в одной транзакции создаёт `vk_actions` (`token_sha256` и `reservation_id` уникальны) и задание outbox `vk.action`. Не больше 50 публикаций пространства за сутки.
5. `core` (`VkProcessor`, очередь `vk`) проверяет токен ещё раз, читает ключ из Vault, вызывает `wall.post` или `wall.createComment` и пишет `feed.vk_action` (`done` со ссылкой на пост или `failed` с кодом).
6. Повторная доставка задания не публикует дважды: строка берётся одним `updateMany` из `queued` в `running`; сорвавшаяся после вызова VK строка становится `lost`, а не повторяется (ВК9).

### 3.4. Новые комментарии (срез 99.6)

1. **Регистрация.** При подключении группы `web` с ключом в руках регистрирует сервер Callback API Радити (`groups.getCallbackConfirmationCode`, `addCallbackServer`, `setCallbackSettings` с `wall_reply_new`). Условия: у ключа есть право «Управление», адрес кабинета на `https` и задан `VK_CONFIRM_SECRET`. Ключ, подключённый заново, сначала удаляет сервер прежнего ключа. Сбой регистрации подключение не ломает — группа остаётся без уведомлений, и раздел «Встроенные MCP» об этом говорит (ВК18).
2. **Секрет сервера** не хранится: это HMAC `VK_CONFIRM_SECRET` от id группы в Радити, 32 буквы и цифры. Код подтверждения не секрет — он в `vk_communities.callback_code` вместе с `callback_server_id`.
3. **Вебхук** `POST /api/webhooks/vk/<communityId>` (`apps/web/src/server/vk-callback.ts`): тело — не больше 64 КиБ, читается потоком. Группа должна совпадать с `group_id`. На `confirmation` вебхук отвечает кодом, остальные события принимает только с верным секретом. Ответ VK — `ok`. Ответы самой группы ни о чём не сообщают.
4. **Уведомление** `vk_comment`: строка `chat_notifications` с `vk_community_id`, задание `vk.notify` очереди `vk` каждому владельцу и администратору пространства. Не чаще раза в 10 минут на группу и человека: окно ключа outbox и проверка недавних строк. Каналы — Web Push и бот Telegram, письма нет (ВК19). Ни текста, ни автора комментария (ВК17, spec §11): push говорит «Новый комментарий в группе ВКонтакте», бот называет группу клиента. Открывается раздел «Встроенные MCP». Агента событие не запускает: прочитать и ответить — по просьбе клиента или запланированной задачей (ВК20).

## 4. Данные

- `workspace_builtin_mcp`: `workspace_id`, `server` (`varchar(32)`, `CHECK` по списку домена), `enabled`, `updated_by_id`, `updated_at`; ключ — (`workspace_id`, `server`).
- `credential_refs.kind` — новое значение `vk_community`.
- `vk_communities`: `id`, `workspace_id`, `created_by_id`, `group_id` (bigint, уникален в пространстве), `name`, `screen_name`, `is_closed`, `permissions` (массив строк), `credential_ref_id`, `state` (`ok` | `refused`), `state_reason`, `checked_at`, `created_at`, `updated_at`.
- `vk_reservations`: как `repo_reservations` + `community_id`.
- `vk_actions`: `id`, `workspace_id`, `task_id`, `community_id`, `created_by_id`, `kind` (`post` | `reply`), `args`, `token_sha256` (уникален), `state` (`queued` | `running` | `done` | `failed` | `lost`), `error`, `result` (`postId`, `commentId`, `url`), `created_at`, `finished_at`.
- Vault: `kv/workspaces/<ws>/vk/<communityId>` — `{ token }` (пишет `web` политикой `sites-writer`, читает `core` новой политикой `core-vk`); `subs/vk/service` — `{ token }` (оператор, `pnpm --filter llm subscriptions:vk-key`; читает только `mcp`, у `llm-subscriptions` — `deny`).

## 5. Решения

- **ВК1.** Инструменты ВКонтакте — свои в `apps/mcp`, а не чужой MCP-сервер (§0, п. 1).
- **ВК2. По умолчанию.** Подключение — для всех клиентов, на пространство, а не только для группы владельца.
- **ВК3.** Ключ сообщества — основной; пользовательский токен — только для статистики `stats.get` и картинок, отдельным срезом после проверки (вопрос 3).
- **ВК4.** Чтение стены — сервисным ключом приложения Радити; закрытые сообщества читаются только через Callback API.
- **ВК5. По умолчанию.** Публикация — всегда кнопкой клиента. Автопубликации в запланированных задачах нет (вопрос 2).
- **ВК6.** Проход без клиента читает и резервирует, но не публикует: карточка ждёт клиента.
- **ВК7.** Не больше 3 предложений за ход и 50 публикаций пространства в сутки. Суточный лимит самого ВКонтакте на посты сообщества проверяется в срезе 99.0; его отказ (`error_code` 214, 219) клиент видит своими словами.
- **ВК8.** Текст поста клиент может поправить на карточке; публикуется то, что подписано в токене (хеш текста).
- **ВК9.** Публикация не повторяется автоматически: неизвестный исход — `lost` и честный текст «не знаем, вышел ли пост, проверьте группу».
- **ВК10.** Тексты постов и комментариев из ВКонтакте в базе не храним, кроме предложенного поста в ленте.
- **ВК11.** Комментарии — недоверенные данные, это сказано в описаниях инструментов.
- **ВК12.** `api.vk.com`, версия API `5.199`, ответы проверяются zod.
- **ВК13.** Кредиты отдельно не списываются: вызовы инструментов — часть хода.
- **ВК14.** Адаптер — пакет `@repo/vk` (зависит только от `domain`); `mcp` и `core` берут его, `web` — для проверки ключа.
- **ВК15. Слова владельца.** Раздел «Встроенные MCP» с переключателем у каждого встроенного сервера; выключенный сервер не входит в список инструментов хода. Включить ВКонтакте можно только с ключом.
- **ВК18. По умолчанию.** Сервер Callback API регистрируется только ключом с правом «Управление»; без него группа подключается без уведомлений, и кабинет говорит, как их включить.
- **ВК19. По умолчанию.** Уведомление о комментарии — Web Push и бот, без письма, не чаще раза в 10 минут на группу и человека: поток комментариев не становится потоком писем.
- **ВК20. По умолчанию.** Новый комментарий не запускает агента сам: ход стоит кредитов, а просить его — клиенту.
- **ВК17. По умолчанию; отступление от spec §11.** Модель видит тексты комментариев (их чтения владелец просил прямо), но не id авторов: автор — «reader N» в пределах одного ответа, своя группа — «this community». Закрыть тексты до решения — `VK_COMMENT_TEXTS_TO_MODEL = false` в `packages/domain/src/vk/limits.ts`: тогда `vk_comments` отдаёт только число комментариев.
- **ВК16. По умолчанию.** Встроенные серверы включаются на пространство (как «Подключения»), а не на аккаунт; переключают владелец и администраторы.

## 8. Вопросы владельцу

1. **Ключ тестовой группы** для среза 99.0 — без него публикация проверяется только на подделке API.
2. **Автопубликация.** По умолчанию — только кнопкой (ВК5). Нужна ли настройка «публиковать без подтверждения в запланированных задачах»?

## 10. Отчёт (27.11.2026)

Ветка `feat/vk`, отдельный worktree от `main`.

**Что сделано**

- **Домен** (`packages/domain/src/vk`, `builtin-mcp`, порт `ports/vk-api.ts`): лимиты, пути Vault, отказы с русскими текстами, аргументы инструментов, строки ленты `feed.vk_proposal` и `feed.vk_action` (вместе с замороженными образцами), токен нажатия, задание `vk.action`, очередь `vk`.
- **Адаптер `@repo/vk`**: `VkHttpApi` — POST на `api.vk.com`, ключ в теле, а не в адресе; ответы проверяются zod; ошибка VK становится отказом домена без слов VK; ограничены размер ответа и частота вызовов. Там же `vkConfigFromEnv` (`VK_CONFIRM_SECRET`).
- **Данные**: миграции `20261128200000_credential_kind_vk_community` и `20261128200100_vk_communities` — таблицы `workspace_builtin_mcp`, `vk_communities`, `vk_reservations`, `vk_actions`, CHECK-ограничения, `credential_refs_platform_scope_check` с `vk_community`. Функции — `packages/db/src/vk.ts`.
- **Кабинет**: «Настройки → Встроенные MCP» (`/settings/builtin-mcp`). Переключатель ВКонтакте открывает поле ключа и включается только с принятым ключом. Ключ проверяется в VK (`groups.getById`, право `wall`), уходит в Vault и обратно не показывается. «Отключить» стирает ключ; последняя группа выключает сервер.
- **Агент** (`apps/mcp/src/vk`): `vk_communities`, `vk_posts`, `vk_comments`, `vk_stats`, `vk_post_propose`, `vk_reply_propose`. Допуск хода читает `builtinMcp` при каждом вызове: выключенный сервер пропадает из `tools/list` и `tools/call` со следующего вызова.
- **Публикация**: `VkChanges` в `pass-runner` (карточки после хода, закрытие при срыве, уборка зависших резервов), карточка с правкой текста и кнопкой «Опубликовать»/«Запланировать» (после нажатия — и после перезагрузки, по строке `feed.vk_action` — кнопки нет; второе нажатие сервер всё равно отклоняет, `VK_ALREADY_PUBLISHED`), мутация `builtinMcp.vkPublish`, `VkActions` и `VkProcessor` в `core`. `core` заново проверяет подпись, совпадение строки, хеш текста и берёт ключ из Vault только на этот вызов. Если VK не ответил, строка получает состояние `lost` и повторно не отправляется; уборка задач отмечает `lost` у строк, чей процесс умер посреди вызова.
- **После ревью spec**: id авторов комментариев не уходят модели (ВК17); сбой до вызова VK (Vault, база) — `failed`, а не `lost`; успешный ответ VK странной формы — `lost`; `vk_actions` переживают отключение группы (`community_id` — `ON DELETE SET NULL`); цель ответа читается из резерва через zod; адаптер VK закрыт для `llm`, `preview` и `browser` в dependency-cruiser.
- **Vault и сервер**: политика `core-vk`; пути VK у `sites-writer` и `mcp-content`; `deny` у `llm-subscriptions`; общий секрет `vk_confirm_secret` в `platform-secrets.mjs seed/render`; команда `subscriptions:vk-key`.

**Проверки** (worktree `feat/vk`): `typecheck`, `lint`, unit-тесты `@repo/domain`, `@repo/vk`, `@repo/db`, `@repo/trpc`, `mcp`, `core`, `web`, `llm` — зелёные; `pnpm check-architecture` — без нарушений; `pnpm test:infra` — 625; `pnpm check-env` — ок; `pnpm verify:db` — миграции, сверка `schema.prisma`, наборы пакетов с базой.

**Что не сделано и почему**

- Срез 99.0: на живой группе ничего не проверено — нет ключа. Самое важное — принимает ли VK `wall.post` от ключа сообщества (§1).
- Сервисный ключ VK на сервер не положен. Пока его нет, агент не читает стены (`VK_READ_UNAVAILABLE`), но готовить и публиковать записи можно.
- Картинки в постах и `stats.get` (99.7).
- Уведомления о комментариях (99.6) не проверены на живой группе: регистрация сервера и подтверждение VK работают только на `https`-адресе сервера.
