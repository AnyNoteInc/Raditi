## 2. Перенос остатка (Ц7)

В конце периода `k` на счёте тарифа доступно `A = balance − held`; начисление периода `k` — `G` (строка `grant` заказа этого периода). Кредиты тратятся сначала из перенесённых (они старше), поэтому из `A` к квоте периода `k` относится `min(A, G)`, а остальное — прошлый перенос, проживший свой период.

- **Продление и оплата в просрочке.** Перенос `C = min(A, G)`. Журнал: строка `expire` на всё `A` с ключом `sub:<subscriptionId>:<periodEndMs>:expire` (как сейчас) и строка `grant` без заказа на `C` с ключом `sub:<subscriptionId>:<periodEndMs>:carry`. Так каждая строка принадлежит своему периоду по ключу, а сгорает на деле `A − C`.
- **Тариф кончается** (не продлён, не оплачен 7 дней, возврат с `--end-subscription`): сгорает всё `A`, как сейчас.
- **Резерв закончившегося периода** (`heldEarlier`): как сейчас — израсходованное списывается, остальное сгорает. Не переносится: упрощение, не больше одного шага на каждую задачу в работе.
- **Шкала «Использования»** текущего периода: `перенесено + начислено = списано + отложено + сгорело + осталось`; новая часть `carried` — строка `grant` с ключом `…:carry` предыдущего периода. Закончившийся период клиент не видит.
- Повтор продления не переносит дважды: ключи строк идемпотентны.

## 4. Результат

Ветка `feat/new-pricing` от `main` `1539cad0`, дерево `../raditi-pricing`, 06.11.2026. Срезы сделаны агентами по этому плану; каждый срез — свой коммит.

### Что сделано

- **63.1, числа.** Миграция `20261106100000_billing_pricing_2026_11` меняет условия строк `start`, `business`, `agency` и `pack` на месте, только если строка ещё держит прежние опубликованные условия; остановки нет, подписки, заказы, счета и журнал не трогаются (Ц15). Сиды несут новые условия. `signupGiftCredits` = 50; `unpaidWorkShareOfMonth` = 0,5 и `unpaidWorkLimit(creditsPerMonth)` (вниз до целого, не меньше 1), `trialUnpaidWorkCredits` = подарок. Письмо при регистрации говорит о 50 кредитах.
- **63.2, перенос остатка.** `carryTariffRemainder` в `@repo/billing` (`ledger.ts`): при продлении и оплате в просрочке — `expire` всего доступного `A` под `sub:<id>:<periodEndMs>:expire` и `grant` без заказа на `C = min(A, G)` под `sub:<id>:<periodEndMs>:carry`, в одной транзакции, под блокировкой подписки, затем счёта; повтор ничего не пишет. Конец тарифа по-прежнему сжигает всё (`expireTariffRemainder`). Шкала «Использования»: `carried + granted = charged + held + expired + left`, рядом прогноз `carryLimit`, `carryNext`, `burnNext`; запись аудита получила `carriedCredits`.
- **63.3, страницы.** «Небольшая правка — около 66 / 58 / 50 ₽», из пакета — 75 ₽ (`apps/web/src/lib/credit-price.ts`, Decimal, одно округление); фраза о списании только за выполненную работу; строки дня — только у тарифа с дневным лимитом; калькулятор главной на новых ценах. Найдено и исправлено: главная пропускала тариф без дневного лимита (`landing-plans.ts`) и с новыми сидами показала бы пустой блок тарифов.
- **63.4, юридические тексты.** Приложение 1 оферты (цены, кредиты, пп. 1.2, 1.4, 1.6, 1.9) и соглашение (3.3, 13.2, 13.4) — без новой редакции (Ц16); README юридических текстов — пункт 21 для юриста.
- **63.5, документы.** `docs/business.md` и модель `docs/model/Raditi_unit_economics.xlsx` (933 формулы, генератор `docs/model/build_unit_economics.py`, 241 значение сверено с `calc.py`); spec §16, §17 и §20 «Новая ценовая политика — решения 06.11.2026» и «Ключи плана и API — поправка к П83 от 06.11.2026»; `CLAUDE.md`, roadmap, история в планах 37 и 53.

### Отступления от §2 и последствия

- `carried` шкала находит по `orders.period_end` последнего заказа с `period_start` раньше начала текущего периода, а не по ключу с концом, равным началу периода: при оплате в просрочке новый период начинается в момент оплаты. `G` — начисление заказа, у которого `period_start` равно началу закончившегося периода.
- Тексты неоплаченного тарифа на «Использовании» переписаны: оплата в просрочке тоже переносит остаток.
- `billing:rates` при K = 6,00 теперь требует `--confirm-exposure`: учётная стоимость всей квоты «Бизнеса» — 51,5 % цены, «Агентства» — 60,0 % (порог — половина цены); «Старт» — 45,2 %, пакет — 40,3 %.
- Подарок (50) больше стандартного шага (45): без тарифа вторая задача может начаться, пока первая держит 45 кредитов подарка.
- Подписка dev-базы на прежних условиях продлевается по новым; заказы хранят свою сумму.
- П. 1.2 оферты («…результат отменен автоматической проверкой после выкладки, Кредиты не списываются») не точен с 26.10.2026, когда списание пошло по проходам: откат выпуска не возвращает уже списанные проходы. Это старое расхождение, вынесено юристу (README юридических текстов, вопрос 15).
