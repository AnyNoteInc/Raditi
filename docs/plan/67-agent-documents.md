# План 67. Документы агента: страницы и тексты в панели справа, поделиться по ссылке

Запрос владельца от 11.11.2026 и 12.11.2026: когда клиент просит «сделай документ / отчёт / сводку / прайс / план»,
агент по умолчанию делает не файл Word, а **страницу** (`.html`) или **текстовый документ** (`.md`). Документ сам
открывается в панели справа — там же, где браузер, — документов может быть много, их удобно листать; документом
можно поделиться по ссылке. Word и Excel — только по явной просьбе клиента.

Постановка — решения Д1–Д9 (значения по умолчанию, по указанию владельца от 09.10.2026 действуют как решения).
Ниже — как они легли на код, где пришлось выбрать, и что ждёт владельца.

## 1. Решения по ходу (отступления и уточнения постановки)

- **Д1, подсказка формата.** `requestedFileFormats(text)` (`packages/domain/src/tasks/document-formats.ts`) читает
  слова клиента **этого прохода** — то, что ушло в подсказку хода (`promptOf`), без слов платформы. Строку
  `## The format the client asked for` планировщик добавляет **в конец инструкций** хода, а не внутрь общего блока
  `ANSWERING`: тексты трёх видов чата остаются байт в байт, одна строка дописывается в одном месте.
- **Д2.** `documentKindOf(name)` — в `packages/domain/src/tasks/chat-files.ts`. Схема `feed.file` v1 не меняется:
  вид выводится из имени, версия — по порядку строк. Модель документов чата —
  `chatDocumentsOf(rows)` в `packages/domain/src/tasks/chat-documents.ts` (чистая, её читают кабинет и сервер).
- **Д3, кто отвечает на домене страниц.** `apps/web`, разделение по `Host` в `apps/web/src/proxy.ts`. Чтобы на хосте
  страниц не отвечали `/api/*` и `/_next/*`, у `proxy` теперь общий `matcher` на все пути: на хосте кабинета для
  путей, которые прежний `matcher` пропускал, он отвечает `NextResponse.next()` и ничего не меняет; на хосте страниц —
  только `GET /v/<token>`, `GET /s/<token>` и `/robots.txt`, остальное — 404 без `Set-Cookie`; `/v/` и `/s/` на хосте
  кабинета — 404. Отдельное приложение `apps/pages` не понадобилось: маршрутам нужны только `@repo/db`,
  `@repo/storage` и `@repo/trpc`, всё это у web есть. Токен — `packages/trpc/src/services/chat/page-tokens.ts`.
- **Д3, подпись.** Ключ HMAC — HKDF-SHA256 от `PAGES_SIGNING_SECRET` с `info` вида (`raditi-page-view-v1` и
  `raditi-document-share-v1`): токен просмотра и токен ссылки не подходят друг к другу. Вне production пустой секрет
  заменяется значением для разработки; в production без секрета страницы и ссылки выключены.
- **Д3, переходы между документами со страницы** — не делаем: ссылка страницы на имя файла внутри фрейма просто не
  работает (непрозрачный origin). `postMessage` — отдельным срезом, если владелец попросит.
- **Д4, печать страницы из панели** — не делаем: печать — через «Открыть в новой вкладке» и печать браузера.
- **Д5, картинки md.** Маршрут `GET /api/tasks/<taskId>/files/<fileId>/image`: PNG, JPEG, WebP, GIF по байтам
  (`imageTypeOf`, рядом с проверкой аватара), SVG — никогда.
- **Д6 и Д8, один набор правил.** Публичная версия md рисуется **тем же компонентом**, что и в кабинете:
  `DocumentMarkdown` строит дерево `react-markdown` с политикой адресов, а `/s/` превращает его в HTML через
  `renderToStaticMarkup` с картинками `data:`. Второго конвейера (`remark-rehype` → `rehype-sanitize`) нет — значит,
  нет двух наборов правил, которые разойдутся; сырой HTML так же выбрасывается (`skipHtml`), React экранирует текст.
  Якоря — свой `slug` с префиксом `doc-` (`packages/domain/src/tasks/document-slug.ts`), без новой зависимости.
- **Д7, предел файлов за ход** поднят с 10 до 30 (`outboxLimits.files`). Протокол раннера предел не несёт (там только
  байты архива), манифест 30 имён по 200 знаков — не больше 24,3 КиБ при пределе 32 КиБ. Условие: `core` и раннер
  выкатываются одним выпуском — так и есть на одном сервере (`infra/server/README.md`); старый `core` отклонил бы
  манифест нового раннера с 11 и больше именами.
- **Д7, «Скачать все документы»** — не в этой работе (по желанию, отдельным срезом).
- **Д8, операторская команда** — `pnpm --filter core documents:revoke -- <shareId> --reason "…"`.
  Отзыв при удалении чата, проекта, рабочего пространства и при пропаже файла не пишется отдельно: `/s/`
  проверяет всё это при каждом открытии и отвечает 404.
- **Д8, предел открытий** — `rate_limits` через `admitInWindow` (как у аватара): 120 открытий `/p/` и `/s/` одной
  ссылки в минуту и 600 в час с адреса.
- **Д9, «Сделать файл Word»** — не в этой работе (по желанию).

## 3. Остаточные риски

- Страница агента может уйти навигацией на чужой адрес: CSP навигацию не закрывает. На ней только то, что агент
  собрал для этого клиента; инструкции запрещают всё внешнее; фрейм без `allow-top-navigation`.
- Смена `PAGES_SIGNING_SECRET` гасит все выданные ссылки и адреса просмотра (`infra/server/README.md`).
- Эвристика телефонов и почт в окне «Поделиться» ловит не всё: предупреждение говорит клиенту проверить документ.

## 4. Ждёт владельца

1. Купить отдельный регистрируемый домен страниц (по умолчанию в примерах — `raditi-pages.ru`), не поддомен
   `raditi.ru` и не `raditi-preview.ru`; до этого в production `PAGES_ORIGIN` пуст — страницы только скачиваются.
2. Ниже `lg` документ сам не открывается: только карточка в ленте и точка на «+».
3. Предел просмотра md — 2 МиБ.
4. Делиться могут владелец и администратор рабочего пространства.
5. Шеринг в production выключен (`PAGES_SHARING`), пока не решено, что делать с жалобами и злоупотреблениями.
6. Карточка ссылки для мессенджеров — общая, без названия документа.
7. Mermaid и формулы не рисуются.
8. «Поделиться набором документов» — нет, только одним документом.
