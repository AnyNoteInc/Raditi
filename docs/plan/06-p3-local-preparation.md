# P3: текущая локальная подписка Codex и подготовка B2

29.09.2026. Ветка `codex/p3-llm-gateway`. Продолжение сессии Claude Code `Bootstrap` по указанию владельца: использовать текущий локальный Codex, аккаунта Kimi нет.

## Что сделано

На действующей подписке проверена схема A: новый ход с инструментом и продолжение той же временной сессии, JSON Schema, расход из ответов провайдера. Через локальный egress с mTLS получены пять успешных ответов и проба 1 МиБ. Файл входа не изменён, личный конфиг не переносился, повторного входа или refresh не было. Измерения и ограничения — [spike.md](../research/2026-09-subscriptions/spike.md).

Исправлен recorder: SSE без `Content-Type`, сохранение usage при закрытии клиента после terminal, различение исхода модели и завершения транспорта. Добавлен отдельный воспроизводимый launcher с временными каталогами, проверкой неизменности файла входа и отчётом без токенов, идентификаторов и содержимого. Проверки ошибок используют синтетические данные; обычные тесты не обращаются к подписке.

Выполнен подготовительный B2:

- Удалены LiteLLM из dev compose, отдельная сеть, конфиг, цель Prometheus, алерт и панели Grafana; начальная настройка PostgreSQL больше не создаёт его роль и базу.
- Из `.env.example` и списка переменных сборки удалены ключи LiteLLM, Yandex AI Studio, Cloud.ru и GigaChat. SmartCaptcha и SpeechKit сохранены; личная `.env` не изменялась.
- Удалены ID драйверов `gigacode` и `sourcecraft`. Общие проверки входных данных отвергают их в манифесте снимка и командах раннера prepare/adopt. Парсеры Codex, Kimi, Qwen и OpenCode сохранены; Qwen/OpenCode остаются выключены в каталоге продукта.
- Обновлены текущие инструкции и комментарии. Драйверы Codex/Kimi пока не запускают производственные ходы: их `prepare`/`command` относятся к P4/P5. Основного шлюза подписок ещё нет; профиль dev `llm` временно отсутствует до его фейков.

Существующие контейнеры, тома, базы и история цен не удалялись. `litellm_key_hash` оставлен до миграции сужения P4; в Prisma изменены только комментарии. Старые API-провайдеры и модели пока остаются в сидах и базе: этот переходный коммит не является готовым доступом к моделям и не закрывает P3.

## Точка продолжения

Позднее B3 реализован и проверен на отдельной PostgreSQL: [результат и следующая задача](07-p3-catalog-migration.md). Описание ниже фиксирует точку остановки B2.

Следующий локальный шаг — B3: **в одном согласованном изменении** выключить старых API-провайдеров/модели и класс `service` миграцией, добавить `reserve_output_tokens`, убрать создание старых провайдеров и моделей из сидов и обновить их тесты. Иначе `db:seed` на новой базе снова создаст старые модели включёнными из-за значений БД по умолчанию. Исторические строки и цены сохранить, миграции прошлого не переписывать; проверить миграцию и повторный seed на отдельной локальной PostgreSQL.

Удалённый `egress-1`, канал из России, Kimi и полная проверка P3 остаются открыты. Локальный результат не подтверждает их и не снимает production-гейты проекта.
