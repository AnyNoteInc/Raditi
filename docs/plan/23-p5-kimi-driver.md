# P5: локальный драйвер Kimi

30.09.2026 реализованы `prepare` и `command` для `@moonshot-ai/kimi-code@2.1.1`. Общий runtime содержит Kimi и Codex 0.158.0. Проверка использует синтетический репозиторий и ответы, одноразовые сервисы данных и локальную Linux-ВМ; настоящая подписка Kimi и облако не использовались.

## Реализация

- Конфигурация, инструкции, явный профиль агента и обёртка находятся в `/agent-home/kimi`. Ключи хода — только в `/run/raditi/secrets` (права 0400); обёртка читает оба файла один раз и сразу удаляет. Подготовленные файлы, env и argv ключей не содержат.
- Общая с Codex обвязка хода — схема контекста запуска, два файла секретов, размещение входных файлов и проверка вложений — живёт в `packages/agent-drivers/src/cli-run.ts`. Список вложений проверяется правилом плана хода (`turnInputSchema`), ошибка — `Invalid attachment path`.
- Обёртка читает запрос и параметры из файлов, заполняет JS argv и импортирует настоящий закреплённый `dist/main.mjs`. CLI 2.1.1 не читает запрос из stdin; обычный запуск с одним аргументом из 100 000 кириллических символов упирается в Linux `E2BIG`. Проверен ввод около 200 КиБ через импорт. Префикс `Client request:` сохраняет буквальный `-` и не позволяет `/goal …` включить специальный CLI workflow. Пути вложений перечисляются как данные; картинки отдельно не обрабатываются.
- Модель задаётся через `KIMI_MODEL_NAME`, provider `kimi`, адрес `/kimi/v1` и явный alias `--model __kimi_env_model__`. Effort `low`, `high` или `max` передаётся на каждом ходе. Подготовка старого плана без effort допустима для recovery; новый запуск требует профиль.
- Первый ход использует `--agent-file /agent-home/kimi/raditi-agent.md`: его приоритет выше проектных agent profiles, которые Kimi загружает без проверки доверия. Профиль закрепляет инструкции платформы и JSON-схему результата. На resume Kimi сохраняет первый system prompt; текущие инструкции и схема передаются в запросе только когда они изменились: восстановленный журнал сессии должен называть ровно текущую версию (маркер `raditi-instructions-<sha256>`), иначе инструкции повторяются. Итог проверяет `turnResultSchema`, отдельного флага JSON Schema у Kimi нет.
- Домашний MCP config использует `bearerTokenEnvVar`. Проектные `.mcp.json` и `.kimi-code/mcp.json` без trust store игнорируются. Trust store, плагины и пользовательские настройки не восстанавливаются. Общий allowlist оставляет файловые инструменты, Bash, вопросы и `mcp__raditi__*`, исключая подагентов и встроенные серверные инструменты. Обновления, телеметрия, product skills и автоматическое название сессии выключены; secondary model отсутствует.
- SDK и MCP читают ключи напрямую из неперечисляемых свойств отдельного объекта `process.env`. Bash и дочерние команды копируют перечисляемое окружение и ключей не получают. Это поведение проверено на закреплённом CLI, а не предполагается из общего контракта Node. Уточнение после ревью 02–04.10.2026: «не получают» относится к окружению. Ключи живут только в памяти процесса CLI и не попадают ни в один `/proc/*/environ` — это утверждает фикстура под gVisor; чтение `/proc/<pid>/mem` тем же uid отклоняется. Запись текста с ключом хода через `wp_rest` шлюз MCP отклоняет до журнала и до обращения к сайту.
- `KIMI_MODEL_MAX_OUTPUT_SIZE=65536` — потолок шлюза, а не резерв допуска.
- `session.resume_hint` после ответа даёт native id `session_<UUID>`. Снимок включает `session_index.jsonl`, `sessions/<workDirKey>/<id>/state.json` и `agents`; конфигурация, логи, задачи и секреты туда не попадают. Дополнительный порт обнаружения id не понадобился. Usage остаётся на шлюзе; завершение хода определяет успешный выход процесса.

Семантика сверена с исходником Kimi commit `f67e6398fb3210ad8ace970e2dfd5bcc984ed61f` и реальным CLI. Первичные документы: [команда CLI](https://github.com/MoonshotAI/kimi-code/blob/f67e6398fb3210ad8ace970e2dfd5bcc984ed61f/docs/en/reference/kimi-command.md), [агенты](https://github.com/MoonshotAI/kimi-code/blob/f67e6398fb3210ad8ace970e2dfd5bcc984ed61f/docs/en/customization/agents.md), [MCP](https://github.com/MoonshotAI/kimi-code/blob/f67e6398fb3210ad8ace970e2dfd5bcc984ed61f/docs/en/customization/mcp.md). Пробы исходника и CLI — `/tmp/raditi-p5-kimi-scout.log`.

## Проверка через супервизор

`pnpm verify:kimi-supervisor` использует общий с Codex launcher, который создаёт собственные PostgreSQL, SeaweedFS и OpenBao в Docker Desktop. Схема мигрируется в новой базе; ключ Transit и S3 bucket принадлежат этому запуску. Рабочий `.env` и существующие сервисы не читаются. Раннер в Colima получает только ключи хода и presigned-ссылки; песочница работает под `runsc` с uid/gid `10001:10001`.

Цепочка: `TurnSupervisor` → `RemoteTurnExecutor` → pull-раннер → `LocalTurnExecutor` → обёртка → настоящий Kimi CLI → настоящий `sandbox-gw` → синтетические LLM/MCP. Основной шлюз подписок и выдача ключей здесь подставные; их собственная проверка — B13. Git-публикация и gitleaks 8.30.1 настоящие, remote — временный локальный bare-репозиторий.

Проверки прохода:

- Первый запрос — `-`, второй содержит почти 100 000 символов, преимущественно кириллицу. Bash CLI проверяет ядро gVisor, uid/gid, версию Kimi и отсутствие обоих токенов в дочернем env; меняет `index.php` и создаёт файл хода.
- Второй ход в новом контейнере получает только зашифрованный снимок первого, возобновляет тот же native id и содержит прежний ответ в истории. Проверяет файлы первого хода. Ключи новые, effort меняется `low` → `high`; текущие инструкции второго хода присутствуют в запросе.
- Оба хода выполняют MCP initialize, tools/list и настоящий синтетический `site_info`; фикстура проверяет соответствующие tool outputs и поддерживает стандартные служебные сообщения MCP.
- Проект пытается заменить модель/config, MCP и default/выбранный agent profile. Запросы сохраняют закреплённые настройки и системные инструкции; посторонние маршруты и инструменты не объявляются.
- Снимки, манифесты, назначения и журнал не содержат ключей. Журнал содержит реальные started/command/message; Kimi не печатает usage или terminal event. Публикация выполняется после удаления песочницы.
- Убираются контейнеры, сети, правила firewall, том токена раннера, временные строки, S3-объекты и ключ Transit. Launcher также проверяется при SIGTERM.

Общий стенд сохранил отдельный `pnpm verify:codex-supervisor`; сценарии P2 с авариями остаются в `verify:runner`. Приватная диагностика при отказе имеет права `0600`; её содержимое и временные журналы могут включать синтетические ключи, их не следует публиковать.

Сквозной проход Kimi прошёл локально; лог — `/tmp/raditi-p5-supervisor-proof.log`. В ходе проверки уточнён протокол фикстуры: она принимает стандартный `notifications/cancelled` после инициализации с проверкой параметров. Неизвестные методы, маршруты, чужие инструменты и ключи по-прежнему отклоняются. Итоговые unit-проверки (на 30.09.2026; сейчас agent-drivers — 251, domain — 684, orchestrator — 1 893 без базы): domain — 601, agent-drivers — 191 (26 новых Kimi), orchestrator — 1 265, проверочные скрипты — 33; 113 интеграционных тестов без БД пропущены. Инфраструктура — 224 пройденных, 2 opt-in пропущены. Сборка, typecheck, lint, архитектура, окружение и форматирование прошли.

Регрессионный проход Codex на том же общем P5 runtime и общем launcher также прошёл: два хода, восстановление UUID, смена профиля, снимки и публикация. Лог — `/tmp/raditi-p5-codex-regression.log`.

Отдельный SIGTERM отправлен launcher при `Running=true` и `Runtime=runsc` у реальной песочницы. Завершение с кодом 1 заняло 1,845 с: после него отсутствуют sandbox, runner, gateway, сети, том токена и три сервиса данных; правила INPUT IPv4/IPv6 вернулись к пустому baseline. Результаты — `/tmp/raditi-p5-supervisor-cancel-evidence.json`, лог — `/tmp/raditi-p5-supervisor-cancel.log`. Собственная приватная диагностика отказа сохранена с правами `0600`.

## Повтор

Сначала пересоберите образы из текущего дерева. Digest-ы `raditi-p5verify-*` и `raditi-p4verify-*` ниже — исторические: они записаны 30.09.2026 и старше правок `infra/sandbox` от 02.10.2026 (CLI из lock-файла, 11-минутный предел `sandbox-gw`). Прогоны ревью 03–04.10.2026 шли на свежих сборках; `pnpm verify:kimi-supervisor` и `pnpm verify:codex-supervisor` прошли 04.10.2026 под gVisor.

Нужны Docker Desktop, отдельная локальная Linux-ВМ с Docker и `runsc`, загруженные образы и gitleaks 8.30.1. Launcher не загружает образы и отвергает удалённый Docker. Локальные digest aarch64 от 30.09.2026:

```sh
export P2_RUNNER_DOCKER_SOCKET="$HOME/.colima/gvisor/docker.sock"
export P2_RUNNER_HOST=192.168.5.2
export P2_GITLEAKS_BINARY=/absolute/path/to/gitleaks
export P2_SANDBOX_IMAGE=raditi-p5verify-sandbox@sha256:ef84b5b697db968132f587c570f85d3253edcffb0653c078f7518d376ff0b0db
export P2_RUNNER_NODE_IMAGE=raditi-p4verify-base@sha256:c9aa741bebc082a511708ed1eacf49e9979db7db8a10d780b77f080c6d327c7d
export SANDBOX_GATEWAY_IMAGE=raditi-p4verify-gateway@sha256:73ebae30f83e172977fef14e574456af76b46ba2f4e68dc2b08cd1057723e5b8
export SANDBOX_NETWORK_GUARD_IMAGE=raditi-p4verify-network-guard@sha256:4f09d0283b512f5ecfc1a9077ec617eb35e80e93d3e7dc34e1d140914054783d
pnpm verify:kimi-supervisor
pnpm verify:codex-supervisor
```

CLI устанавливаются только в runtime stage, из `packages/agent-drivers/cli/package-lock.json` (`npm ci --ignore-scripts`, сверка версий `npm ls`). Доверенные base/gateway/watchdog/network-guard CLI не получают. Образ по этому digest оставлен локально; публикации в реестр Gitea не было.

## Оставшиеся гейты

P5 локально подготовлен до приёмки P3. Настоящая подписка Kimi, зарубежный канал и учётные ставки ещё требуют проверки владельца в изолированном стенде. Целевой реестр и облачная выкладка остаются после полного WordPress e2e. Миграция сужения B16 — отдельный релиз после P3.

Проверка лимита репозитория на настоящих сайтах остаётся открытым пунктом P2/P5. Синтетический репозиторий этого прохода её не заменяет.

Следующая локальная задача по основному сценарию — P6, MCP-инструменты сайта; этот синтетический `site_info` не заменяет их реализацию. Изменения не закоммичены и не отправлены.
