  `fingerprint(pages)`, первый подошедший шаг:

  | Шаг | Условие | Ответ |
  | --- | --- | --- |
  | 1 | Страница манифеста с `<name>files_joomla</name>`, либо на главной `<meta name="generator" content="Joomla!`, либо `/media/jui/`, либо `/media/vendor/` рядом с `/media/system/` | `yes` |
  | 2 | На главной `FOREIGN_GENERATOR` | `no` |
  | 3 | Иначе, в том числе страниц нет, страница защиты от ботов, ошибка 503, заглушка хостинга, главная с `/wp-content/` или `/bitrix/` в атрибутах `src` и `href` | `unknown` |

  Шаг 2 — первый вид строки Т27 «Адрес и папка — разные сайты»: мета-тег `generator` печатает работающая система, старый сайт его не оставляет. Ссылки на `/bitrix/` и `/wp-content/` — другое дело, это могут быть остатки прежнего сайта. На них Joomla отвечает `unknown`, чужое «yes» даёт строку «Снаружи признаки другой платформы, свой стек ответил `unknown`», её пример и есть Joomla на остатках Битрикса. Ответ `no` здесь сделал бы эту строку недостижимой.

Строка с сайта наружу не идёт, только `id` поколения.

  Метки корня — постоянная `JOOMLA_ROOT_MARKERS = ['administrator', 'libraries', 'plugins']` (Т15), она идёт в `rootMarkers()` адаптера в Э3.7.

  `rootHint` судит только имена корня, на шаге 2, до пароля базы (Э2.7). В публичной папке лежат `index.php`, `defines.php`, `administrator/`, `api/`, `media`, `images`, `.htaccess`, `robots.txt` (`PublicFolderGeneratorHelper`, `research/src/joomla/pkg-5.4.10`). Без подсказки такой сайт дошёл бы до «Не узнали»: `index.php` в корне есть, а «Без доступа» этот исход не предлагает. С подсказкой он получает строку `outside_root` Т27. `renamed_folder` Joomla не отвечает: имя `administrator` задано в `includes/defines.php`, настройки для него нет. На корне с `libraries` подсказки нет, даже если рядом лежит `defines.php`: это поздний отказ `readLayout` на экране настройки (Э3.3, Т16, сценарий I4).

  ```js
  /** Чем хост отличается для контейнеров. Читается из `docker info` и пробным контейнером, не из process.platform. */
  export function hostOf({ operatingSystem, bridgeGateway, hostGateway, localAddresses }) {
    if (/Docker Desktop/.test(operatingSystem))
      return { kind: 'desktop', mirror: true, listen: '127.0.0.1', relay: null, upstream: 'host.docker.internal' }
    return localAddresses.includes(hostGateway)
      ? { kind: 'linux', mirror: false, listen: '127.0.0.1', relay: bridgeGateway, upstream: 'host.docker.internal' }
      : { kind: 'vm', mirror: false, listen: '127.0.0.1', relay: bridgeGateway, upstream: bridgeGateway }
  }
  ```

  `hostGateway` стенд получает пробным контейнером, `localAddresses` — из `networkInterfaces()`, как `verify-preview-network.mjs:316-330`. Третий вид — ВМ Colima: `host-gateway` ведёт на Mac, а не на `docker0`, это уже записано в `infra/dev/preview-verify/README.md:18` и `packages/sandbox-providers/src/preview/config.ts:25-27`. `docker info` в ВМ не говорит «Docker Desktop», поэтому без пробы она считается обычным Linux.

  На Linux и в ВМ: задания раннера в сети хоста видят loopback напрямую, зеркало не поднимается. Роли `llm` и `mcp` слушают loopback (`listenHost`, `app-bootstrap`); стенд поднимает в своём процессе `net`-пересыльщик `relay:<порт>` → `127.0.0.1:<порт>` для `llm`, `mcp` и шлюза предпросмотров, адрес шлюза моста — `bridgeGatewayAddress` (`apps/core/scripts/verify-agent-content-role.mjs:148`), как его зовёт `bridgeGateway` стенда контента (`apps/core/scripts/verify-agent-content.mjs:270`). `LLM_GATEWAY_CLIENTS: '127.0.0.1/32'` остаётся: роль видит пересыльщик. `PREVIEW_GATEWAY_HOST` остаётся `127.0.0.1`: это адрес прослушивания роли `preview` (`apps/preview/src/config/config.ts:159`), адрес моста занял бы порт пересыльщика.

  В виде `vm` контейнеры ходят на `upstream`: `SANDBOX_LLM_UPSTREAM` и `SANDBOX_MCP_UPSTREAM` равны `http://<docker0>:<порт>`, этот адрес добавляется в `LLM_GATEWAY_HOSTS` и `MCP_ALLOWED_HOSTS`.

  Реле браузера агента стенду подставить нечем: `previewRuntimeConfig` (`apps/core/src/previews/previews.providers.ts:50-60`) `gatewayHost` не передаёт, хотя схема `DockerPreviewConfig` его принимает. Поэтому здесь одна малая правка продукта, а не настройка демона ВМ: профиль Colima общий с другими стендами. `core` читает `PREVIEW_RELAY_GATEWAY_HOST`, значения `host.docker.internal` (по умолчанию) или IPv4, в production только частный адрес, и передаёт его как `gatewayHost`. Та же настройка нужна M10 при `PREVIEW_EXECUTOR=runner`. Поведение остальных путей не меняется: значение по умолчанию равно сегодняшнему.

  `bash infra/dev/stack-verify/colima-m7.sh <стек> [--no-sync] [--build=<id>] [--group=<группа>] [--runtime=runc|runsc] [--no-m2]`. Шаги и проверки перечислены в Э3.14. `--build=` ограничивает сборки шагов 3 и 4, `--no-m2` пропускает шаг 3: здесь нужен один выпуск, а не обвязка М2 всех сборок.

## Расхождения с проектом

1. **Три сборки на четыре ветки.** §5.1 называет 3.10.12, 5.4.10, 6.2.0, а §4 обещает полную форму и 4.x, §5.5 требует М0–М4 «на всех ветках стека». Без прогона `j4` не может быть `dev`. К тому же граница 4.0 (Т62) опиралась бы на ветку, которая ни разу не запускалась. Предложение: четвёртая сборка 4.4.14, в договоре так и записано (Э3.9). Цена — один архив и несколько минут на прогон. Вопрос В1.
2. **Договор Э2 и порядок адаптера.** Э2.3, нарушение 4: при `files: 'off'` `readVersion`, `readLayout`, `driftProbe`, `derivedCopyOf` обязаны быть `null`, а нарушение 5 при `files !== 'off'` требует все методы. Поэтому постепенная регистрация с `off` невозможна. Сделано: модули пишутся без реестра, адаптер появляется целиком в Э3.7 со значением `dev`. Значение ставится до стенда, а не после него, потому что закрытый стек не проходит `project.create` стенда: условие §5.5 доказывается к концу этапа, в production Joomla закрыта всё это время. Э5 принял тот же порядок; Э4 проверить при сборке плана.
3. **`configuration*` срезает ядро.** `docs/research/2026-11-site-stacks/joomla.md:865` и спайк (`configuration.php*`, «на Linux цепляет только `configuration.php`») верны для `.gitignore`, но `createImportPathPolicy` сравнивает без учёта регистра. Сделано: `/configuration*` только в корне, на глубине три точные формы (Э3.3), тест на настоящих именах.

## Вопросы

- **В3. Если `release` на Linux не зеленеет.** CI тогда идёт с `import,preview`. Но условие `dev` этим не закрыть: М7 требует М4 под `runsc`, а это Linux. Такой исход — вопрос О2 в §7 проекта, этап до ответа не закрывается.
