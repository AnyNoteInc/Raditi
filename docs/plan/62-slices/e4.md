  ```ts

  export const OPENCART_VERSION_FILE = 'index.php'
  export const OPENCART_DRIVER_FILE = 'system/library/db/mysqli.php'

  /** The constant literal of `define('NAME', '…')`, stated once; null when it is none or several. */

  /** The file defines NAME, with a literal or not. */
  export function opencartDefines(file: Uint8Array, name: string): boolean
  /** `define('DIR_STORAGE', DIR_SYSTEM . 'storage/')`, as both installers write it. */
  export function storageBesideSystem(file: Uint8Array): boolean
  /** `set_charset('utf8')` of the driver, lower case; null when the file does not state it. */
  ```

  `opencartDefine` — через `phpStringsAfter`, как `defineOf` в `wordpress-db-copy.ts:23`: регистр `define` любой, кавычки любые, конец `[ \t\r\n]*\)`. `storageBesideSystem` — регулярное выражение по байтам latin1, пробелы вокруг `.` любые. `opencartCharsetOf` — `set_charset\(\s*['"]([A-Za-z0-9]+)['"]\s*\)`: в 3.0 и ocStore стоит `utf8`, в 4.1 `utf8mb4`.

  ```ts

  export const opencartExtrasSchema = z.strictObject({
    adminDir: z.string().regex(/^[A-Za-z0-9_-]{1,64}$/),
    /** Только ocStore 3.0.4+: на 7.4 он не стартует (`composer/platform_check.php`). Иначе таблица ветки. */
    firstPhp: z.literal('8.1').optional(),
  })
  export type OpencartExtras = z.infer<typeof opencartExtrasSchema>
  ```

  Значение по умолчанию — как `modxFactsOf`: требование контракта 7 Э2. Сайт без записанной раскладки до рецепта не доходит: его держит `no_layout` (Э2.9).

  `opencartReadVersion(read)`, одно чтение: `index.php`, `opencartDefine(file, 'VERSION')`, `parseSiteVersion`. `read` вернул `null`, нет литерала, схема не прошла — `{ kind: 'unknown' }`. Ошибку чтения метод не ловит: в сеансе мастера сбой соединения бросает, это `transfer_failed` с повтором, а не `version_unknown` (§2.3, Т26, ловушка 2). `other_product` метод не возвращает. Проходят `3.0.3.8`, `3.0.4.1b`, `2.3.0.2.4`, `4.1.0.4`, `1.5.6.4`.

  `opencartReadLayout(tree)`, по порядку, первый сработавший шаг отвечает:

  | Шаг | Условие | Ответ |
  | --- | --- | --- |
  | 1 | `tree.read('config.php')` — null | `refused`, `outside_root` |
  | 2 | `DB_DRIVER` не литерал из `mysqli`, `mysql`, `mpdo`, `pdo` | `refused`, `other_engine` |
  | 3 | Не `storageBesideSystem`, и литерал `DIR_STORAGE` не равен `<система>storage/`, где `<система>` — литерал `DIR_SYSTEM` или литерал `DIR_OPENCART` плюс `system/` | `refused`, `outside_root` |
  | 4 | Папка админки не найдена (ниже) | `refused`, `renamed_folder` |
  | 5 | `tree.read(OPENCART_DRIVER_FILE)` дал файл, `opencartCharsetOf` не null и не `utf8`, `utf8mb3`, `utf8mb4` | `refused`, `encoding_unsupported` |
  | 6 | Иначе | `read`, `extras`, `adminPath: '/<adminDir>/'` |

  Папка админки. `tree.list('')`, записи `directory`, имя по `^[A-Za-z0-9_-]{1,64}$`, кроме `catalog`, `system`, `image`, `install`, `extension`, `vqmod`; `admin` первой, затем по алфавиту, не больше 16 папок. Кандидат: `tree.read('<папка>/config.php')` не null; `opencartDefines(file, 'HTTP_CATALOG')`; `opencartDefines(file, 'DIR_CATALOG')` или литерал `APPLICATION` равен `Admin`; `tree.read('<папка>/controller/common/login.php')` не null. Побеждает первый кандидат, чей литерал `HTTP_SERVER` кончается на `/<папка>/` (OC 4 оставляет старую папку рядом, `docs/research/2026-11-site-stacks/opencart.md:140`); такого нет — первый кандидат.

  `firstPhp` пишется только при литерале `VERSION_CORE` файла `index.php`, равном `ocStore`, и `compareSiteVersions(version, '3.0.4') >= 0`. `extras` проходят `opencartExtrasSchema` перед ответом. Ни одно значение `DB_*` из функции не выходит.

  `opencartDatabaseSettings(read)`: `config.php`; файл больше `siteImportLimits.configFileBytes` — null; `DB_PREFIX` не один литерал — null; `opencartCharsetOf` драйвера null — null, и `core` идёт по каталогу базы (`preview-builder.ts:283-298`); `siteDatabaseSettingsSchema.safeParse({ tablePrefix, charset, collation: null })`, отказ схемы — null.

  `opencartConfigSecrets(read)`: `config.php`, затем `admin/config.php`, одно за другим; строки `define` с `DB_PASSWORD`, `DB_SSL_KEY`, `DB_SSL_CERT`, `DB_SSL_CA`, `CACHE_PASSWORD` через `phpConfigStrings`, как `secretDefine` в `wordpress.ts:172`, конец `[ \t\r\n]*[),]`; всё через `secretValues`. Переименованная админка не читается: у метода есть только `read`, пароль в обоих файлах один (`docs/research/2026-11-site-stacks/opencart.md:226`).

  `rootHint` всегда `null`, `renamed_folder` он не отвечает. Подсказку `inspectSiteRoot` (Э2.7) читает и у стека, чьи метки прошли, поэтому ответ по именам дошёл бы до клиента. `admin` в метках нет: папку переименовывают (`docs/research/2026-11-site-stacks/opencart.md:115`, Т15), и сайт с `adm1n` метки проходит.   Закрытая панель (Т2, правка 19). Шаг 2 читает `adminPathDefault`: при папке `admin` отказ приходит там. При папке `adm1n` шаг смотрит на `/admin/` и защиты не видит. `readLayout` по сети не ходит, а в `SiteLayoutReading` нет значения для такого отказа и нет текста, поэтому адаптер ничего не добавляет: клиент узнаёт об этом на старте сессии (Э9.3). Где проверять такую панель — вопрос Он7 (Р19).

  `dev` у ветки и стека — рабочее значение этапа, как у Joomla: `oc30` держит 3.0.0–3.0.4.x и ocStore 3.0.3–3.0.4, `oc305` — 3.0.5+. `8.1` в списке `oc30` стоит для ocStore 3.0.4+ (`firstPhp`). `oc41` остаётся `dev`: клиенту это `not_yet` (Т27). `oc40` — В3. В production до `on` `siteSupportOf` даёт `stack_off`, поэтому сайт с собственным `yes` получает тот же ранний стоп на шаге 1, что Битрикс (Т27). Адаптер для этого ничего не объявляет.

  `fingerprint(pages)`, по порядку: страниц нет — `unknown`; страница `/catalog/view/javascript/common.js` содержит `getURLVar` (сверено: 2.3.0.2, ocStore 3.0.3.7, 3.0.5.1, 4.1.0.4) или на главной есть `catalog/view/theme/`, `catalog/view/javascript/`, `catalog/view/stylesheet/` — `yes`; на главной `FOREIGN_GENERATOR` (Э3.2: `<meta name="generator">` WordPress или Drupal) — `no`; иначе `unknown`. Ссылки на `/wp-content/` и `/bitrix/` дают `unknown`: это могут быть остатки прежнего сайта, чужое «yes» тогда идёт строкой Т27 «Снаружи признаки другой платформы». Сначала `yes`: старая ссылка в описании товара или чужой мета-тег рядом с признаками OpenCart не должны дать отказ «не тот сайт» (Т27). `no` значит только работающую чужую систему: страница защиты от ботов, ошибка 503 и заглушка хостинга дают `unknown` (Т26, ловушка 6). `PublicPage` не несёт статуса, поэтому страница без признака ничего не доказывает (В4 Э2). `publicGeneration(pages)`: на главной `catalog/view/stylesheet/` — `oc41`, иначе `null`: 2.x от 3.0 снаружи не отличить (Т3).

  Запрещено: `isSiteRoot`; чтение `config.php` в `opencartReadVersion`; ловля ошибки чтения в `opencartReadVersion`; значение с хостинга вне регулярных выражений; значение с сайта в ответе `publicGeneration`; условие в `rootHint` по отсутствию `admin`; подсказка клиенту, где посмотреть версию (`62-onboarding.md` §1, «Что не взято»); слово «новости» в `terms`.

Добавлена метка `Backtrace: 0`: 4.1 при `config_error_display = 1` печатает исключение текстом с ответом 200 (`catalog/controller/startup/error.php:82-103`), ни одна метка `docs/research/2026-11-site-stacks/opencart.md` §9 его не ловит, поэтому выпуск кода, сломанного на 4.1, считался бы установленным.
- **Р11. `config_mail_engine` на 4.1.** `docs/research/2026-11-site-stacks/opencart.md:398` советует `''`, Т56 — `mail`. Взято Т56: письмо уходит в заглушку `sendmail_path`, а не теряется в ветвлении; М2, случай 8.

- **Р15. Зависимости этапа.** §5.1: Э4 зависит от Э1 и Э2, Э3–Э5 параллельны. На деле нужны Э3.1, Э3.4, Э3.5, Э3.7, Э3.8, Э3.10–Э3.13, Э5.4. Параллельны модули и политика (Э4.1–Э4.3), дальше Э4 идёт за Joomla. Э3 просил проверить порядок адаптера: принят его порядок, адаптер входит целиком в Э4.4.

- **Р17. Раздел `connection` вырос после срезов.** §2.3 итогового проекта добавил `fullName`, `configFile`, `terms`, а в `recognition` — `coreFolder`. Сделано: все поля в Э4.1, строки условий — из таблицы Т27, имя файла — с доски `O-db-shop`. Значения `fullName` в проекте нет: `'OpenCart'` записано значением по умолчанию, этого исхода OpenCart не даёт. `liveDetail` стоит по рекомендации на вопрос 2, как доски (`62-onboarding.md` §7).
- **Р18. `rootHint` OpenCart.** Т15 оставляет выбор адаптера на Э2 и снимает вид «Имена папок», если таких нет. Подпись доски `O-nofiles-layout` и правка 16 допускают оба пути. Сделано: `rootHint` всегда `null`, значение по умолчанию. `admin` не метка, а подсказку читают и у найденного стека (Э2.7, В11 Э2); переименованная панель поддержана, и ответ по отсутствию `admin` отнял бы у неё полную форму. `renamed_folder` у OpenCart только поздний: папка панели не найдена в `readLayout`.
- **Р19. Правка 19 и переименованная панель.** Т2 говорит, что отказ придёт позже, из `readLayout`, и что текста нет. По сети `readLayout` не ходит, значения для этого нет ни в `SiteLayoutReading`, ни в `siteLimits`, поэтому такого отказа нет вовсе. Шаг 2 смотрит на `/admin/` и ложно откажет, если этот адрес закрыт, а панель живёт в другой папке: нужно условие в Э9.1, значение по умолчанию. Он7 остаётся вопросом владельца.
- **Р20. Ловушки 2 и 6 реализуются и в адаптере.** Т26 называет их общими, но Э4.1 мог сломать обе: поймать ошибку чтения или ответить `no` на странице без признаков. Сделано: договор и тесты Э4.1, порядок `yes` раньше `no`. Общие проверки контракта стоят в Э2.3: нарушение 8, `neutralPublicPages`.
- **Р21. Обещание шага базы магазина.** `O-db-shop` говорит, что таблицы с заказами, покупателями и паролями в копию не идут. Э4.3 проверял это на восьми именах. Сделано: тест по шаблону на все правила, чтобы новая строка политики не сделала текст ложным.
- **Р22. `no` на чужих ссылках.** Договор отвечал `no` на `/wp-content/` и `/bitrix/` в `src` и `href`. Тогда главная с остатками старого сайта слышала «не тот сайт», а строка Т27 «Снаружи признаки другой платформы» у OpenCart была недостижима. Сделано, как у Joomla (Э3.2): на ссылках `unknown`, `no` только по `generator` WordPress или Drupal. Значение по умолчанию. Цена та же: сайт в подпапке адреса под другой CMS без такого мета-тега и без признаков адаптеров проходит мимо этой сверки, Т27 такого обещания не даёт.

## Вопросы

- **В1. Откуда брать ocStore 3.0.3.7 для стенда.** В теге `v3.0.3.7` пуст `vendor/react/promise`, такое дерево не стартует; есть `composer.lock`. Ещё в дереве тега нет `config-dist.php` и `admin/config-dist.php`: `installOpencart` тогда создаёт пустые `config.php` и `admin/config.php` (владелец `www-data`), их содержимое пишет `cli_install.php`, — так шёл Э1.4 (план 62, §10, «Э1.4: отступления от договора»; правки партии Э1). Полный архив с `ocstore.com/downloads`, если он есть, этот шаг не меняет: файл без `-dist` установщик всё равно перепишет. Рекомендую: архив тега и шаг `composer install --no-dev` в контейнере по этому `composer.lock`, образ `composer:2` по digest, в `opencart.mjs`. Запасной путь: архив с `ocstore.com/downloads`, если там полная сборка. Адреса `opencart-3.0.3.8.zip` и `opencart-4.1.0.4.zip` не проверялись: исходящих запросов в этой работе нет. Нет такого файла — исполнитель берёт адрес со страницы релиза, поведение договора то же.
- **В2. Даёт ли `derived_copy` «Попробовать ещё».** Рекомендую нет: `feedFailureRetry: false`, код не в `keptRetryCodes`. Тот же запрос в классе `heavy` даст тот же отказ дороже; клиент может написать другими словами.
- **В3. Что с OpenCart 4.0.** Т27 и §4 называют 2.x, 4.1 и 1.5, про 4.0 молчат. Рекомендую ветку `oc40`, `files: 'off'`, `browser: false`: клиент получает `not_yet`. Без строки версия 4.0.x попала бы под В7 Э2 только выше таблицы, а она внутри.
- **В4. Какие ключи `total_*` и `shipping_*` брать.** Т57 называет тему, модули и оплату, а без итогов корзины и доставки заказа нет. Рекомендую окончания `_status`, `_sort_order` у итогов и пять встроенных способов доставки, в которых секретов нет (`flat`, `free`, `item`, `pickup`, `weight`). Строже: только `flat`.
- **В5. Сайты с vQmod.** Т45 о них молчит. Файлы `vqmod/vqcache/` не импортируются, vQmod пересобирает их сам, папка в `writableFolders` не названа, запуск не проверялся. Рекомендую ничего не добавлять в Э4: сайт либо поднимется, либо честно получит `boot_failed`; строка на экзаменационный сайт Э13.
