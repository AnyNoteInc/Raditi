# План 59. Инструменты диалога справа — только по запросу

Запрос владельца от 29.10.2026 (§1): по умолчанию в диалоге только чат, а браузер, предпросмотр, файлы, база данных и проверки открываются справа — по кнопке «+» в правом верхнем углу или по явному действию. Самостоятельное открытие остаётся одно, из ответа владельца на вопрос по макетам: панель открывается сама один раз, когда браузер агента запустился, пока клиент смотрит диалог (И2). Запрос заменяет прежние решения об автоматическом раскрытии панели (И1). Смысл режимов `task.mode`, требования задачи и возможности агента не меняются — меняются компоновка и способ открытия.

Решения этого плана — **И1–И20** (§4). Где владелец назвал поведение прямо, это его решение; остальное — значения по умолчанию по указанию от 09.10.2026 («принимай все решения по умолчанию»), часть из них владелец видел на макетах 29.10.2026 и не возразил. В spec §20 они войдут блоком «Инструменты диалога справа — решения 29.10.2026». Работа идёт в отдельном дереве `raditi-tools-panel`, ветка `feat/tools-panel` от `main` `d564390a` (#21). План записан 30.10.2026; итог — §8 «Результат».

## 3. Что должно остаться верным

1. **Просмотр — не выполнение.** Открыть, переключить или закрыть инструмент — только показать или скрыть его. Закрытие не отменяет задачу, не закрывает сессию браузера и не значит «Продолжить работу агента»: ручное управление остаётся у того, кто его держал. Просмотр не создаёт сессию браузера (её создаёт только `ensure` в `core`) и не меняет требования задачи; смысл `task.mode`, требования задачи и возможности агента — прежние.
2. **До открытия — ни билетов, ни рамки, ни подробностей.** Пока инструмент не открыт, нет ни `browser.streamTicket` и WebSocket, ни `preview.ticket` и iframe, ни `candidate.get` и `candidate.fileDiff`; лента опрашивается как прежде. Исключение одно — одноразовый поток нажатия «Продолжить работу агента» при закрытом «Браузере» (И11).
3. **Правила не меняются — меняется только то, когда их видно.** Ручное управление и эпохи, пауза, простой (30 минут без зрителя и действий, И18) и пробуждение остановленного предпросмотра (только просьбой, сделанной после остановки, И10) — как прежде.
4. **Панель не открывается по тексту агента.** Упоминание браузера или файла в ответе агента ничего не открывает. Самостоятельное открытие одно — запуск браузера (И2, И3).
5. **Черновик, вложения, прокрутка и идущая задача** переживают открытие, переключение и закрытие: лента и поле не перемонтируются (И19).
6. **Навигация, список диалогов и обе темы — прежние.** Только тема MUI, её токены и существующие компоненты, без новых цветов вне темы и без новых зависимостей без нужды; стек в trpc и web не сравнивается (правило 8). Деньги, Vault, выпуск и песочница не затрагиваются.

Где код основы с ним расходится, исполнитель среза правит по коду и называет отступление в §8 «Результат». 30.10.2026 договор приведён к сделанному коду с правками ревью; что изменилось против первой редакции, помечено «(§8)» и перечислено в §8, «Отступления от договора».

### Модель — `dialog-tools.ts`

`apps/web/src/components/chat/dialog-tools.ts` — чистый модуль без React, тесты — `dialog-tools.test.ts`.

```ts
export const dialogTools = ['browser', 'preview', 'files', 'database', 'checks'] as const
export type DialogTool = (typeof dialogTools)[number]
export type ChangesTool = Extract<DialogTool, 'files' | 'database' | 'checks'>
/** Кто открыл инструмент (И9). */
export const toolOpeners = ['menu', 'changes', 'command', 'card', 'take', 'watch', 'launch'] as const
export type ToolOpener = (typeof toolOpeners)[number]

export interface ToolsState {
  /** Открытые инструменты — вкладки в порядке открытия. */
  open: readonly DialogTool[]
  /** Вкладка на экране; null ровно тогда, когда open пуст (панель закрыта). */
  active: DialogTool | null
  /** Браузер уже открылся сам или клиент его закрыл: в этом показе сам он больше не откроется (И3). */
  launchSpent: boolean
  /** Запуск на узком экране, после которого клиент браузер ещё не открывал (точка, И13). */
  launchUnseen: boolean
  /** `id:revision` кандидата, при котором вкладка изменений последний раз была на экране (И13). */
  seenChanges: string | null
}
export const closedTools: ToolsState = {
  open: [], active: null, launchSpent: false, launchUnseen: false, seenChanges: null,
}
export type ToolsAction =
  | { type: 'open'; tool: DialogTool; by: ToolOpener } // в конец или сделать активной, без дубля
  | { type: 'show'; tool: DialogTool } // вкладка выбрана на полосе: только показать, не просьба (§8)
  | { type: 'close'; tool: DialogTool } // активной становится соседняя справа, иначе слева
  | { type: 'closeAll' } // «Скрыть панель», «К диалогу»
  | { type: 'launch'; wide: boolean } // браузер запустился (И2, И3)
  | { type: 'seen'; changes: string } // вкладка изменений на экране при этой ревизии
export function toolsReducer(state: ToolsState, action: ToolsAction): ToolsState
```

- **Состав меню** — `dialogToolsOf(head: FeedHeadState): DialogTool[]` по И6, в порядке меню. Задача в браузере (`requirements.browser`) — `['browser']`, всегда, в том числе завершённая. Задача с репозиторием — `preview` (если `head.preview !== null`, его `origin` не `null`, а статус не `unavailable` и не `destroyed`), `files`, `database` (если `head.task.databaseChanges`), `checks`.
- **Метка** — `toolMark(tool, head, { open }): string | null` (И5): при `open` — «Открыто»; `files` — число файлов и медиа (как нынешний `candidateCount`), `database` — число записей, `checks` — «N из M» (прошедшие из всех); без данных — «пока нет», в завершённом диалоге без кандидата — «нет»; `browser` — по `head.browser`: у живой сессии управляет клиент — «Управляете вы», иначе просьба о помощи — «Ждём вас», иначе — «Работает агент»; сессии ещё нет, а диалог идёт, — «пока нет» (вкладка тогда говорит, что браузер откроется, когда агент начнёт работу); сессия не живая или диалог закрыт без неё — «Закрыт» (§8; слова — из `browserText.status` и `toolText.mark`); у `preview` метки нет.
- **«Посмотреть изменения»** — `changesToolOf(head): ChangesTool` (И10): первый из `files` → `database` → `checks`, в котором что-то есть, иначе `files`.
- **Пустые состояния** вкладок изменений (И6) — тексты в `chat-texts.ts`, выбор — функция модели по `ended` и `candidate`.
- `candidateCount` переезжает сюда из `preview-pane.tsx`; `paneTabsOf`, `paneOpensItself`, `shownPaneTab` и `PaneTab` удаляются вместе с их тестами.
- **Редьюсер.** `close('browser')`, `close` последней вкладки и `closeAll` — любое закрытие панели клиентом — ставят `launchSpent`. `launch` при `launchSpent` ничего не делает; иначе ставит `launchSpent` и при `wide` открывает `browser` и делает его активным, при узком — только `launchUnseen` (если браузер уже не на экране). `open('browser', …)` и `show('browser')` снимают `launchUnseen`; `show` вкладки, которой нет, ничего не меняет (§8). Редьюсер не знает о фокусе, сети и ширине экрана, кроме `launch.wide`.
- **Фокус** — `movesFocus(by, { covers })`: явное открытие ставит фокус на вкладку; `take` — только когда открытие закрывает диалог (`covers`: ниже `lg` открывается первый инструмент, и нажатая кнопка уходит из вида); `launch` — никогда; исключение держит `DialogView` (ниже, «Запуск»; §8).
- **Точка** — `toolsDot(head, tools)` и имя «+» — `toolsLabel(dot)`; плитки меню — `toolTilesOf(head, tools)`.
- Каждое монтирование `DialogView` начинается с `closedTools` (И1): ничего из этого не хранится ни в URL, ни в cookie, ни в хранилище браузера.

### Компоновка `DialogView` (59.3–59.7)

- **Состояние** — `const [tools, dispatchTools] = useReducer(toolsReducer, closedTools)`. Уходят `view`, `paneTab`, `closedOn`, `paneOpened`, `hasPane`, `changesMark`, `paneClosed`, `opensItself`, `paneShown`, `shownView`, `paneVisible`, переключатель «Что показать» (`viewSwitchText`, `viewId`), `SHOW_PANE_ID` и проп `pane` у `DialogHead`.
- **Открытие** — `openTool(tool, { by })`: диспатч `open`, для `preview` — ещё `previewCalls.call()` при каждом вызове (И10). Фокус после отрисовки — на вкладку `dialog-pane-tab-<tool>` при `menu`, `changes`, `command`, `card` и `watch`; `take` — только когда открытие закрывает диалог: ниже `lg` открывается первый инструмент, и нажатая кнопка уходит из вида (`movesFocus(by, { covers })`, §8); `launch` его не трогает. Её зовут меню «+», `actions.onShowChanges` (`changesToolOf(head)`), `runCommand('preview')`, «Открыть браузер» (`by: 'card'`), `takeControl` (`openTool('browser', { by: 'take' })` и `stream.take()`) и «Смотреть, что делает агент» (`by: 'watch'`). Вкладка, выбранная на полосе, — `dispatchTools({ type: 'show', tool })`: не просьба, `previewCalls.call()` не зовётся (§8).
- **Запуск** — `launched()`: `dispatchTools({ type: 'launch', wide })`. Перед диспатчем, если именно этот запуск откроет панель (от `lg`, панель закрыта, запуск не потрачен), запоминается, где фокус (`focusTakenByOpening`): на «+» шапки (`#dialog-tools`), внутри меню «+» (бумага карточки и листа помечена `data-tools-menu`) или внутри `[data-site-list]`. После отрисовки, если этот элемент удалён из документа или скрыт (нет `getClientRects`), фокус ставится на «+» в конце полосы вкладок; иначе и в остальных случаях фокус не трогается (§8).
- **Закрытие** — `closeTool(tool)` и `closeTools()`: диспатч и сброс `fullscreen` (И17). После последней вкладки фокус — на «+» в шапке (`id="dialog-tools"`, одна кнопка с этим id на экране) с `preventScroll` (§8: в окне ниже 420 px высотой, где шапка не прилипает, «К диалогу» иначе уводила страницу к шапке), после не последней — на ставшую активной вкладку. Закрытие ничего не вызывает ни на сервере, ни в потоке.
- **Поток** — `visible = tools.active === 'browser'` на любой ширине: область на узком экране показана ровно тогда, когда что-то открыто.
- **Шапка.** `DialogHead` выходит из прокручиваемой колонки ленты: на широком экране стоит над областью ленты и не прокручивается, высотой 56 px, как полоса вкладок: пока панель закрыта — сразу под полосой крошек, при открытой — под «Назад к диалогам»; на узком — `position: sticky` у верха вместе со строкой «Чат | Работа» (с учётом липкой полосы оболочки от `md`, `site-shell.tsx`), а при `@media (max-height: 420px)` — `position: static` (§8). Справа, после «⋯», — «+», пока панель закрыта. Лента и поле не перемонтируются.
- **Запас под липким** (§8). Всё в колонке ленты, кроме поля (`[data-feed-field]`), получает `scroll-margin-top: var(--dialog-head-room)` — 112 px ниже `md`, 104 px от `md`, 0 от `lg`; в низком окне 0 и 60 px — и `scroll-margin-bottom: var(--dialog-field-room, 156px)`: высоту поля и 16 px кладёт в переменную `ResizeObserver`.

### Меню и панель

- **Меню** — `apps/web/src/components/chat/tools-menu.tsx`. Кнопка «+» — `IconButton` с `aria-label` «Инструменты» (и суффиксом точки, И13), `aria-haspopup="menu"`, `aria-expanded` и `aria-controls`. Меню на широком экране — `Popover` у кнопки, на узком — `Drawer anchor="bottom"`; внутри `Paper` с заголовком «Инструменты» (свой `id`, вне `MenuList`) и `MenuList` с `aria-labelledby` и `autoFocusItem`. Пункты `MenuItem` — плитки в два столбца (в один — при одном инструменте): значок, название, метка справа, высота не меньше 44. Esc и выбор закрывают меню; `Modal` возвращает фокус на «+», выбор затем ставит его на вкладку. Как сделано (§8): высота плитки задана по контрольной точке — `{ xs: 52 }` в карточке и `{ xs: 92 }` в листе, иначе правило MUI `@media (min-width:600px) { min-height: auto }` её сбрасывает; название в карточке переносится на вторую строку, метка — в одну; в листе значок и метка сверху, название под ними, у листа своя кнопка «Закрыть меню», а его бумага — модальный диалог с `aria-labelledby` на заголовок; бумага карточки и листа помечена `data-tools-menu`; плитка читается «<название>, <метка>» (запятая скрыта с экрана); фокус на первую плитку ставит `onEntering` перехода (под Strict Mode модальное окно иначе возвращало его на «+», 8d4049f9); Tab закрывает меню, как Esc.
- **Панель** — `apps/web/src/components/chat/tools-panel.tsx` (или внутри `dialog-view.tsx`, если так короче):

  - узкий экран: сверху «К диалогу» (закрывает все) и «+», ниже та же полоса; область во всю ширину, чат скрыт `display: none`. Как сделано (§8): область — `flex: 1 1 0` с `min-height: 480px` вместо `calc(100dvh − 112px)`, а оболочка, пока нарисована панель, передаёт ей высоту окна (`&:has([data-site-pane])` у блока под полосой и у `main` в `site-shell.tsx`); ссылка «Назад к диалогам» (`data-site-back` в `site-list-frame.tsx`) ниже `lg` скрыта, пока нарисована панель, а в полноэкранном режиме от `lg` получает `inert`, как полоса оболочки и список.
- **Содержимое вкладок:** `browser` — `BrowserPane` (файл на месте; смонтирован, пока вкладка открыта, как и предпросмотр, но поток идёт только при активной вкладке, а за другой вкладкой браузер не стоит никогда: у задачи в браузере других инструментов нет); `preview` — `PreviewTab` из `preview-pane.tsx`, смонтирован, пока вкладка открыта, даже неактивная (скрыт `hidden`), `showFrame` — пока вкладка открыта; `files`, `database` и `checks` — `CandidateTab`, только активная. id — `dialog-pane-tab-<tool>` и `dialog-pane-panel-<tool>`. `PreviewPane` как компонент со своей полосой вкладок уходит; `DatabasePanel` и `ChecksPanel` окна `/release` не меняются.

### Самостоятельное открытие (59.5)

- `apps/web/src/components/chat/new-dialog-hint.ts` — память модуля `{ taskId, at } | null`: `markNewDialog(taskId, at = Date.now())` зовёт `NewDialog` перед `router.push`; `isNewDialog(taskId, now = Date.now())` — то же `taskId` и `now - at <= 60_000`; `forgetNewDialog(taskId)`. Читается без удаления (Strict Mode), снимается после первого ответа ленты.
- `apps/web/src/components/chat/use-browser-launch.ts` — `useBrowserLaunch(head, { taskId, enabled, onLaunch })`, эффект на каждый новый объект `head` (каждый ответ ленты создаёт новый); `enabled` — задача в браузере и у web есть адрес трансляции (`browserStreamUrl !== null`): где кабинет не может показать браузер, запуск ничего не открывает и точки «браузер запущен» не ставит (§8);

  - запуск — ответ после опоры с `head.browser?.status === 'ready'`, когда опора не знала этой сессии готовой (у готовой сессии опоры другой `sessionId` или её не было), — вызывает `onLaunch()`; повторы гасит редьюсер (`launchSpent`), `wide` берётся в момент запуска;

### Прокрутка (И19) — `use-feed-follow.ts`, без второго механизма

- **Широкий экран, клиент не в конце:** при изменении размеров области или содержимого (открытие, переключение, закрытие панели, перенос строк) верхняя видимая строка `[data-feed-row]` остаётся на прежнем расстоянии от верха области — строка и её смещение запоминаются при прокрутке клиента и восстанавливаются в `ResizeObserver`.
- **Узкий экран:** пока лента скрыта (`display: none`), позиция страницы не трогается; когда лента снова показана, а клиент не был в конце, прокрутка страницы возвращается на запомненную до скрытия; был в конце — конец, как сейчас.

Работа из-за них не останавливается: до ответа действуют значения по умолчанию (указание от 09.10.2026).

**Известные ограничения:**

- **Черновик при конце диалога (И19).** Когда диалог переходит в конечный статус, ветка конца диалога оборачивает `Composer` в другой узел (`dialog-view.tsx`), и черновик теряется. Это не панель и не эта задача.
- **Простой без зрителя (И18).** Раньше на широком экране всегда видимая панель держала ждущую сессию браузера; теперь клиент, который смотрит только чат, через 30 минут без действий найдёт браузер закрытым, и войти на сайт, возможно, придётся снова.
- **Системный «Назад» на телефоне (И14, И19).** Что открыто, в истории браузера не хранится (И1), поэтому системный «Назад» из области инструмента уходит со страницы диалога: черновик и чипы прикреплённых файлов в поле пропадают (загруженное остаётся во входящих). Так было и до этой работы с переключателем «Диалог | …»; заметный возврат — кнопка «К диалогу», она всё сохраняет (ревью 30.10.2026, находка отклонена).
- **Верхний запас под шапкой — числа по замерам (И4).** `scroll-margin-top` ленты — 112, 104 и 60 px: если шапка станет выше (поле переименования выше 44 px, крупный шрифт, новая строка), запас за ней не последует. Нижний запас за высотой поля следит сам (`ResizeObserver`).
- **Низкое окно.** Область инструмента на узком экране не ниже 480 px, поэтому в окне ниже примерно 600 px страница под ней прокручивается — так задумано. Esc в меню «+» в окне ниже 420 px высотой возвращает фокус на «+» средствами MUI, без `preventScroll`, и страница прокручивается к шапке — обычный возврат фокуса, не менялся. Только в `next dev`: под Strict Mode `FocusTrap` меню при повторном монтировании разово отдаёт фокус «+» без `preventScroll` и прокручивает к ней; в сборке этого нет.
- **Та же ловушка высоты MUI вне этой работы.** У `MenuItem` с простым `minHeight: 44` правило MUI от 600 px делает высоту `auto`: так в меню аккаунта (`apps/web/src/components/application/user-menu.tsx`, четыре пункта). Не правилось — это не диалог; правка — `minHeight: { xs: 44 }`, как у меню «⋯» диалога и меню браузера (§8).
- **Фокус в списке диалогов при самостоятельном открытии** проверен только тестом jsdom (по тому, где стоит фокус): в `test:site` нет адреса трансляции, и запуск там выключен, а стенд `verify:browser-task` начинает диалог «Новым диалогом», и фокус в момент запуска стоит на содержимом (`#site-content`), а не в списке.
