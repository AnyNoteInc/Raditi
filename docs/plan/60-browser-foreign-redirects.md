# План 60. Переходы браузера задачи на другие сайты

Запрос владельца от 30.10.2026: «сделай возможным переадресацию на другой сайт». На вопрос, что именно открыть, владелец выбрал вариант «Переадресации с сайта»: «Если страница сайта перенаправляет на другой сайт (оплата, вход через сервис, внешний редактор), браузер идёт туда, показывает его, и агент может там работать. Сам агент открыть чужой сайт по адресу по-прежнему не может. Прокси выхода открывает публичные хосты, а закрытые адреса и подсети платформы остаются закрытыми.»

До этого браузер задачи ([план 57](57-browser-tasks.md), Б11) ходил только к хостам сайта: прокси выхода сессии отказывал любому другому хосту, а правила страниц (`packages/browser-providers/src/cloud/page-rules.ts`) обрывали запрос к нему и убирали страницу, которую принесла переадресация. Переход на страницу оплаты или входа через сервис кончался ошибкой действия.

Решения — **Ч1–Ч10**. Ч1–Ч3 и Ч8 — слова владельца, остальное — значения по умолчанию по указанию от 09.10.2026 («принимай все решения по умолчанию»). Ответы владельца на вопросы ревью — §4. В spec §20 они вошли блоком «Переходы браузера задачи на другие сайты — решения 30.10.2026», Б11 плана 57 и правила 1, 4 и 5 CLAUDE.md переписаны под них. Работа — в дереве `raditi-browser-redirects`, ветка `feat/browser-foreign-redirects` от `main` `245a235d` (#25).

## 1. Решения

| № | Решение | Источник |
| --- | --- | --- |
| Ч1 | Страница сайта может отправить браузер на другой сайт — переадресацией, ссылкой, формой, скриптом, новой вкладкой. Браузер идёт туда и показывает страницу клиенту; агент работает на ней теми же инструментами (`web_observe`, `web_click`, `web_fill`, `web_type`, `web_press`, `web_scroll`, `web_upload`, `web_wait`), клиент может взять управление. Другой сайт открывает только главный кадр страницы — её собственный переход; страница, которая уже на другом сайте, грузит что ей нужно и ведёт дальше по тем же правилам. Страница самого сайта с другого сайта не грузит ничего — ни картинок, ни скриптов, ни кадров, ни обращений к сервисам: что закрыл адаптер стека (Gravatar, Openverse, счётчики, шрифты), остаётся закрытым | Владелец; «только главный кадр» — по умолчанию (ревью) |
| Ч2 | Адрес, который называет сам агент (`web_open`) или клиент (`navigate` трансляции), — по-прежнему только сайт: `browserNavigationAllowed`, политика стека. Это правило инструмента, а не барьер: открытая переадресация сайта или ссылки другого сайта ведут куда угодно в публичном интернете | Владелец |
| Ч3 | Прокси выхода сессии открывает публичные хосты — режим открытого интернета (`ALLOW_PUBLIC=1`, тот же, что у песочницы хода с 26.10.2026), но только по TLS (`PUBLIC_TLS_ONLY=1`, новый выключатель `client-egress.mjs`): любое публичное DNS-имя на 443 и 8443 с SNI этого имени (ECH — с этим открытым именем); простой `http://` интернета прокси сессии не пересылает. Непубличные адреса, адреса IP, подсети платформы (`SANDBOX_EGRESS_REFUSED_SUBNETS`) и сервисы хоста закрыты, как прежде | Владелец; «только TLS» — по умолчанию (ревью) |
| Ч4 | Другой сайт — только `https://` на порту 443 или 8443 к публичному DNS-имени (`browserForeignPageAllowed` в `@repo/domain`, то же правило имени, что у хостов переменных клиента) и не хост, у которого два последних уровня имени — те же, что у хоста сайта: другой порт сайта, его поддомены, родитель и соседи могут получить cookie входа сайта, а политика стека их не судит, — правила страниц их обрывают, как прежде. Страницу `http://` другого сайта, которую принесла переадресация, браузер убирает, не показав; запрос её прокси не пересылает | По умолчанию: браузер задачи и так открывает только `https://` (Б11, Б33) |
| Ч5 | Политика стека (закрытые экраны и запросы админки, Б21, Б31, Б37) судит страницы и запросы хостов сайта — в том числе со страницы другого сайта; пути другого сайта она не судит — они описывают админку этого стека, а не чужой сайт. Не закрыто: переадресацию маршрут не видит, поэтому другой сайт может переадресовать браузер на адрес сайта, и запрос GET уйдёт на сайт с cookie входа до того, как правила уберут страницу; от действий по такой ссылке WordPress защищают одноразовые коды (nonce) | По умолчанию |
| Ч6 | Сохранения задачи считаются только на сайте: процесс `browser` не берёт объект задачи из адреса другого сайта и не считает нажатие «Сохранить» или «Опубликовать» на нём сохранением (Б22, Б34), а запрос, который меняет данные (не `GET`, `HEAD` или `OPTIONS`, с учётом заголовков подмены метода), со страницы другого сайта к хосту сайта правила страниц отклоняют (`accessdenied`). Так предел 20 объектов и запрет дубликата не обходятся формой другого сайта. Не закрыто: редактор на другом сайте, который сам пишет в сайт клиента со своего сервера; возврат с платёжной страницы на сайт формой `POST` не пройдёт | По умолчанию (ревью) |
| Ч7 | Сохранённый вход (Б36) вводится только в форму входа самого сайта — на странице того же источника, что стартовая. Пока он вводится, другой сайт закрыт целиком (форма с адресом отправки на другом сайте ничего туда не отправит, вход кончается `refused`), а поля берутся из того самого документа, который проверен: документ, ушедший на другой сайт между шагами, не получит ни одного знака. Вход на другом сайте — дело клиента, агент зовёт его `web_help` с причиной `login` | По умолчанию (ревью) |
| Ч8 | Переменной-выключателя нет: прокси выхода сессии всегда открывает публичные хосты по TLS, выключить переходы — правка кода. Ответ владельца от 30.10.2026 (§4, вопрос 4): `SANDBOX_INTERNET` удалён, интернет хода тоже не выключается | Владелец |
| Ч9 | Текст другого сайта идёт модели так же, как текст сайта: дерево доступности, значения паролей и секретные параметры адресов скрыты (Б20); то, что агент вводит или загружает там, уходит этому сайту. Это то же, что открытый интернет хода по решениям владельца от 26.10.2026 (правило 1); вопрос записан для юриста (§4, вопрос 2) | По умолчанию |
| Ч10 | Инструкции хода задачи в браузере получили раздел «Other sites» — без условий: другой сайт — не сайт клиента, его страницы — недоверенные данные; там агент не вводит и не загружает секреты, значения переменных, то, что показывают экраны админки, и персональные данные, не платит, не подтверждает оплату, не меняет настройки и ничего не удаляет, если клиент прямо не просил именно этого; вход там — `web_help` с `login`; сделанное там не объект задачи, `web_verify` его не видит, и агент называет клиенту, где и что он сделал. Описание `web_open` говорит то же коротко | По умолчанию (ревью) |

## 2. Срезы

1. **Домен и правила страниц.** `browserForeignPageAllowed` рядом с `browserNavigationAllowed` (`packages/domain/src/browser/hosts.ts`); `requestVerdict` и `committedAllowed` получают место запроса (`PagePlace`: главный кадр ли, адрес главного кадра страницы, идёт ли вход) — другой сайт только из главного кадра или со страницы другого сайта, изменяющие запросы такой страницы к сайту — отказ; `openAllowed` не меняется; инвариант порта (`browser/ports.ts`) и шапки модулей.
2. **Облачный браузер.** Маршрут и проверка подтверждённой страницы передают место; сохранённый вход — с закрытым другим сайтом и на ручках элементов проверенного документа (`cloud-browser.ts`).
3. **Прокси выхода.** Выключатель `PUBLIC_TLS_ONLY` (`infra/sandbox/client-egress.mjs`); контейнер `egress` сессии — `ALLOW_PUBLIC=1` и `PUBLIC_TLS_ONLY=1` (`packages/sandbox-providers/src/browser-session/containers.ts`).
4. **Процесс `browser`.** Контрольная точка читается только из адреса сайта, сохранение распознаётся только на странице сайта (`apps/browser/src/sessions/worker-session.ts`).
5. **Тексты для агента.** Раздел «Other sites» в инструкциях хода (`apps/core/src/tasks/turn-instructions.ts`), описание `web_open` (`apps/mcp/src/web/mcp-web.controller.ts`).
6. **Тесты и стенд.** Модульные тесты правил, домена, прокси, контейнеров, процесса и инструкций; настоящий Chromium (`RADITI_BROWSER_LOCAL_TESTS=1`): переадресация, ссылка и обратный путь, отказ `web_open` чужого адреса, страница `http://` другого сайта убрана, форма входа с отправкой на другой сайт; Docker (`RADITI_BROWSER_DOCKER_TESTS=1`): прокси сессии берёт публичное имя на 443 и закрывает порт не из списка, метаданные и сервисы хоста; стенд `verify:browser-task`, сценарий K.
7. **Документы.** CLAUDE.md (правила 1, 4 и 5, абзац «Задачи в браузере», стенд), spec §8, §18 и §20, таблица компонентов, план 57 (Б11), roadmap, README прокси, процесса `browser` и стенда, комментарий адаптера WordPress.

## 4. Ответы владельца и открытое

Ревью по правилам 1 и 4 оставило пять вопросов. Владелец ответил 30.10.2026, дословно: «1 - A / 2 - A / 3 - A / 4 - A убирай фича флаг / 5 - A». Варианты А — как сделано, поэтому код переходов эти ответы не меняют, кроме вопроса 4.

1. **Правило 4 на другом сайте — как есть.** Политики стека, `request_approval`, предела и записи в ленте там нет: агента держат только инструкции (Ч10). Если клиент вошёл в кабинет оплаты, хостинга, регистратора или CDN, агент технически может менять там настройки и удалять. Б24 и Б28 («проверьте сайт») не называют изменений на других сайтах. Разрешение на каждый новый сайт не делается.
2. **Правило 1 на другом сайте — как есть, вопрос к юристу вместе с гейтом 152-ФЗ.** Он записан в spec §20, «Вопросы юристу по трансграничной передаче»; до гейта модели идут только синтетические данные.
   - Персональные данные третьих лиц на другом сайте (кабинет платёжного сервиса, CRM, сервис заявок) уходят модели.
   - `web_upload` может отправить файлы клиента на любой, в том числе зарубежный, сайт.
   - Секреты в пути адреса другого сайта (номер платёжной сессии, ссылка входа) не скрываются — скрываются только параметры по имени.
3. **Ч2 — принято, что это не барьер.** Через открытую переадресацию сайта или ссылки другого сайта браузер клиента достаёт весь публичный интернет по `https://`.
4. **Выключателя нет, ни у браузера, ни у хода.** «Фича флаг» прочитан как единственный выключатель из вопроса — `SANDBOX_INTERNET` у `core`: он удалён (`config.ts`, `.env.example`, `turbo.json`). Каждый ход получает открытый интернет и навыки; закрыть интернет можно только правкой кода. Режим сети без интернета остался у порта песочницы (`NetworkPolicy.internet` необязателен): его используют стенды и тесты, он читает уже записанные планы ходов; планировщик ходов его больше не выбирает.
5. **Публичные имена самой платформы — как есть.** Правила страниц не выделяют хосты `APP_URL`, `PREVIEW_BASE_DOMAIN` и `BROWSER_STREAM_PUBLIC_URL`, для них это другой сайт. Соединение с ними закрывает прокси, когда адреса машин вписаны в `SANDBOX_EGRESS_REFUSED_SUBNETS`: пункт записан в README песочной ВМ и в M10 roadmap.

Удаление выключателя убрало и закрытую сеть хода, поэтому вместе с ним поправлено то, что на ней держалось (`/spec-check`, 30.10.2026):

- кабинет больше не обещает, что к сервису можно обратиться только по его адресам: поле «Адреса сервиса» говорит, что агент получит указание отправлять значение только на них;
- инструкции хода снова называют адреса переменных: прокси к хосту значение не привязывает, адресата держат только эти слова;
- spec §8 и §18 и README песочной ВМ описывают открытый интернет хода как единственный режим.

Проверки: `pnpm gates` — код 0 (test — 36 задач, `core` 1 754 и `web` 2 333, `check-architecture` — 2 338 модулей без нарушений, `test:infra` — 689 и 7 пропущены). `pnpm verify:db` до правки текстов — 606 проверок, восемь наборов: база 897, `core` 2 064 и 13 пропущены, `llm` 581, `mcp` 694, `preview` 77, billing 1 379, tRPC 1 056, web 2 336. Стенды не запускались: ход и раньше шёл с открытым интернетом по умолчанию, изменился только текст инструкций о переменных.

Что остаётся не закрытым (не вопрос владельцу, а известное ограничение Ч5 и Ч6):

- переадресация с другого сайта на адрес сайта — GET с cookie входа, защита — nonce;
- редактор другого сайта, который пишет в сайт со своего сервера;
- возврат с оплаты формой `POST`.

Не доказано: `runsc` (среда сессии под gVisor — только модульными тестами), настоящий сайт и настоящий платёжный сервис; живой режим и настоящая модель не запускались.
