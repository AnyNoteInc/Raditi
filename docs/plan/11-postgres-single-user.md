# PostgreSQL: единый пользователь raditi

30.09.2026. По указанию владельца все сервисы используют одного PostgreSQL-пользователя `raditi`. Это заменяет разделение прав из [отчёта B6](10-p3-gateway-database.md).

## Изменения

Web, core, будущие MCP/LLM, миграции, сиды и мониторинг используют `raditi`, владельца прикладной базы и схемы. У пользователя есть доступ ко всем таблицам, включая ключи шлюза, учёт и историю миграций, и возможность выполнять DDL. Проверки бюджета, отзыва ключей и правил учёта остаются в сервисном коде и ограничениях данных.

В шаблонах app-ВМ один прикладной пароль `postgres/password` и одинаковый PostgreSQL-пользователь во всех `DATABASE_URL`. Отдельные файлы паролей web/core/llm/owner удалены. Служебный `postgres` остаётся для init и обслуживания через сокет, без пароля для сетевого входа; сервисы его не используют. Dev exporter также переведён на `raditi`.

App bootstrap и dev init больше не создают `raditi_app`, `raditi_web`, `raditi_core`, `raditi_llm` или `postgres_exporter`. На прежней установке они транзакционно удаляют эти роли, их членства, права таблиц и колонок и default privileges. Перед очисткой проверяется отсутствие принадлежащих прежним ролям объектов данных и зависимостей в другой БД. При неожиданной зависимости откатывается весь переход: данные автоматически не удаляются и не передаются другому владельцу.

Схема данных не менялась. Уже применённая миграция B6 сохранена: её условные GRANT пропускаются после удаления старых ролей. Новая миграция не требуется; роли обслуживает bootstrap.

Восстановление использует `pg_restore --no-acl`: старый дамп может ссылаться на уже удалённых пользователей. Владение `raditi` сохраняется. После полного восстановления с `--create` bootstrap запускается повторно, поскольку ACL базы и схемы тоже не восстанавливаются из дампа. Порядок перехода, ротации пароля и восстановления обновлён в [runbook](../../infra/app/README.md).

Действующий контракт обновлён в spec, CLAUDE.md, roadmap и проекте P3. Прежние отчёты сохраняют исторические результаты с пометкой о замене решения. Изменение относится к PostgreSQL; существующие политики Vault и настройки Redis остаются самостоятельными механизмами.

## Проверки

`pnpm verify:db` использует одноразовую локальную PostgreSQL и случайные пароли. Для настоящих app bootstrap и dev init SQL проверены удаление старых ролей, сохранность данных, идемпотентность, атомарный отказ при владении чужим объектом и при правах на другую БД. Дамп таблицы со старыми ACL восстановлен после удаления старых ролей с сохранением строки и владельца `raditi`.

Независимое ревью исправило команду dev bootstrap в README: запускать в базе `raditi`, где находятся его зависимости, а не в служебной базе `postgres`. Сверка восстановления нашла пропущенный повторный bootstrap в `verify-edge` после перехода на `--no-acl`; он добавлен. Отдельный полный PostgreSQL dump/restore подтвердил, что bootstrap снова закрывает доступ `PUBLIC`, сохраняя данные, владельца и историю миграций.

Проверки выполнялись локально. Рабочая БД и облачные серверы не изменялись. Полный `verify:edge` с пересборкой приложений и продуктовый WordPress e2e в этой правке не запускались; полный локальный e2e остаётся обязательным перед облачной выкладкой.
