# Проверка каркаса B0–B5

26 сентября 2026 года, macOS + Docker Desktop. Код прошёл независимую проверку по `CLAUDE.md`
и спецификации: пакеты и БД, приложения, инфраструктура. Замечания исправлены.

## Локальные проверки

- `pnpm install --frozen-lockfile`: успешно, Node 26.10.0 / pnpm 12.6.0.
- `DATABASE_URL=postgresql://raditi:raditi@localhost:5432/raditi pnpm gates`: успешно.
  Типы и линтер — 19/19 задач; архитектурные зависимости без нарушений;
  тесты — 1059, включая все 77 тестов БД без пропусков; сборки Next.js и NestJS проходят.
- `pnpm e2e`: 6/6 smoke-тестов. Проверены главная, юридическая страница,
  анонимный и авторизованный health web, зависимости core и запуск MCP.
- `pnpm dev`: web :3000, core :8081, MCP :8082 отвечают 200. Web/core видят
  PostgreSQL, Redis, S3 и OpenBao. Детали health доступны по токену; MCP отдаёт только status.
- Сиды дважды запущены на рабочей dev-БД без создания дублей и обновлений.

## Инфраструктура

Проверены обязательные сервисы, мониторинг и профиль `site`. Все обязательные цели
Prometheus имеют `up = 1`, все шесть обязательных blackbox-проверок — `probe_success = 1`.
PostgreSQL и Redis: `pg_up = 1`, `redis_up = 1`. Grafana открывает дашборд
«Радити — обзор», проверка источника Prometheus возвращает OK.

WordPress отвечает 200 и показывает первоначальный установщик; `probe_success` профиля `site` равен 1.
Установка и настройка самого тестового сайта — перед сценариями PoC.
Все шесть бакетов `raditi-*` существуют; `s3-init` успешно выполнен дважды.
При недоступности S3 он завершается с ошибкой. Promtool подтвердил конфигурацию и 6 правил.

Профили `llm`, `ci`, `monitoring-host` не включались: их цели ожидаемо DOWN и вынесены
в отдельные панели. Проверка вызовов моделей и регистрации раннера остаётся соответствующим задачам PoC.
