# s4. Круг Tiptap ↔ канонический remark на русском корпусе (19.11.2026)

*Спайк 4 этапа Э0а [плана 88](../../../../plan/88-artifacts.md). Код продукта не менялся. Всё шло в Node без браузера, корпус синтетический и написан для спайка. Каталог запуска ниже называется `<scratch>`.*

## Вопрос

Портит ли круг «канонический Markdown (remark) → Tiptap через `@tiptap/markdown` → Markdown → канонический remark» русские документы агента? Что ломается и как это исправить? Это проверка утверждения §7.7 «Документ»: «сервер приводит Markdown к одному виду: маркер списка `-`, таблицы без выравнивания. Поэтому круг «редактор → Markdown → редактор» ничего не портит» — и выбора §7.13.

## Коротко

**Нет — с `@tiptap/markdown` 3.34.0 круг портит документы. Да — если Markdown в редактор и обратно переводит свой мост mdast ↔ документ Tiptap на том же remark, что рисует `@repo/doc-render`.**

- **`@tiptap/markdown` меняет видимые слова в 15 из 30 документов.** Главное — неразрывные пробелы в таблицах становятся обычными: «1⍽990⍽₽» в прайсе, в 12 документах из 30. В 9 из этих 15 документов показ больше ничем не меняется: на вид слова те же, другими становятся перенос строки и сверка цитат (дополнено проверкой). Ещё сноски становятся текстом, экранированные `\#`, `1990\.`, `\-` превращаются в заголовок и список, кавычка в подсказке и пробел в адресе ломают ссылку. Забор кода внутри блока рвёт блок, а картинка в строке или в ссылке роняет загрузку раздела. Правка одного слова переписывает и другие строки в 17 из 29 документов. Правила канона этого не лечат: ошибки — в сериализаторе Tiptap.
- **Мост remark** (`harness/lib/remark-bridge.mjs`, 385 строк) возвращает байт в байт все 109 конструкций, 30 документов и 129 разделов. Второй круг равен первому, документ в редакторе после круга тот же. Все 108 правок человека (слово, жирный, пункт списка, ячейка) меняют ровно свою строку. Это сравнение выхода моста с ним же: потерю, которую вносит сам мост, оно не видит — посаженная в копию моста ошибка Tiptap (пробелы в ячейках) оставила эту строку зелёной. Сохранность текста агента показывают строка «мост, канон `fixed`» (107 из 109 конструкций, 30 из 30 документов) и сверка «сырой текст → канон» (дополнено проверкой).
- **«», „“, тире, «ё»**, в том числе разложенная, эмодзи и длинные строки переживают оба пути. Неразрывный пробел вне таблиц переживают оба пути, в таблицах — только мост.
- **Канон надо уточнить.** «Таблицы без выравнивания» — это только без выравнивания пробелами (`tablePipeAlign: false`). Выравнивание столбцов `:-` и `-:` держат и Tiptap 3.34 (`align` у ячейки), и doc-render. Канон — то, что отдаёт мост: сырой HTML уходит, `<br>` — перенос строки, ссылки по номеру становятся обычными, смешанный список задач делится, выделения вкладываются в одном порядке. Версия сериализатора закрепляется точно: от неё зависит канон.
- **Сверять цитаты агента по видимому тексту нужно.** Канонизация переписывает около 4 % строк агента: по исходнику находятся 480 из 498 его цитат, по видимому тексту — 497.
- **`mui-tiptap` 1.31.0** ставится с React 19.3.1, `@mui/material` 9.4.0 и Tiptap 3.34.0 без замечаний `pnpm peers check` и монтируется в jsdom. Попутно найдены две ошибки показа в `@repo/doc-render`: `<br>` склеивает слова, у сносок виден английский заголовок «Footnotes». Проверка нашла третью: подчёркнутые заголовки первого и второго уровня обходят правило уровней раздела (дополнено проверкой).

### Правки, которые оставляет человек

46 случаев: документ редактора → Markdown → канон → снова редактор. Здесь редактор сам по себе даёт формы, каких нет в тексте агента.

| Случай | `@tiptap/markdown` | Мост |
| --- | --- | --- |
| Текст абзаца начинается с `# `, `2026. `, `1. `, `- `, `+ `, строка `===` под текстом, 4 пробела в начале | после перезагрузки — заголовок, список, блок кода | `\#`, `2026\.`, `&#x20;` — абзац остаётся абзацем |

| Пробел или неразрывный пробел на краю жирного или курсива | выносится наружу | выносится наружу |
| Перенос строки в заголовке | заголовок распадается на заголовок и абзац | перенос становится пробелом |
| Пустые абзацы подряд | `&nbsp;`-абзац, второй круг другой | уходят |
| Подчёркивание (`StarterKit` по умолчанию) | `<u>` в Markdown, doc-render его не рисует | расширения нет |
| Пересекающиеся жирный и курсив | `<em>` в Markdown | `**а&#x431;_&#x432;г_**_де_` — верно |
| Кавычка в подсказке, пробел в адресе ссылки | ссылка ломается | `\"`, `<…>` |
| Таблица без строки заголовка | добавляется пустая строка заголовка | первая строка становится заголовком |
| Перенос, два абзаца или список в ячейке | `<br>` в Markdown — doc-render склеивает слова | пробел |
| Неразрывный пробел в ячейке | становится пробелом | сохраняется |

Сводка стенда ставит этим двум вставкам «=»: ссылка и жирный теряются при самой вставке, до круга, поэтому круг их не видит (дополнено проверкой). У моста после первого круга документ редактора другой в 12 случаях из 46, все — то, чего Markdown держать не может: пробелы с краёв выделений, перенос в заголовке и в ячейке, пустые абзацы, перенос в конце абзаца, строка заголовка таблицы, буквенная нумерация, признак `spread`. Второй круг равен первому во всех 46.

- Канонизация меняет 85 строк в 29 документах из 30 (исправлено проверкой). ### `mui-tiptap`

- `pnpm install` и `pnpm peers check` — «No peer dependency issues found».
- `RichTextEditor` с `StarterKit` и `Markdown` монтируется в jsdom: есть `.ProseMirror` и классы `MuiTiptap`, `getMarkdown()` отдаёт текст с неразрывными пробелами и «ёлочками».

Если рядом загрузить ESM-сборку `@tiptap/*`, получатся два `@tiptap/core`, и ProseMirror ругается «Adding different instances of a keyed plugin». ### UniqueID

Id узлов живут одну сессию редактора. Markdown их не несёт, при следующей загрузке они новые (`uid-check.mjs`: 3 id, после перезагрузки все другие). До события создания id пустые (`null`). С `element: null` они не появляются до `mount()`, а без опции `element` Tiptap сам создаёт отдельный элемент, и id появляются (исправлено проверкой).

### Попутно: показ в `@repo/doc-render`

Обе ошибки воспроизведены на `react-markdown` 10.1.0 и `remark-gfm` 4.0.1 со `skipHtml`, как в `packages/doc-render/src/document-markdown.ts`. В настоящем кабинете не проверялись. Проверка повторила обе на настоящих `DocumentMarkdown` и `rehypeDocumentRules`, скопированных из репозитория (`verify/doc-render-real.mjs`), — то же самое (дополнено проверкой).

- **`<br>` склеивает слова.** `окно.<br>Вторая` показывается как «окно.Вторая», ячейка `10:00–18:00<br>(обед…)` — как «10:00–18:00(обед…)». Агенты пишут `<br>` в ячейках таблиц, хотя инструкции просят без HTML. Канон моста превращает `<br>` в перенос строки, в ячейке — в пробел.
- **Заголовок сносок по-английски.** `remark-rehype` подписывает раздел сносок «Footnotes» и прячет подпись классом `sr-only`. Фильтр `rehypeDocumentRules` удаляет класс (у `h2` в `ATTRIBUTES` нет атрибутов), и «Footnotes» становится видимым заголовком над сносками. Ссылка «↩» остаётся без подписи. Проверено копией фильтра элементов и атрибутов (`footnote-label-check.mjs`). Лечится `remarkRehypeOptions: { footnoteLabel: 'Примечания', … }` у `react-markdown`. Настоящие правила дают заголовку id `doc-footnotes`, а оглавление вкладки «Документы» собирает `h1[id], h2[id], h3[id]` нарисованного документа (`documents-pane.tsx`), так что по коду «Footnotes» попадает и в оглавление; в кабинете не проверялось (дополнено проверкой).
- **Подчёркнутые заголовки обходят правило уровней раздела (добавлено проверкой).** `sectionMarkdownProblem` (`packages/domain/src/pages/doc.ts`) ищет только строки `#` и `##`. Раздел `Итоги месяца` + `---` или `===` она принимает, а doc-render рисует в нём `<h2>` или `<h1>` — уровни названия и разделов. Канон с `setext: false` превращает такой раздел в `## Итоги месяца`, и та же функция его отклоняет (`heading_level`). Строку текста и сразу под ней `---` агент может написать и вместо черты. Проверено `verify/section-levels.mjs` и `verify/setext-section.mjs` на настоящей функции и doc-render.

### Метод

- **Среда.** Node и jsdom, без браузера. Главные ошибки круга — пробелы в таблицах, сноски, экранирование, ссылки — в чистом JavaScript и от браузера не зависят. От браузера зависят HTML внутри Markdown, вставка и набор. Памяти и времени отчёт не мерит. Сводка, с которой сходятся таблицы отчёта, собрана из `results/*.json` свежего прогона.
- **Положительные контроли.** У путей Tiptap они есть: это сами находки. Строка моста по построению слепа к потерям самого моста, это показала посаженная ошибка. Поэтому проверка опиралась на строку «канон `fixed`», сверку «сырой текст → канон», 52 новые конструкции и 1 556 правок.
- **Пробелы корпуса.** В корпусе нет кода в ссылке или в жирном и нет подчёркнутых заголовков в разделах. Именно там нашлись две новые ошибки.
- **Мелочи.**
  - «Пробелы с краёв выделений — то, чего Markdown держать не может» — строже: может, ссылками на знаки (`&#x20;`), как мост и делает для цифры (`&#x31;`). Вынос пробела наружу — разумная норма, не потеря.
  - «Видимый текст» нормализует только `[ \t\n\r\f]`, поэтому NBSP → пробел считается сменой слов. На вид их не отличить, но меняются перенос строки и сверка цитат.

### План 88 и правила

- Предложения к §7.7 и §7.13 следуют из доводов: `@tiptap/markdown` теряет текст, мост — нет, и на новых конструкциях тоже. Ар17 и Ар18 (трёхстороннее слияние правок человека) держатся на том же свойстве — правка меняет одну строку. Это ещё один довод за мост.
- Нужно добавить: метку `code` без `excludes`, заголовки раздела 3–6 и правило для подчёркнутых, пакет для канонизатора по правилам слоёв (`doc-render-npm`, `mcp-minimal-packages`, `domain`). Подробно — пункт «Что добавить к предложениям выше».
- Точное закрепление `remark-*` и `mdast-util-*`. Каталог `pnpm-workspace.yaml` держит диапазоны `^` (`remark-gfm: ^4.0.1`), а `mdast-util-to-markdown` — транзитивная зависимость. Закрепить её можно прямой зависимостью пакета моста или `overrides`. Обновление — миграцией, как предлагает отчёт.
- Правило 10. Видимый «Footnotes» нарушает его уже сейчас. В `remarkRehypeOptions` нужен `footnoteLabel` по-русски, а заголовок не должен становиться видимым `h2` оглавления. Подписи «↩» сейчас нет вовсе: фильтр снимает `aria-label`. Если её вернуть, `footnoteBackLabel` тоже нужен по-русски.
