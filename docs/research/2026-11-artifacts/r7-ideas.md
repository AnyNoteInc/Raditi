# Артефакты: определения, типы, способы применения, риски

Исследование r7 — продуктовый разбор для раздела «Артефакты» (запрос владельца от 19.11.2026). Только чтение
репозитория, веб в этой работе не открывался (так поставлена задача). Откуда что:

- **Радити сегодня** — файлы репозитория на 19.11.2026, пути названы в тексте.
- **Другие продукты** — разведка репозитория «Возможности AI-агентов на 14.11.2026»
  (`docs/research/2026-11-agent-features/features.md`, `products.md`, у каждой строки там свой первоисточник) и
  описание инструмента Artifact в этой сессии Claude Code (19.11.2026). В вебе в этой работе не перепроверено.
- **Оценки ценности (1–5) и сложности (S/M/L)** — суждение автора, не замер. Где факт проверить не удалось — «не
  подтверждено».

## 0. Коротко

1. **Артефакт — то, над чем работают; страница — то, что показывают.** У артефакта читатели — только названные
   люди после входа в кабинет, у страницы — любой человек по ссылке без входа. Слово «страница» в артефактах не
   используется.
2. **Документ агента планов 69 и 74 — уже почти артефакт.** У него есть разделы, живая проверка `core` и версии.
   Предлагаю сделать его первым типом «Документ», а вкладку справа «Документы» — вкладкой «Артефакты». Тогда у
   клиента пять понятий вместо шести: артефакт (работаем), файл (скачиваем), страница (показываем), память и
   контекст проекта.
3. **Главный принцип устройства.** Структурные артефакты хранят данные, а рисует их доверенный код Радити. Это
   таблица, презентация, бланк, письмо, отчёт, схема, структура сайта, фирменный стиль. Свободный HTML агента —
   только в «Макете» и «Холсте». Что это даёт:
   - ручную правку без агента;
   - один вид по фирменному стилю;
   - меньше чужих скриптов;
   - обход того, что модель не видит картинок (`UNSEEN_IMAGES` в `apps/core/src/tasks/turn-instructions.ts`).
4. **Совместная правка — по блокам с номером версии блока, без CRDT.** Как `expectedVersion` у страниц (план 73,
   Дер25). Агент пишет блок, `core` проверяет его на ходу, как разделы плана 74 (`DocSections.checkLive`, 1,5 с).
   Человек правит свой блок сразу. Два агента правят разные блоки параллельно, один и тот же — по очереди.
5. **Первая волна типов** — «Документ», «Таблица», «Макет», «Холст», «Фирменный стиль». Под них нужна общая
   основа (сложность L): владение, история, доступ, комментарии, присутствие, инструменты агента, вкладка справа.
6. **Самые ценные для малого бизнеса применения:**
   - ручная правка вместе с агентом в одном объекте;
   - «Опубликовать» и «Обновить страницу» (меню по QR, которое меняется одной фразой в Telegram);
   - правка по выделению;
   - история с «Вернуть» и метками «Отправлено клиенту» и «Согласовано»;
   - шаблоны под виды бизнеса.
7. **Главные риски:**
   - секреты и значения переменных в артефактах: значения переменных проверить умеет только `core`;
   - чужие данные в общем артефакте уходят модели через агента собеседника;
   - доступ по ссылке как обход правил страниц: фишинг, бесплатный хостинг;
   - путаница «Поделиться» и «Опубликовать»;
   - визуальные типы агент делает вслепую;
   - запуск по расписанию не может войти во внешние сервисы: живой артефакт обновляется только открытым вебом.

Короткие формулы для интерфейса:

- **Артефакт** — «наработка, которую вы делаете вместе с агентом; видна только вам и тем, с кем вы поделились».
- **Страница** — «то, что видят все, у кого есть ссылка».
- **Файл** — «то, что скачивают».
- **Память** — «что агент помнит о вас».
- **Контекст** — «что вы дали проекту прочитать».

### 1.2 Как они связаны

- **Артефакт → страница.** «Опубликовать» делает из текущей версии артефакта страницу: новую, новую версию
  выбранной или страницу сайта по пути. Это та же цель публикации, что у `pages.publishFile` (план 73, Дер9).
  Дальше артефакт меняется приватно, а страница — только по новому нажатию «Обновить страницу». Карточка
  показывает «Опубликовано: v3 · есть изменения после публикации». Публикация идёт по правилам страниц:
  `checkPageContent`, значения переменных, лимиты, бесплатно. Автоматической публикации каждой правки нет:
  страница публична, поэтому выход наружу — отдельное действие.
- **Страница → артефакт.** «Править вместе с агентом» в «Страницах» делает артефакт из исходника страницы — HTML
  или Markdown (`page_contents.source`, Дер26) — связанный с ней. Публикация из него — следующая версия той же
  страницы с `expectedVersion`. Страница без артефакта живёт, как сейчас.
- **Документ агента → артефакт.**
  - Длинный документ `doc_*` становится артефактом вида «Документ»: перенос `chat_documents`, разделы — блоки.
  - Файл `.html` или `.md` агента становится артефактом автоматически — в конце хода, как сейчас файл становится
    документом во вкладке.
  - Файлами остаются только то, что скачивают: Word, Excel, PDF, картинки.
- **Файл ↔ артефакт.**
  - Импорт: `.xlsx` и `.csv` → «Таблица»; `.docx`, `.pdf`, `.md` → «Документ»; картинки → в «Фирменный стиль» или
    на «Холст».
  - Экспорт: PDF, PNG, XLSX, CSV, DOCX, HTML.
  - Файл — снимок, артефакт — живой объект.
- **Артефакт ↔ контекст проекта.** Артефакт проекта можно «закрепить в контексте». Тогда каждый чат проекта
  видит его в перечне контекста (имя, вид, размер, дата правки) и читает инструментом по блокам, по мере нужды, а
  не целиком в каждом проходе. В отличие от файла контекста, он живой: правка видна со следующего вызова.
  «Фирменный стиль» проекта закреплён всегда.
- **Артефакт ↔ память.** Память хранит факт и ссылку — «Цены — в артефакте «Прайс 2026»», — а не сам прайс. Агент
  не копирует артефакт в память. Запись памяти из прохода, где агент читал артефакт, который правили другие люди,
  — только «Предложено»: это внешний текст в смысле ПР18.
- **Запланированная задача ↔ артефакт.** Задачу можно привязать к артефакту. Каждый запуск пишет новую версию с
  меткой «Запуск задачи «…» · 24 ноября».

### 1.3 Как не спутать страницы и артефакты в интерфейсе

| Где | Артефакт | Страница |
|---|---|---|
| Главная кнопка «наружу» | «Поделиться» — люди по почте или ссылка «после входа», роли | «Опубликовать» — ссылка для всех, пароль по желанию |
| Значок на карточке | «Видно только вам» / «Доступ: 3 человека» | «Опубликована» / «С паролем» / «Снята» |
| Связь | «Есть страница: `kroshka….pages.raditi.ru/menu` · v3» | «Сделано из артефакта «Меню»» |
| История | Все версии, «Сравнить», «Вернуть» | Номер vN, хранится только последняя |
| Удаление | В корзину на 30 дней; доступы снимаются сразу | Адрес отвечает 410, корзина 30 дней |
| Раздел кабинета | «Артефакты» | «Страницы» |

Мелочь, которая путает: тег «Черновики» в «Страницах» (`pageTagLabels.pending`) означает «страница ещё не ожила», а
у артефактов «черновик» — естественное слово. Тег лучше переименовать в «Ещё не опубликованы» — так уже называется
состояние (`pageStateLabels.pending`).

### 1.4 Слова

- **«Артефакт».** Это слово владельца, и для раздела оно — значение по умолчанию. Но для владельца пекарни это
  калька айтишного «artifact»: по-русски «артефакт» — археологическая находка (правило 10 — без жаргона).
  - Варианты: «Наработки», «Заготовки».
  - Не подходят: «Материалы» (так окно проекта называет файлы контекста — «Загружайте материалы…»), «Черновики»
    (тег «Страниц»).
  - Если раздел остаётся «Артефакты», у заголовка нужна подсказка, как у «Страниц» (Дер7): «Тексты, таблицы,
    макеты и другие наработки, которые вы делаете вместе с агентом. Видны только вам и тем, с кем вы
    поделились».
- **Рейка.** Пункт рейки — 60 px, подпись — Golos Text 11 px (`application-rail.tsx`: «Расписание» заняло 65 px
  и не влезло, поэтому пункт назван «Задачи»). «Артефакты» по оценке около 58 px — влезает впритык, надо
  проверить на экране.
- **Названия типов** — ниже, по-русски, без «страницы», «дашборда», «квиза», «лендинга» и «брендбука».

## 2. Типы артефактов

**Как считать сложность.** Общая основа делается один раз, её сложность — L:

- сущность и права, история с «Вернуть», доступ по ссылке;
- комментарии, присутствие, живая проверка `core`;
- общие инструменты агента;
- вкладка справа, раздел в рейке, страница артефакта, «Опубликовать», экспорт в браузере.

Ниже сложность типа — **поверх основы**:

- **S** — использует то, что уже есть: рендер Markdown `@repo/doc-render`, изолированный фрейм страницы
  `PAGE_SANDBOX`, разделы документа.
- **M** — свой просмотр и ограниченный редактор, свои операции агента и свой экспорт.
- **L** — сложный редактор (формулы, свободная графика, ручная вёрстка слайдов), верность чужим форматам или новая
  публичная возможность.

**Ценность** — для владельца малого бизнеса: насколько часто нужно и сколько денег или времени экономит.

| 15 | Карточки товаров | Тексты, характеристики, слайды для площадок | 4 | L | 3 |

| 18 | Доска задач | Столбцы и карточки или список дел | 2 | M | 3 |

Волна 1 — то, что владелец назвал сам («текст», «html-страница или холст»), и самое частое: «Таблица» и
«Фирменный стиль», без которого холст выходит разношёрстным. Волна 2 — дешёвые шаблоны и типы поверх таблицы.
Волна 3 — новые зависимости, чужие форматы или новые обязательства.

### 2.1 «Документ»

- **Что это.** Текст по разделам в Markdown: инструкция, статья, бриф, аудит, регламент, ответы на частые вопросы.
  - Уже есть как документ агента `raditi_doc_*` — разделы, вид `page` или `text`, живая проверка `core`, vN
    (планы 69, 74).
  - Нет ручной правки, комментариев, истории содержимого (хранится только последняя версия —
    `chat_document_contents`) и доступа людям.
- **Сценарии.**
  - Пекарня: регламент открытия смены и санитарный список для новых продавцов.
  - Салон: правила записи и отмены — для администратора, для страницы на сайте и для поста.
  - Агентство: аудит сайта клиента; ссылка клиенту с ролью «Комментатор», клиент отмечает «Согласовано».
- **Агент.** Скелет → материал → по разделу → «Источники» → проверка, как сейчас. Дальше:
  - правит раздел по комментарию или выделенному отрывку;
  - сокращает и переписывает под тон «Фирменного стиля»;
  - отвечает в треде комментария.
- **Клиент руками.** Правит раздел (Markdown с просмотром, позже — простой редактор), комментирует отрывок,
  ставит метку версии.
- **Наружу.**
  - «Опубликовать» — уже есть: страница для чтения из `@repo/doc-render`.
  - «Скачать .md» — уже есть.
  - PDF — печатью браузера.
  - DOCX — файлом от агента: `python3-docx` есть в образе песочницы (`infra/sandbox/Dockerfile`).
- **Сложность: S.** Рендер, разделы и проверка есть; новое — редактор раздела и хранение истории.
- **Ценность: 5.** Нужен каждому сегменту каждую неделю. Переносом документа агента в артефакты снимается одно
  понятие.

### 2.2 «Таблица»

- **Что это.** Строки и столбцы с видами: текст, число, ₽, дата, выбор, ссылка, картинка, флажок. Сортировка,
  фильтр, группы, итоги по столбцу. Формул в первой версии нет.
- **Сценарии.**
  - Пекарня: меню и прайс с категориями. Из таблицы — страница меню, ценники на витрину и табличка с QR.
  - Ремонт: смета — работы, объём, единица, цена, итог; из строки сметы — «Бланк» предложения.
  - Магазин: каталог 200 товаров из таблицы поставщика — с чисткой названий и едиными единицами.
  - Ещё: сравнение поставщиков с источниками — это история демо главной, `landing-story.ts`: «Найди трёх
    поставщиков кофейного зерна и сравни цены». И выгрузка заявок сайта (ДС1–ДС7).
- **Агент.**
  - добавляет, меняет и удаляет строки пачками;
  - сравнивает поставщиков и конкурентов поиском и браузером, со ссылкой-источником в строке;
  - нормализует данные;
  - считает итоги кодом в песочнице, а не «в уме»;
  - разбирает приложенный `.xlsx` (`openpyxl` есть в образе) и выгрузку из браузера (`web_download`, ДС5).
- **Клиент руками.** Правит ячейку, добавляет строку, сортирует, фильтрует, прячет столбец.
- **Наружу.**
  - XLSX и CSV, печать.
  - «Опубликовать» — доверенным рендером: прайс или меню в цветах фирменного стиля, без HTML агента.
  - Источник данных для «Печатного макета», «Бланка», «Календаря» и «Отчёта».
- **Сложность: M.** Сетка с видами столбцов, операции строк, импорт и экспорт. С формулами — L.
- **Ценность: 5.** Прайс и меню — самая частая просьба владельца-одиночки (`docs/business.md`, раздел 2: «цены,
  фото, часы работы, акции»).
- **Заметки.** Заявки, клиенты, заказы — данные клиента (ДС1–ДС8). Но «Поделиться» таблицей со столбцами телефонов
  и почты — передача данных людей третьему лицу. Окно должно об этом сказать.

### 2.3 «Макет»

- **Что это.** Один самодостаточный экран HTML со скриптами: прототип, калькулятор, подбор услуги по вопросам,
  тест, конструктор заказа.
  - Сегодня это файл `.html` во вкладке «Документы»: скрипты разрешены, сеть закрыта (`PAGE_SANDBOX`,
    `connect-src 'none'` в `packages/domain/src/pages/headers.ts`).
- **Сценарии.**
  - Ремонт: калькулятор стоимости по площади и виду работ — ссылка в объявлении и в визитке.
  - Салон: «подбор процедуры» из четырёх вопросов с ответом и кнопкой «Позвонить».
  - Репетитор: тест по теме урока для ученика по ссылке. Пекарня: «соберите торт» с ценой.
- **Агент.** Пишет HTML и проверяет логику кодом в песочнице (node). Числа — цены, коэффициенты — выносит в блок
  «Настройки» (JSON), чтобы клиент менял их без агента.
- **Клиент руками.** Пробует макет, меняет числа в «Настройках» формой, комментирует, смотрит исходник.
- **Наружу.**
  - «Опубликовать» — на странице скрипты работают, сеть закрыта; QR на страницу.
  - Встроить на свой сайт нельзя: у страниц `frame-ancestors 'none'` — вопрос владельцу (§6).
- **Сложность: S.** Просмотр и изоляция есть; новое — вид исходника и форма «Настроек».
- **Ценность: 4.**

### 2.4 «Холст» (макеты сайта)

- **Что это.** Доска из кадров, как холсты Claude Code, которыми пользуется сам владелец.
  - Строка — экран: «Главная», «Услуги», «Контакты».
  - В строке — кадр компьютера (1440) и телефона (390), рядом — «Вариант А» и «Вариант Б».
  - Переключатели вида: светлый и тёмный, цвета «Фирменного стиля».
  - Комментарии, приколотые к точке кадра; голоса приглашённых.
  - Каждый кадр — «Макет» в изолированном фрейме.
- **Сценарии.**
  - Агентство: три варианта главной для клиента; клиент голосует и комментирует по ссылке.
  - Салон: новый вид сайта — до того, как собирать сайт из страниц.
  - Ремонт: посадочная под рекламу «Ремонт ванной под ключ» — компьютер и телефон, два варианта.
- **Агент.**
  - рисует кадр за вызовом;
  - держит единый стиль по «Фирменному стилю»;
  - правит по приколотым комментариям;
  - делает вариант рядом, а не поверх;
  - по «Сделать сайт по варианту Б» публикует страницы через `page_publish` с `treeId` и `path`.
- **Клиент руками.** Смотрит в размерах, комментирует точку, голосует, переставляет, прячет и переименовывает
  кадры, отмечает выбранный вариант.
- **Наружу.** PNG и PDF кадра или строки; «Сделать сайт» — сайт из страниц; ссылка «Посмотреть» людям с ролью
  «Читатель».
- **Сложность: M.** Доска с масштабом, кадры во фреймах, булавки комментариев, варианты, рендер PNG. Свободное
  рисование, как в графическом редакторе, — L, его не предлагаю.
- **Ценность: 4.** Агентствам — 5, одиночке — 3: макет ему нужен редко, нужен сразу сайт.
- **Заметки.** Модель не видит картинок — кадр рисуется вслепую.
  - Агенту нужен текстовый отчёт вёрстки: переполнение, наложения, контраст, мелкий шрифт, горизонтальная
    прокрутка на 390 px.
  - Этот отчёт может снимать Chromium в песочнице: Playwright есть в образе. Но ходу с `requirements.browser`
    навык Playwright не выдаётся (spec §20, РА1–РА7). Доступен ли Chromium из `bash` такого хода — не
    подтверждено.

### 2.5 «Фирменный стиль»

- **Что это.** Цвета, шрифты, логотип и фото, тон («на «вы», без восклицательных знаков»), слова, которых не
  говорим, примеры удачных текстов.
  - Шрифты — из набора, который встраивается в страницу: внешних шрифтов страница не грузит (`font-src`, сеть
    закрыта).
  - Один стиль на проект или на аккаунт; его читает каждый чат проекта.
- **Сценарии.**
  - Пекарня: тёплая палитра и тон для постов, меню и страниц.
  - Агентство: свой стиль на каждый клиентский проект.
  - Салон: правила фото («светлый фон, без фильтров») и подписи мастеров.
- **Агент.**
  - Собирает черновик с сайта клиента: читает CSS страницы браузером, цвета и шрифты текстом, без зрения. Или
    собирает по словам клиента.
  - Проверяет контраст цветов.
  - Применяет стиль: CSS-переменные в новых страницах (общий файл `/_files/brand.css` сайта из страниц,
    Дер34), шаблоны «Картинки», письма, презентации.
- **Клиент руками.** Выбирает цвета, грузит логотип, пишет правила тона, отмечает «так нельзя» на примерах.
- **Наружу.** Страница «Фирменный стиль» (PDF печатью), CSS-файл.
- **Сложность: M.**
- **Ценность: 4.** Сам по себе нужен редко, но поднимает качество всех визуальных типов и страниц. Стоит считать
  его особым артефактом проекта: всегда в контексте.

### 2.6 «Структура сайта» (вместо «карты сайта» — чтобы не путать с `sitemap.xml`)

- **Что это.** Дерево будущего сайта. У узла — цель, главное действие («Позвонить», «Записаться») и задание на
  текст; связь с кадром «Холста». Кнопка «Собрать сайт» превращает дерево в сайт из страниц.
- **Сценарии.**
  - Салон: главная, «Услуги» (пять), «Мастера», «Цены», «Контакты».
  - Репетитор: личный сайт — предметы, отзывы, запись.
  - Ремонт: посадочные по видам работ под объявления.
- **Агент.**
  - предлагает дерево по виду бизнеса и пишет задания узлов;
  - собирает сайт: `page_publish` с путями, ссылки от корня, стиль — по правилам «Pages and sites» в
    `turn-instructions.ts`;
  - потом обновляет страницы изменённых узлов.
- **Клиент руками.** Переставляет, переименовывает, удаляет узлы, отмечает «готово к сборке».
- **Наружу.** Сайт из страниц (по тарифу 20 / 100 / 200 сайтов, план 73, Дер36); задание для разработчика
  документом.
- **Сложность: M.** Дерево — по образцу дерева страниц плана 73, сборка — существующими инструментами.
- **Ценность: 4.** После плана 83 сайт из страниц — главный способ дать клиенту сайт.

### 2.7 «Готовые ответы»

- **Что это.** Ответы на частые вопросы и отзывы: вопрос → ответ → канал → тон. Для отзывов — таблица «отзыв →
  черновик ответа → отправлено».
- **Сценарии.**
  - Салон: ответы администратора в мессенджерах — цены, запись, подготовка к процедуре.
  - Пекарня: черновики ответов на отзывы на картах, раз в неделю.
  - Ремонт: ответы на возражения по телефону («почему дороже, чем у частника»).
- **Агент.** Пишет ответы в тоне стиля. По расписанию собирает новые публичные отзывы — в запуске без надзора
  браузер только читает, этого хватает — и пишет черновики.
- **Клиент руками.** Правит, копирует, отмечает «Отправлено».
- **Наружу.** Копирование одной кнопкой; страница вопросов и ответов.
- **Сложность: S** — шаблон «Документа» и «Таблицы».
- **Ценность: 4.**
- **Заметки.** Имена авторов отзывов — данные третьих лиц, хоть и публичные. Ответ на отзыв агент отправляет
  только по прямой просьбе и со входом клиента.

### 2.8 «Бланк» (договор, счёт, акт, смета, коммерческое предложение)

- **Что это.** Шаблон документа с полями — «Заказчик», «Адрес объекта», «Сумма», «Срок». Заполняется формой, из
  строки «Таблицы» или пачкой.
- **Сценарии.**
  - Ремонт: смета и договор подряда на каждый объект.
  - Агентство: договор, акт и счёт каждому клиенту раз в месяц.
  - Репетитор: договор с родителями ученика.
- **Агент.**
  - делает бланк из образца клиента (`.docx` читает `python-docx`) и находит поля;
  - заполняет поля из слов или таблицы, пересчитывает суммы кодом;
  - называет списком поля, которых не хватает.
- **Клиент руками.** Заполняет поля, печатает, подписывает.
- **Наружу.** PDF печатью, DOCX файлом от агента; пачка — по файлу на строку.
- **Сложность: M.**
- **Ценность: 4.**
- **Заметки.** Реквизиты — только самого клиента; документы от имени чужих организаций — отказ инструкциями. Радити
  не проверяет юридическую силу текста: так и сказать на бланке. Данные заказчиков-физлиц — персональные
  (правило 1).

### 2.9 «Календарь публикаций»

- **Что это.** Даты × площадки (ВКонтакте, канал Telegram) × темы. У записи — текст, связанная «Картинка» и
  состояние «идея → черновик → готово → опубликовано».
- **Сценарии.**
  - Пекарня: декабрь с праздниками и новинками.
  - Магазин: календарь распродаж до Нового года.
  - Салон: план к 8 Марта.
- **Агент.** Раскладывает темы по датам, пишет тексты, делает картинки. Запланированная задача каждый понедельник
  готовит черновики недели.
- **Клиент руками.** Переносит даты, правит тексты, отмечает «Опубликовано».
- **Наружу.**
  - CSV и XLSX; файл календаря `.ics` для телефона.
  - Публикация в соцсети — руками или агентом в облачном браузере по прямой просьбе и со входом клиента.
- **Сложность: M** — вид календаря поверх таблицы и связь с запланированными задачами.
- **Ценность: 4.**

### 2.10 «Картинка» (пост, история, обложка, баннер)

- **Что это.** Картинка в размере площадки: квадрат, вертикальная история, обложка сообщества, баннер сайта.
  - Собирается из шаблона: фото клиента, текст, цвета стиля; SVG или HTML, выгрузка в PNG.
  - Нейросетевой генерации фото нет: модель одна — GLM (правило 1).
- **Сценарии.**
  - Пекарня: пост о новых круассанах для ВКонтакте и канала Telegram.
  - Магазин: баннер распродажи для сайта и письма.
  - Салон: история «−20 % по вторникам».
- **Агент.** Выбирает шаблон, сокращает текст под длину, ставит фото по имени файла, делает три варианта. Видеть
  результат не может.
- **Клиент руками.** Меняет текст в полях, выбирает фото и вариант, скачивает PNG.
- **Наружу.** PNG; в «Календарь публикаций»; в Telegram файлом.
- **Сложность: M** — шаблоны и выгрузка PNG в браузере клиента (SVG → canvas).
- **Ценность: 4.** Спрос — 5. Без генерации фото и без зрения агента качество держат шаблоны.
- **Заметки.** SVG агента — только как картинка (`<img>`), не как документ: в SVG бывают скрипты. Документы плана
  67 SVG не показывают вовсе (Д5).

### 2.11 «Код для сайта»

- **Что это.** Фрагмент кода с пошаговой инструкцией, куда его вставить: счётчик, разметка организации для поиска,
  виджет записи, правка стилей конструктора сайта.
- **Сценарии.**
  - Салон: разметка организации (адрес, часы) для поисковиков.
  - Магазин: полоса акции в шапку сайта на конструкторе.
  - Репетитор: кнопка «Написать в Telegram» на сайт.
- **Агент.** Пишет код и инструкцию, проверяет синтаксис в песочнице. По прямой просьбе вставляет код через
  облачный браузер в админку со входом клиента: чат без проекта открывает любые публичные `https://`-сайты.
- **Клиент руками.** Копирует и вставляет.
- **Наружу.** «Скопировать», файл.
- **Сложность: S.** Подсветка кода в ответах есть с плана 76.
- **Ценность: 3.** После плана 83 Радити сайты клиентов сам не правит, а владельцам сайтов помогать по-прежнему
  нужно.
- **Заметки.** Ключ API в коде — отказ (правило 2).

### 2.12 «Печатный макет» (ценники, листовка, визитка, сертификат, табличка с QR)

- **Что это.** Макет в миллиметрах для обычного принтера: A4 и A5, несколько ценников на листе, визитки. QR-код
  ведёт на страницу.
- **Сценарии.**
  - Пекарня: ценники на витрину пачкой из «Таблицы» и табличка «Меню по QR» на столы.
  - Салон: подарочный сертификат.
  - Ремонт: листовка в почтовые ящики.
- **Агент.** Раскладывает по шаблону, переносит данные из таблицы, проверяет, что текст влезает в рамку.
- **Клиент руками.** Правит тексты, печатает.
- **Наружу.** PDF печатью браузера (`@media print`), PNG.
- **Сложность: M.**
- **Ценность: 3.** Офлайн-бизнесу — 4–5.

### 2.13 «Презентация»

- **Что это.** Слайды 16:9 из шаблона — заголовок, тезисы, цифры, фото, таблица; заметки докладчика; показ на весь
  экран.
- **Сценарии.**
  - Ремонт: предложение управляющей компании.
  - Пекарня: предложение корпоративного питания.
  - Агентство: предложение клиенту с примерами работ. (Репетитор — слайды урока.)
- **Агент.** Собирает слайды из контекста проекта и таблиц, держит шаблон, сокращает текст слайда, пишет заметки.
- **Клиент руками.** Переставляет слайды, правит тексты, показывает.
- **Наружу.** PDF; публикация страницей (слайды подряд). PPTX — позже, агентом: `python-pptx` в образе нет.
- **Сложность: M** (PPTX — L).
- **Ценность: 3.**

### 2.14 «Отчёт с графиками»

- **Что это.** Показатели, графики, таблицы и выводы «что изменилось». Агент описывает график данными, рисует его
  доверенный код.
- **Сценарии.**
  - Агентство: месячный отчёт клиенту из выгрузки Яндекс Метрики, которую клиент скачал сам или в облачном
    браузере со своим входом.
  - Пекарня: еженедельная сводка цен конкурентов и поставщиков с открытых сайтов.
  - Магазин: продажи недели из выгрузки CRM.
- **Агент.** Считает кодом (`python3`), пишет выводы и сравнение с прошлой версией.
- **Клиент руками.** Читает, комментирует, делится с партнёром.
- **Наружу.** PDF, страница с паролем.
- **Сложность: M.**
- **Ценность: 3.**
- **Заметки.** Запуск по расписанию идёт без надзора: браузер только читает, навыки с ключом недоступны (Зп27,
  Зп32), а сохранённого входа больше нет (план 83). Поэтому сам по себе обновляется только отчёт по открытому
  вебу и по тому, что клиент положил в артефакт.

### 2.15 «Карточки товаров»

- **Что это.** Карточки для торговых площадок и досок объявлений: название, описание, характеристики, ключевые
  слова, слайды-картинки. Выгрузка в шаблон площадки.
- **Сценарии.**
  - Магазин: 30 новых товаров из таблицы поставщика.
  - Пекарня: подарочные наборы.
  - Ремонт: объявления по видам работ.
- **Агент.**
  - пишет тексты в пределах площадки — пределы берёт из шаблона, который загрузил клиент, а не из памяти модели;
  - подбирает ключевые слова поиском;
  - делает слайды по шаблону и заполняет шаблон `.xlsx` (`openpyxl`);
  - по прямой просьбе загружает карточки в кабинет продавца через облачный браузер со входом клиента.
- **Клиент руками.** Проверяет и правит карточки, загружает их сам или поручает агенту.
- **Наружу.** XLSX по шаблону, PNG слайдов, CSV.
- **Сложность: L.** Правила и шаблоны площадок меняются, пачки по сотням товаров, слайды вслепую.
- **Ценность: 4.** Магазину — 5, остальным — 1.

### 2.16 «Анкета»

- **Что это.** Вопросы, варианты ответов, ветвление. Внутри артефакта — только проектирование и пробный проход.
- **Сценарии.**
  - Салон: анкета нового клиента.
  - Репетитор: входная проверка ученика.
  - Агентство: бриф на сайт.
- **Агент.** Составляет вопросы и логику, убирает лишние личные вопросы, проверяет ветки.
- **Клиент руками.** Правит вопросы, проходит пробно.
- **Наружу.**
  - Сбор ответов — работа страниц, отдельным планом: новая публичная запись, хранение, пределы, защита от спама,
    согласие, выгрузка. Сейчас у страниц `form-action 'none'`.
  - До того — «Макет» без отправки или документ.
- **Сложность: M**; сбор ответов — L.
- **Ценность: 3.**
- **Заметки.** Состояние здоровья (противопоказания в салоне) — особая категория персональных данных (152-ФЗ,
  ст. 10 — по памяти, юристу). Анкета ребёнка — с согласия родителя. Оператор этих данных — клиент.

### 2.17 «Письмо» (рассылка)

- **Что это.** HTML-письмо для своего сервиса рассылок: тема, строка-подсказка в списке писем, блоки, кнопка,
  текстовая версия; вид на телефоне и в тёмной теме.
- **Сценарии.**
  - Магазин: письмо к распродаже.
  - Салон: поздравление постоянным клиентам.
  - Агентство: ежемесячный дайджест клиента.
- **Агент.** Собирает письмо из блоков (табличная вёрстка, встроенные стили, ширина 600), проверяет ссылки, пишет
  текстовую версию.
- **Клиент руками.** Правит тексты блоков, смотрит на телефоне.
- **Наружу.** «Скопировать HTML» и файл `.html`; «Версия в браузере» — страницей. Радити не отправляет.
- **Сложность: M.**
- **Ценность: 2.** Малый бизнес чаще пишет во ВКонтакте и Telegram, чем рассылает письма — суждение, не замер.
- **Заметки.** Рекламное письмо — только с предварительного согласия получателя (38-ФЗ, ст. 18 — по памяти,
  юристу).

### 2.18 «Доска задач»

- **Что это.** Столбцы «Сделать / В работе / Готово» и карточки со сроками — или простой список дел с флажками.
- **Сценарии.**
  - Пекарня: открытие второй точки.
  - Салон: подготовка к ремонту зала.
  - Агентство: запуск сайта клиента.
- **Агент.** Разбивает цель на задачи и берёт на себя свои — «найти», «сравнить», «написать», — отмечая сделанное.
  Напоминает через запланированную задачу.
- **Клиент руками.** Двигает карточки, отмечает сделанное, ставит людей с доступом.
- **Наружу.** CSV, печать.
- **Сложность: M** (список дел — S).
- **Ценность: 2.** Привычные бесплатные доски есть у всех. Ценность — только в задачах, которые делает сам агент.

### 2.19 «Схема»

- **Что это.** Блоки и стрелки: процесс, путь клиента, оргструктура. Описание — текстом, рисует доверенный код.
- **Сценарии.**
  - Ремонт: заказ от звонка до сдачи объекта.
  - Салон: путь клиента от поста до повторного визита.
  - Агентство: схема работ для клиента.
- **Агент.** Пишет схему текстом, перестраивает, объясняет.
- **Клиент руками.** Переименовывает блоки, комментирует; двигать блоки руками — позже.
- **Наружу.** PNG и SVG как картинка, в документ.
- **Сложность: M.** Нужна новая зависимость рисования: сейчас блок `mermaid` показывается кодом (план 67, §4,
  п. 3).
- **Ценность: 2.**

### 2.20 «Карта идей»

- **Что это.** Тема в центре, ветки вокруг. Строится из списка с отступами.
- **Сценарии.**
  - Пекарня: идеи новогодних наборов.
  - Агентство: темы контента клиента.
  - Репетитор: план курса.
- **Агент.** Раскрывает ветку по нажатию («ещё идеи сюда»), сворачивает карту в план-документ.
- **Клиент руками.** Добавляет, удаляет и переносит ветки.
- **Наружу.** PNG, документ-план.
- **Сложность: S** поверх «Схемы»; отдельно — M.
- **Ценность: 2.**

### 2.21 «Сценарий ролика»

- **Что это.** Кадры: что в кадре, текст на экране, слова, длительность.
- **Сценарии.**
  - Пекарня: «как мы печём багет», 30 секунд.
  - Салон: «до и после».
  - Ремонт: обзор сданного объекта.
- **Агент.** Пишет сценарий под длительность и площадку, подбирает подписи.
- **Клиент руками.** Правит и снимает.
- **Наружу.** Документ, PDF.
- **Сложность: S** — шаблон «Документа».
- **Ценность: 2.**

### 2.22 Шаблоны вместо новых типов

Многие частые просьбы — не типы, а шаблоны существующих:

| Шаблон | Тип |
|---|---|
| Меню, прайс-лист | Таблица |
| Сравнение поставщиков или конкурентов с источниками | Таблица |
| Расписание занятий, график смен | Таблица |
| Учёт оплат учеников | Таблица |
| Регламент, инструкция для сотрудника | Документ |
| Бриф, политика отмены | Документ |
| Письмо поставщику | Документ |
| Контент-план на месяц | Календарь публикаций |
| Смета → предложение | Таблица + Бланк |

Шаблон стоит S и даёт клиенту главное — не начинать с пустого листа.

## 3. Сквозные способы применения

### 3.1 Сквозные истории (как это выглядит у клиента)

1. **Пекарня: меню, которое меняется одной фразой.**
   - «Таблица «Меню»» → «Опубликовать» → страница меню.
   - «Печатный макет» — табличка с QR на эту страницу на каждый стол.
   - Потом в Telegram: «поменяй цену круассана на 120 и обнови меню». Агент правит строку, публикует следующую
     версию той же страницы и отвечает ссылкой.
   - QR на столах не меняется: адрес страницы один (Ст16).
2. **Салон: посты без вечера за телефоном.**
   - «Фирменный стиль» и «Календарь публикаций» на месяц.
   - Запланированная задача каждый понедельник готовит три «Картинки» и тексты недели.
   - Владелица в Telegram выбирает варианты и отмечает «Опубликовано».
3. **Ремонт: смета → предложение → договор.**
   - «Таблица» сметы → «Бланк» предложения из неё → PDF заказчику, метка «Отправлено заказчику».
   - После разговора — правки и «Сравнить с отправленным».
   - Потом договор из того же бланка.
4. **Агентство: макет → согласование → сайт → отчёт.**
   - «Холст» с тремя вариантами главной → «Поделиться» клиенту с ролью «Комментатор» → голоса и булавки → агент
     правит по комментариям.
   - «Сделать сайт по варианту Б» → сайт из страниц.
   - Раз в месяц — «Отчёт» клиенту по той же ссылке.
5. **Магазин: из таблицы поставщика — на площадку.**
   - Приложенный `.xlsx` → «Таблица» каталога → «Карточки товаров» → XLSX по шаблону площадки.
   - По просьбе агент загружает карточки в кабинет продавца облачным браузером со входом клиента.
6. **Репетитор: сайт и тесты.**
   - «Структура сайта» → сайт из страниц; «Макет» теста по ссылке для учеников.
   - «Таблица» расписания и оплат.

### 3.2 Применения по ценности для владельца малого бизнеса

| Ранг | Применение | Ценность | Почему | Как в Радити |
|---|---|---|---|---|
| 1 | **Правка руками и агентом в одном объекте** | 5 | Цену или опечатку проще поправить самому: секунды и ноль кредитов. Агент видит правку и продолжает от неё | Правка блока человеком сразу. Агент в следующем вызове видит «изменено вами, 14:20». История правок общая |
| 2 | **«Опубликовать» и «Обновить страницу»** (+ QR) | 5 | Это и есть результат для бизнеса: меню, прайс, акция по ссылке | Цель публикации — как у `pages.publishFile`. Связь «артефакт → страница» с меткой «есть изменения после публикации». QR — доверенный рендер |
| 3 | **Правка по выделению** | 5 | «Вот это короче», «эту ячейку пересчитай», «здесь кнопку крупнее» — без объяснений, где это | Выделение (отрывок, ячейки, область кадра) уходит агенту якорем в блок. Агент меняет только этот блок (OR-79 — у 12 продуктов) |

Метки «Отправлено клиенту», «Согласовано», «Опубликовано v3». «Сравнить», «Вернуть» новой версией. У страниц возврата нет — у артефакта он есть |
| 5 | **Шаблоны по видам бизнеса и «Сделать шаблоном»** | 5 | Чистый лист — главный тормоз первого запуска; шаблон — готовый первый результат за подарочные 50 кредитов | Галерея: пекарня, салон, ремонт, магазин, репетитор, агентство. Нажатие кладёт просьбу в черновик чата, как примеры пустых «Страниц» (`keepChatDraft`, Дер6). Свой артефакт можно сделать шаблоном |
| 6 | **Экспорт и печать** | 4 | Отправить поставщику PDF, распечатать ценники, загрузить XLSX на площадку | Сначала в браузере клиента, бесплатно: печать в PDF, SVG → PNG, CSV. Сложные файлы (DOCX, XLSX по шаблону) — агентом, это проход |
| 7 | **Telegram: ссылка, файл, правка словами** | 4 | Владельцы живут в Telegram | Строка «Артефакт «…» обновлён» со ссылкой в кабинет (как страницы и документы сейчас, план 80). Файл PDF или PNG — по просьбе: файлы `/workspace/out` уже уходят документом. Правка словами — обычный ход чата |
| 8 | **Фирменный стиль ко всему новому** | 4 | Посты, страницы, письма и презентации выглядят как одна компания | Особый артефакт проекта всегда в контексте. Агент берёт из него CSS-переменные и тон. Для сайта из страниц — общий файл `/_files/brand.css` |
| 9 | **Артефакт в контексте проекта и «@» в поле** | 4 | Не повторять «возьми прайс из прошлого чата» | «Закрепить в контексте». «@» предлагает артефакты рядом с файлами проекта (крючок плана 78 `ComposerMentions`). Агенту — ссылка `artifact:<id>` и строка, что это |
| 10 | **Поделиться для согласования** | 4 | Партнёр, бухгалтер, заказчик, клиент агентства смотрят и согласуют без пересылки файлов | Роли «Читатель», «Комментатор», «Редактор». Кнопка «Согласовать» ставит метку на версию. Вход — по почте или через Яндекс одной кнопкой (`packages/auth/src/yandex-sign-in.ts`). Письмо «С вами поделились» без содержимого |
| 11 | **Живой артефакт по расписанию** | 4 | Цены конкурентов, новые отзывы, курс валют, черновики постов — каждую неделю сами | Задача привязана к артефакту, каждый запуск — новая версия с меткой. Только открытый веб и данные самого артефакта: в запуске без надзора браузер только читает, навыки с ключом закрыты (Зп27, Зп32) |
| 12 | **Пачка из таблицы** | 4 | 10 предложений, 50 ценников, 30 карточек за раз | «Бланк», «Печатный макет» или «Карточки» из выбранных строк «Таблицы». Пачка — один проход со строкой «сделано N из M» |
| 13 | **«Сделать сайт по этому макету»** | 4 | Из согласованного макета — сразу работающий сайт, без разработчика | Кадры «Холста» или узлы «Структуры сайта» → `page_publish` с путями. Связи «кадр → страница» сохраняются для следующих обновлений |
| 14 | **Комментарии, на которые отвечает агент** | 3 | Удобно для правок «по месту» и для чужих замечаний | «Попросить агента» в треде — проход в чате артефакта. Агент отвечает в треде и закрывает сделанное. Зовут только владелец и редакторы — за свои кредиты |
| 15 | **«Сохранить как артефакт»** из ответа, файла, страницы, сайта | 3 | Хорошее не теряется в ленте | Кнопка у ответа агента: список → «Документ», таблица Markdown → «Таблица». Импорт `.xlsx`, `.docx`. «Перенести тексты сайта» — агент читает открытый сайт браузером |
| 16 | **Проверка вторым агентом** | 3 | Опечатки, арифметика сметы, расхождение с фирменным стилем, рискованные обещания в предложении | «Проверить» — проход только с правом комментировать, без правок |
| 17 | **Варианты и голосование** | 3 (агентствам 4) | Выбрать из двух-трёх, не описывая словами | Группа кадров «Вариант А/Б/В», голоса приглашённых, «Выбрать вариант» |
| 18 | **Несколько чатов и агентов над одним артефактом, присутствие** | 3 | Сама по себе клиенту не видна, но без неё ломаются истории 2, 3 и 11 | Блоки с версиями. «Агент чата «Цены к Новому году» пишет строку 12». Два агента — разные блоки параллельно |
| 19 | **Данные из сервисов клиента через браузер** | 3 | Выгрузки CRM, заявок, заказов, Метрики | `web_download` (ДС4, ДС5) в чате со входом клиента → «Таблица» или «Отчёт». В запуске по расписанию — нет |

| 21 | **Поиск по артефактам** | 3 | Через месяц их десятки | По названию и тексту в разделе и в «@» |
| 22 | **Голосом** | 2 | «Поменяй цену» на ходу | Диктовка поля уже есть (SpeechKit, план 77), поле «Попросить агента» в артефакте — то же |
| 23 | **Ремикс чужого артефакта** | 2 | Агентство дарит клиенту шаблон | «Сделать копию себе» у артефакта с доступом: копия без истории, комментариев и доступов |
| 24 | **Кредиты артефакта** | 2 | Понять, сколько стоил отчёт | «На этот артефакт ушло N кредитов» по проходам, которые его меняли |

Почему не выше «совместная работа нескольких агентов»: владелец просил её прямо, и она нужна. Но клиенту она видна
только через истории 2–4 и 11. Для малого бизнеса ценность — в результате, а не в числе агентов.

## 4. Риски

### 4.1 Правило 1 — содержимое артефакта идёт модели

- **Когда идёт.** Каждый раз, когда агент читает артефакт. Гейт 152-ФЗ держится по классу данных пространства, в
  котором идёт ход (`issue`, `cross_border_clearances`).
- **Общий артефакт.** Артефакт владельца A читает агент собеседника B. Значит, данные A обрабатывает ход B, под
  его пространством и его гейтом.
  - Юридически передачу решил A, когда поделился.
  - Технически это новый путь между пространствами: сейчас каждый ход видит только своё пространство (Ст20 — чужое
    неотличимо от отсутствующего).
  - Окно «Поделиться» должно сказать: «Агенты тех, кому вы дали доступ, тоже смогут читать артефакт».
- **После отзыва доступа.** Что агент B уже прочитал, остаётся в его чатах и зашифрованных снимках сессии. Отзыв
  этого не стирает, и это тоже сказать в окне.
- **Данные людей.** Заявки, клиенты, отзывы, ученики — данные клиента (ДС1–ДС8). Их передача собеседнику —
  решение клиента как оператора. Таблица со столбцами телефонов и почты получает предупреждение при «Поделиться».
  Особые категории (здоровье в анкете салона) — отдельное предупреждение, юристу.
- **Telegram.** Исключение Т1 (план 80) покрывает задания, файлы и ответы чата. По умолчанию артефакт уходит
  ссылкой в кабинет; превью картинкой или файлом — только по просьбе.
- **Внешние офисные сервисы.** Выгрузки в Google Slides и подобные — нет, только скачивание файла.

### 4.2 Правило 2 — секреты в артефакте

- **Где появятся.** Клиент сам впишет пароль в таблицу «Доступы». Агент может вписать значение переменной в «Код
  для сайта» или в документ. Соавтор может вставить чужой токен.
- **Проверить значения умеет только `core`.** Значения переменных пространства web пишет в Vault и обратно не
  читает (правило 2, политика `core-workspace-env`). Поэтому:
  - **правка агента** пишется «не проверенной», и `core` проверяет её на ходу тем же сканером, что разделы
    документа: ключи хода, значения переменных, известные формы секретов (план 74, Д2). Другим людям блок виден
    после проверки;
  - **правка человека** проверяется на известные формы сразу (`secretInContent`, ПР8), а на значения переменных
    — асинхронно в `core`. Найденное прячется от агентов и от других людей, с подсказкой «Похоже на пароль или
    ключ — сохраните его в «Настройки → Переменные»»;
  - **история** хранит прежние версии. Найденный секрет вычищается и из них, иначе «Вернуть» вернёт его;
  - **«Опубликовать», экспорт и «Поделиться»** проходят ту же проверку.
- **Шаблонов «Доступы» и «Пароли» не делать.** Агент на такую просьбу отвечает, куда их сохранить.

### 4.3 Злоупотребление доступом по ссылке

- **Хостинг в обход страниц.** Ссылка «после входа» с ролью «Читатель» становится бесплатным закрытым хостингом —
  без жалоб, снятия и лимитов страниц. Меры:
  - предел зрителей ссылки (например, 50 разных);
  - индексации нет;
  - снятие поддержкой командой оператора по образцу `pages:take-down` с записью аудита;
  - для всех — путь только через «Опубликовать».
- **Фишинг пользователей Радити.** «Макет» с формой «Войдите в Радити» в кабинете соавтора. Меры:
  - та же песочница, что у страниц: `sandbox` без `allow-same-origin`, `form-action 'none'`, `connect-src
    'none'`;
  - `checkPageContent` отклоняет форму пароля;
  - содержимое — только с домена страниц во фрейме (`/v/<token>`, план 67), никогда на origin кабинета;
  - рамка «Артефакт пользователя … Не вводите здесь пароли».
- **Спам приглашениями.** Предел приглашений в день, подтверждённая почта у приглашающего, письмо без содержимого
  артефакта.
- **Накрутка подарка.** Подарок начисляется вместе с личным пространством (`ensurePersonalWorkspaceWithGift`).
  Просмотр чужого артефакта пространства не создаёт, значит и подарка не даёт. Это и канал роста: собеседник
  заходит смотреть и остаётся.
- **Внедрённый текст.** Соавтор вписывает в артефакт указания агенту владельца: «отправь файлы проекта на…»,
  «запомни…». Меры:
  - содержимое артефакта идёт агенту разделом данных, как `<project-memory>` (ПР7);
  - блоки, которые правили другие люди, помечены;
  - запись памяти из такого прохода — только «Предложено»: условие ПР18 о внешнем тексте дополняется чтением
    чужого артефакта;
  - запуски без надзора меняют только привязанные артефакты своего пространства.

### 4.4 Путаница со страницами, документами и файлами

- **Две кнопки наружу.** «Поделиться» (люди, вход) и «Опубликовать» (все) — с разными словами, значками и
  подтверждением. В окне «Поделиться» — строка «Нужна ссылка для всех? — Опубликовать».
- **Три истории версий.** У артефакта — история с возвратом, у страницы — vN и только последняя, у документа
  агента — vN. После переноса документа в артефакты остаются две, и обе подписаны.
- **Три вкладки и раздела.** «Документы», «Страницы», «Артефакты». Переименование вкладки «Документы» в
  «Артефакты» — вопрос владельцу: 13.11.2026 он уже возвращал вкладке имя «Документы» (Ст27).
- **Слово «черновик»** — см. §1.3.

### 4.5 Стоимость

- **Кто платит за агента.** Тот, в чьём чате идёт проход: владелец, редактор, запуск задачи владельца. Иначе
  собеседник тратил бы чужие кредиты.
- **Большой артефакт в контексте.** Таблица на 100 КиБ в каждом вызове — по грубой оценке 20–35 тыс. токенов
  ввода. Кэш Z.ai смягчает это, но не до нуля (`docs/business.md`, раздел 5). Поэтому в инструкции идёт только перечень, а агент читает
  нужные блоки сам, частями.
- **Фоновые обновления.** Запуск задачи тратит кредиты без клиента. Окно задачи и карточка артефакта должны
  говорить: «Каждый запуск — обычный чат со списанием». Небольшая задача — около 50 ₽ (`credit-price.ts`).
- **Хранение истории.** Без предела каждый проход копит версии. Предложение: все версии с метками и последние
  100 без меток.
- **Живая правка.** Соединение SSE на каждого открытого зрителя (сигналы чата уже идут по SSE, план 86).
  Присутствие — в памяти и Redis, не в базе.
- **Экспорт на сервере.** Рендер Chromium — это отдельная изолированная служба (у `apps/browser` он есть, но для
  сессий). Поэтому сначала экспорт в браузере клиента.
- **Разработка.** Каждый редактор — отдельный продукт: таблица, слайды, холст. Доверенный рендер и правка блоками
  вместо визуальных редакторов, волны, минимум новых зависимостей.

### 4.6 Совместная правка

- **Что ломается.** Потерянные правки, агент перезаписал руку клиента, фоновая задача испортила согласованную
  версию, два агента пишут одно.
- **Меры.**
  - блоки с `expectedRevision`;
  - блок, который правит человек, «занят» на несколько секунд, и агент получает отказ «клиент сейчас правит этот
    блок»;
  - метка «Согласовано» закрепляет версию, «Сравнить» показывает, что изменилось после неё;
  - фоновая задача не трогает артефакт, который сейчас открыт на правку.
- **Без CRDT** — сознательно: блочные правки агентов и людей нечасты, а CRDT добавляет зависимость и сложность
  проверки правила 2. Проверять нужно целый блок, а не символ.

### 4.7 Модель не видит картинок

«Холст», «Картинка», «Печатный макет», «Карточки товаров» агент делает вслепую (`UNSEEN_IMAGES`). Меры:

- шаблоны платформы для визуальных типов;
- текстовый отчёт вёрстки (переполнение, контраст, размеры);
- булавки комментариев клиента как главный канал обратной связи;
- честные тексты: «Посмотрите и отметьте, что поправить».

Если модель позже начнёт видеть картинки, ценность визуальных типов вырастет первой.

### 4.8 Юридические и репутационные

- **Бланки.** Договоры, счета, акты — инструмент клиента, а не юридическая консультация. Документы от имени чужих
  организаций и под чужой маркой — отказ, как у инструмента Artifact этой сессии.
- **Письма** — согласие на рекламу (38-ФЗ, ст. 18, юристу).
- **Анкеты** — особые категории данных и данные детей.
- **Шрифты** — только встроенный свободный набор.
- **«Сделай как у конкурента»** — стиль, а не копия текстов и фото.

### 4.9 Правило 10 и телефон

- **Слова.** «Артефакт» — жаргон (§1.4). «Дашборд», «квиз», «лендинг», «брендбук» в интерфейсе не пишутся.
- **Телефон.** «Холст» и «Таблица» на телефоне — просмотр, комментарий и правка ячейки или текста. Расстановка
  кадров — только от `lg`.
- **Доступность.** Клавиатура и экранный диктор — как у вкладок плана 59; axe в e2e уже ловит нарушения.

## 5. Что из этого следует для устройства (заметки для плана)

- **Владение.** Таблица `artifacts`:
  - `workspace_id` (личное пространство владельца), `owner_user_id`;
  - `project_id NULL` — только проект владельца, ПР1;
  - `kind`, `title`, `state` (`active`, `trashed`, `purged`), `revision`;
  - `created_in_task_id` — история «создано в чате», как `pages.task_id`.
- **Доступ.** Строки `artifact_shares`: человек (`user_id` или почта приглашения) и роль. Ссылка доступа —
  выключена по умолчанию, хранится только хеш её токена, открывает только после входа и даёт роль ссылки.
  - **Роли:** владелец; «Редактор» — правит руками и своими агентами; «Комментатор» — комментарии, голоса,
    «Согласовать»; «Читатель».
  - **Агенту в чате владельца нет** доступа, ссылок, удаления насовсем и снятия публикации. Удаление — в корзину с
    `confirmedByClient`, как `page_delete` (Дер27).
- **Блоки** — единица правки: раздел, строка (и схема столбцов), кадр, слайд, поле бланка, узел, запись
  календаря. У блока — `revision`, автор последней правки (человек, агент чата, запуск задачи), состояние
  проверки.
- **Правка агента — сразу, а не в конце хода.** Артефакт приватен и обратим историей. Поэтому запись блока
  видна, как только `core` её проверил (как разделы плана 74). Публикация наружу остаётся по правилам страниц: в
  конце хода, через `PageChanges`.
- **Инструменты агента — семейство `artifacts`, имена у провайдера `raditi_artifact_*`.**
  - Общие: `artifact_list`, `artifact_read` (по блокам, частями, с `revision`), `artifact_create` (вид,
    название, проект, шаблон).
  - Правка блоков: `artifact_write` (блок целиком, `expectedRevision`), `artifact_edit` (поиск-замена в блоке с
    одним совпадением, как `page_edit`), `artifact_insert`, `artifact_move`, `artifact_remove`.
  - Таблица: `artifact_rows` (пачка строк: добавить, изменить, удалить).
  - Комментарии: `artifact_comments`, `artifact_comment_reply`, `artifact_comment_resolve`.
  - Прочее: `artifact_label` (метка версии), `artifact_publish` (страницей, по правилам `page_publish`),
    `artifact_export` (файл в чат).
  - Отказы — результатом `isError`, как у страниц: `ARTIFACT_NOT_FOUND` и для чужого,
    `ARTIFACT_BLOCK_CHANGED`, `ARTIFACT_BLOCK_BUSY`, `ARTIFACT_FORBIDDEN`, `ARTIFACT_CONTENT_REFUSED`.
- **Запуск без надзора** пишет только в артефакты, привязанные к его задаче: новую версию с меткой. Доступ,
  публикация и удаление ему закрыты — то же правило, что Зп32 для страниц.
- **Где видно.**
  - вкладка «Артефакты» справа вместо «Документов» (`dialogTools` в `apps/web/src/components/chat/dialog-tools.ts`);
    сама открывается, когда агент начал артефакт при открытом чате, по правилу Д4 и Д5 планов 67 и 74;
  - раздел в рейке;
  - страница `/artifacts/<id>` — «пространство артефакта»: артефакт крупно, сбоку чат артефакта, комментарии,
    присутствие и история;
  - в проекте — вкладка «Артефакты» рядом с «Чатами проекта» и «Закреплённые» в «Контексте». Колонка проекта
    остаётся из четырёх строк, «ровно как у Claude» (ПР6);
  - «@» в поле.
- **Деньги.** Хранение, ручная правка и экспорт в браузере — бесплатно. Проходы агента — кредиты того, чей чат.
  Публикация — бесплатно по правилам страниц, в пределах сайтов тарифа.
- **Пределы (предложение).** Блок — 32 КиБ, как раздел документа. Текст артефакта — 2 МиБ, как страница. Файлы
  артефакта — до 50 МиБ, как сайт из страниц. Людей на артефакт — 50. Зрителей ссылки — 50. История — все с
  метками и последние 100 без меток.
