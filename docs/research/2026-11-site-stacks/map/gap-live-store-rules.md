## 1. Главное

Три ответа требуют решения владельца, потому что откатов здесь нет. Предел 20 — инженерная задача, решения не требует.

1. **Цена. Запрета сейчас нет ни в одном правиле, и путь уже открыт.** Б1 пропускает любую правку через админку, список правила 4 цену не называет, а список товаров WooCommerce проверен тестом как открытый (`packages/site-adapters/src/wordpress-browser-task.test.ts:110`). Закрыты только заказы (`packages/site-adapters/src/wordpress-mcp-policy.ts:186-189`). При этом `docs/spec.md:91` и `docs/business.md:80,82` называют цены типовой просьбой. Значит, вопрос не «разрешить ли», а «как закрыть уже открытое». Рекомендация: торговые поля закрыты агенту до одобрения со значениями, карточка товара открыта. Цену пока вписывает клиент через «Взять управление».
2. **Редактор страниц Битрикса — не выбор из двух.** Как записано в `bitrix.md:395`, открывать нельзя: модель прочитает `/bitrix/.settings.php` с паролем базы, потому что у администратора проверка файлов всегда истинна (`B/main/classes/general/user.php:4898-4901`). Закрывать целиком тоже дорого: телефон и часы работы в шаблоне вендора лежат именно в таких файлах. Есть третий вариант: только проект без файлов, только разрешённые пути, запрос без `<?`. На шаблонах вендора это 34 страницы из 65 [з]. У проекта с файлами страницы идут обычным путём через предпросмотр: правка в браузере ломает `main`.
3. **Предел 20 надо считать по запросу записи, а не по кнопке.** На OpenCart 3 кнопка «Сохранить» в дереве страницы не имеет имени [з]. У Битрикса одно групповое действие меняет всю выборку без списка ID [к]. Групповые действия агенту закрыты всегда и в счёт не идут: их нечем посчитать. Отказ на AJAX-запись сейчас вообще не доходит до агента (`packages/browser-providers/src/cloud/cloud-browser.ts:441`).
4. **Заказы.** Правило твёрдое, текстов нет. Инструкция хода запрещает читать данные покупателей, но не говорит, что ответить (`apps/core/src/tasks/turn-instructions.ts:289`). Тексты для этих просьб — раздел 6. Клиента они ведут в его обычный браузер: политика закрывает заказы и ему (план 57, Б21).
5. **Правило 9 буквально о деньгах платформы, но ловушка на сайте настоящая.** OpenCart приводит цену через `(float)` без проверки: «1 990,00» становится 1 рублём на живой витрине [к, приведение типа — з]. Проверку формата дешевле всего сделать сразу, при любом решении по цене.

### 2.2 Почему цена не просто контент

- **Следствия не отменить правкой.** Обзор Президиума ВС от 18.10.2023, п. 3: заказ по ошибочной цене — заключённый договор, покупатель не обязан распознавать ошибку; п. 4: оговорка продавца о праве аннулировать заказ незаконна ([КонсультантПлюс](https://www.consultant.ru/legalnews/23607/); это пересказ, не заключение юриста). Текст вернуть можно, принятый заказ нет.
- **Истории цены нет.** Поиск по именам `price_history`, `history_price`, `price_log` в моделях OpenCart, ocStore, JoomShopping и miniShop2 пуст; `b_catalog_price` держит текущую цену [к]. Откатывать не из чего.
- **Платформа цену не видит.** `browserCheckpointKinds = ['post']` (`packages/domain/src/browser/checkpoint.ts:19`), в проверенном объекте нет поля цены (`checkpoint.ts:84-96`). Лента не покажет «было → стало», пока это не добавлено.
- **Прецедент.** Shopify Sidekick не трогает живой магазин, пока человек не проверит черновик и не опубликует его, в наборе не больше 50 изменений, а опубликованное автоматически не отменяется ([Shopify](https://help.shopify.com/en/manual/ai-powered-tools/sidekick/help-and-guidance)).

## 3. Страницы-файлы Битрикса

### 3.1 Что на самом деле делает редактор

- `fileman_html_edit.php` пишет файл целиком: `$prolog.$filesrc.$epilog` через `SaveFileContent` (`B/fileman/admin/fileman_html_edit.php:263,284`). Заголовок экранируется `EscapePHPString` (`B/main/admin_tools.php:387`), через него PHP не вписать.
- Ограничение PHP в редакторе есть, но не для администратора. Режим `fm_lpa` включается только у пользователя без `edit_php` (`fileman_html_edit.php:145`), а `edit_php` — это «Изменение PHP-кода» (`B/main/lang/ru/admin/operation_description.php:14,34`). Браузер задачи работает от имени клиента, а клиент обычно администратор [п].
- Чтение опаснее записи. `CanDoFileOperation` у администратора сразу истинна, проверка `IsConfigFile` идёт только для тех, у кого нет `edit_php` (`B/main/classes/general/user.php:4898-4910`, `B/main/tools.php:3028-3035`). Значит, `fileman_html_edit.php?path=/bitrix/.settings.php` покажет конфигурацию с паролем базы (`fileman_html_edit.php:184,397-398`) [к]. Скрытие значений работает для полей пароля, а не для текста редактора (`packages/browser-providers/src/cloud/secret-fields.ts`). Это правило 2, а не только правило 3.
- Отмены в админке нет. `CUndo` вызывается из публичных диалогов (`B/main/public/file_edit.php:305-306`), привязан к пользователю и живёт сутки (`B/main/classes/general/undo.php:178-180`).
- Истории нет: только строка журнала `FILE_EDIT` без содержимого (`fileman_html_edit.php:303-322`).

### 3.2 Что страница значит для правил

**Б1 и новая редакция правила 3 расходятся.** Б1 называет кодом «тему, плагины, сборку, выкладку», текст страницы туда не входит. Новая редакция говорит: «Файлы, код и медиа сайта агент меняет только в рабочей копии и предпросмотре» (`61-chats-first.md:1152`). Страница «О компании» — контент по смыслу и файл по форме, и формулировка правила должна выбрать одно.

**Инвариант `main`.** Правило 3: `main` всегда равен установленной версии. Записи WordPress в браузере идут в базу и его не задевают. Страница Битрикса лежит в дереве и в репозитории (`map/adapter-contract.md:105`). Правка в браузере оставит прод отличным от `main`, а сверка выпуска ловит расхождение только на файлах этого выпуска (`docs/spec.md:1270`). Предпросмотр строится из `main` и покажет старую страницу как актуальную. Следующий выпуск этого файла получит отказ. Поэтому у проекта с файлами браузер по страницам закрыт независимо от оценки риска.

| Битрикс, «для всех» | `action_target=selected` даёт список ID из одной пустой строки, затем сервер сам выбирает все строки фильтра. ID в запросе нет | `B/main/interface/admin_list.php:399-447`, `B/iblock/admin/iblock_list_admin.php:2171-2179` |

| Битрикс, цена в строке | `CATALOG_PRICE[...]` на странице списка, без редактора | `B/iblock/admin/iblock_list_admin.php:1877` |
| Joomla, пакетная обработка | Задача `article.batch`, в единственном числе. Закрытие по `articles.*` её пропустит | `J5/administrator/components/com_content/tmpl/articles/default_batch_body.php:65` |
| miniShop2, таблица | Ячейка сохраняется сама, кнопки нет вообще | `MS2/assets/components/minishop2/js/mgr/category/product.grid.js:17-18` |

Есть и обратная дыра, общая для всех: отказ `route.abort` на AJAX-запись агенту не сообщается. `refused` ставится только для навигации главного кадра (`cloud-browser.ts:441`), остальное `#run` считает успехом (`:725-729`). На OpenCart 4.1 и MODX сохранение идёт через AJAX, поэтому агент увидит успешный клик и ничего больше.

### 4.2 Что сделать

1. **Запись агента — только из редактора одного объекта.** Разрешённый список пар «адрес + действие»; любой другой запрос с телом для агента отказ. Групповые действия, правка в строке, быстрые действия списка закрыты всегда. Так уже у WordPress: `bulk_edit` и `inline-save` (`wordpress-browser-task.ts:290-297`). Закрытое не считается: считать его нечем.
2. **Счёт — по запросу.** Новый чистый метод адаптера, условно `browserWriteOf(request)`, отвечает: запись объекта с такой ссылкой, новый объект, служебное или неизвестно. Worker проверяет `#overChangeLimit` перед `route.continue()`. Состояние лежит в памяти, очередь действий ждать не надо. Неизвестное у новых стеков — отказ.
3. **Кнопка остаётся подсказкой** для барьера дубликатов там, где имя есть. Б22 тоже выигрывает: неясный исход виден по запросу, а не по адресу.
4. **Отказ записи доходит до агента.** Worker запоминает отказанную запись и отвечает на текущий инструмент `BROWSER_ACTION_DENIED`.
5. **Запись с массовым следствием закрыта как массовая.** Один объект, но следствие на весь каталог: `catalog/option`, `catalog/attribute*`, `catalog/filter*` из `browser-mcp.md:232` и `com_fields` из `:230`. Сохранение основного товара OpenCart 4.1 меняет варианты, и заранее по запросу этого не видно: остаётся известным пределом с записью в spec, как пределы политики WordPress (`docs/spec.md:1335`).
6. **Для агента OpenCart 3 нужно имя кнопки.** Без него путеводитель описывает «первую безымянную кнопку». Простейшее средство — скрипт инициализации, копирующий `data-original-title` в `aria-label` (проверить на настоящем сайте [п]).

Оценка общего механизма: 300–500 строк и тесты, один раз. WordPress можно перевести вторым шагом.

## 6. Что отвечать на просьбы о заказах

Сейчас агент знает запрет, но не ответ. `BROWSER_ACTION_DENIED` говорит только «не разрешено для этой задачи» (`packages/domain/src/browser/tools.ts:318-321`), путеводитель WordPress велит сообщить клиенту и не искать обход (`wordpress-browser-task.ts:832`), окно браузера пишет «На эту страницу агенту и вам переходить нельзя.» (`apps/web/src/components/chat/chat-texts.ts:520`). `opencart.md:806` прав: владелец магазина спрашивает об этом часто.

Принципы: сначала что я не могу, затем почему одной фразой, затем куда идти и что могу вместо этого. Без слов «персональные данные», «политика», «админка» (правило 10). Клиента отправлять в обычный браузер: «Взять управление» здесь не поможет, а совет открыть другой чат увёл бы на путь без защиты (`map/gap-plan-61-not-accounted.md`, §5). Название раздела подставляет `browserGuide()` адаптера. Сверено по языковым файлам: OpenCart «Продажи → Заказы» (`opencart/ocstore-3.0.3.7/upload/admin/language/ru-ru/common/column_left.php:55,87`), Битрикс «Заказы» (`B/sale/lang/ru/admin/menu.php:2`), miniShop2 «Заказы» (`MS2/core/components/minishop2/lexicon/ru/default.inc.php:148`).

| Просьба | Ответ |
| --- | --- |
| «Сколько заказов за неделю?», «Покажи заказы» | Заказы и покупателей я не вижу: их данные в Радити не попадают. Посмотреть их можете вы в панели управления сайтом, в обычном браузере: раздел «Продажи → Заказы». Если нужно что-то поменять на самом сайте, напишите что. |

| «Напиши покупателю», «Выгрузи клиентов», «Сделай рассылку» | Покупателям я не пишу и их контакты не вижу. Могу подготовить текст письма здесь, в чате, а отправите его вы сами. |
| «Сделай скидку 10% на всё», «Добавь промокод» | Скидки на весь магазин и промокоды я не настраиваю: такая правка сразу меняет цены для всех покупателей. Вы можете настроить их в панели управления сайтом. Могу подготовить баннер или страницу об акции. |

Отчёт о числах («выручка», «сколько заказов») можно сделать позже: если считать доверенным чтением и отдавать только числа, данных людей он не передаёт. Такого инструмента нет, и в первый выпуск он не нужен.

Нужны два маленьких изменения кода. В `BROWSER_RULES` добавить абзац об этих ответах. В `BrowserTaskPolicy` добавить причину отказа: закрытый экран и неизвестный экран разрешённого списка говорят клиенту разное, а `requestDenied` отвечает только «да» или «нет». «Эта часть сайта мне пока недоступна» честнее, чем ссылка на защиту данных.

## 7. Правки к правилам (проект текста)

**Правило 3, к исключению Б1.** «Страница-файл — файл сайта: в проекте с файлами она идёт только через предпросмотр и `/release`, в браузере не меняется. В проекте без файлов [по ответу на вопрос 2] агент меняет только её текст; адаптер не пропускает запись кода и чтение файлов вне страниц».

**Правило 4, к перечню.** «цены, скидки и остатки на работающем магазине; пока `request_approval` нет, эти поля агенту закрыты, клиент у управления меняет их сам». К Б34: «предел считается по запросам записи; групповые действия и правка в строке агенту закрыты и в предел не входят».

**Правило 9, дополнение.** «Цены сайта клиента платформа читает и показывает строкой, как их хранит сайт, с валютой, без приведения к `number`. Агент записывает их только в формате стека: запрос с другим форматом отклоняется. Процент и формула считаются Decimal с HALF_UP, а не моделью, и показываются как „было → стало“».

Основание последнего — проверка [з] на `php:8.3`: `(float)"1 990,00"` даёт 1, `(float)"1990,50"` даёт 1990.

| Стек | Как принимает цену | «1 990,00» |
| --- | --- | --- |
| OpenCart 3, 4, ocStore | `(float)$data['price']`, проверки нет (`OC3/admin/model/catalog/product.php:143`, `OC4/admin/model/catalog/product.php:246`) | 1 |
| JoomShopping | запятая в точку, затем первое число (`JS/site/Helper/Helper.php:705-710`) | 1 |
| miniShop2 | `(float)` (`MS2/core/components/minishop2/model/minishop2/msproductdata.class.php:28`) | 1 |
| Битрикс, форма | убирает пробелы и запятую (`B/catalog/admin/templates/product_edit_action.php:633`) | 1990 |
| Битрикс, список | только запятая (`B/iblock/admin/iblock_list_admin.php:2037,2042`) | 1 |

Проверка формата — чистая функция политики, несколько строк на стек. Её стоит делать при любом ответе владельца, и для WooCommerce тоже.

## 9. Вопросы владельцу

1. **Может ли агент менять цену, скидку и остаток на работающем магазине?** Предлагаю: нет, пока нет одобрения со значениями; клиент вписывает цену сам через «Взять управление»; это относится и к WooCommerce, где путь открыт сейчас. Другие варианты: закрыть карточку целиком или разрешить поштучно без жёсткой границы, принимая риск ошибочной цены (раздел 2.5).
2. **Продаём ли проект Битрикса без доступа к файлам?** Если да, предлагаю узкий редактор: только текстовые страницы, без кода, без отката. Если нет, редактор страниц закрыт, страницы идут через предпросмотр (раздел 3.4). Правку браузером у проекта с файлами предлагаю запретить в обоих случаях.
3. **Снятие товара с продажи агентом по явной просьбе.** Предлагаю да: обратимо и заменяет удаление там, где нет корзины.
4. **Тексты о заказах (раздел 6).** Предлагаю принять как есть, после вычитки владельцем. Закрытые экраны в браузере платформы остаются закрытыми и для клиента (Б21).
5. **К юристу вместе с гейтом 152-ФЗ.** Нужно ли в оферте сказать клиенту, что правки на работающем магазине идут без отката и что ответственность перед покупателем за ошибочную цену остаётся на нём как на продавце? Значения по умолчанию нет.
