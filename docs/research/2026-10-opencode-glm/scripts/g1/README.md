# Скрипты разведки G1 (05.10.2026)

Стенд, которым получены наблюдения отчёта [docs/plan/40-opencode-spike.md](../../../../plan/40-opencode-spike.md): настоящий OpenCode CLI 1.18.34 в контейнере с монтированиями песочницы и пределами стенда супервизора (1 vCPU, 1024 МиБ, 128 процессов), под `runc` и под `runsc`. Провайдера изображает сценарный фейк в соседнем контейнере: ключа плана нет, к `api.z.ai` никто не ходит. Ключ хода и токен MCP — синтетические, той же формы, что выдаёт `core`; фейк узнаёт их по SHA-256 и значений не хранит.

## Запуск

Нужны два демона Docker: обычный (`runc`) и демон Linux-ВМ с `runsc`. В обоих должен быть базовый образ песочницы `raditi-p5verify-sandbox:local`. Из сети берётся одно: пакет `opencode-ai` 1.18.34 и пакет его исполняемого файла для архитектуры образа — при сборке.

```
export SPIKE_DOCKER_RUNC=unix://<сокет Docker>
export SPIKE_DOCKER_RUNSC=unix://<сокет Docker ВМ с runsc>
export SPIKE_OUT=<каталог вне репозитория>

DOCKER_HOST=$SPIKE_DOCKER_RUNC docker build -t raditi-oc-spike:1.18.34 image
DOCKER_HOST=$SPIKE_DOCKER_RUNC docker save raditi-oc-spike:1.18.34 | DOCKER_HOST=$SPIKE_DOCKER_RUNSC docker load

node spike.mjs runc p1 p1crash p2 p2ports p3 p4 p6 p7 p7order
node spike.mjs runsc p1 p1crash p2 p2ports p3 p4 p6 p7 p7order
mkdir -p "$SPIKE_OUT/strings"
for name in overflow crash thinking deny tables; do
  DOCKER_HOST=$SPIKE_DOCKER_RUNC docker run --rm --network none -v "$PWD":/spike:ro --entrypoint node raditi-oc-spike:1.18.34 /spike/strings.mjs $name > "$SPIKE_OUT/strings/$name.txt"
done
node collect.mjs
node spike.mjs runc down && node spike.mjs runsc down
```

Каждый пункт поднимает стенд заново и убирает его за собой: сеть `raditi-oc-net` (`10.213.77.0/24`, internal), контейнеры `raditi-oc-fake-<runtime>` и `raditi-oc-cli-<runtime>-<запуск>` с меткой `raditi-oc-spike=1`. Итог пункта — `$SPIKE_OUT/<runtime>/<пункт>.json`, сырые файлы каждого запуска — `$SPIKE_OUT/<runtime>/<запуск>/`. `SPIKE_FORMS=<имена через запятую>` ограничивает пункт 4, `SPIKE_PARALLEL` задаёт число одновременных контейнеров CLI (по умолчанию 3).

Сырые результаты в репозиторий не кладутся. `collect.mjs` выбирает нужные файлы, проверяет, что в них нет строк вида ключа хода и токена MCP, и переносит их в `samples/7x-g1-*` скриптом очистки. Всё в `samples/` — JSON: вывод CLI записан как `{"events": […]}`, текст (stderr, выдержки из исполняемого файла) — как `{"text": …}`, записи фейка одного запуска — как выжимка `{"requests": […], "toolResults": […]}` без тел запросов (имя на `.requests.json`). Файлы, которых в `$SPIKE_OUT` нет, пропускаются с сообщением.

## Что лежит в `samples/`

| Каталог | Что в нём |
| --- | --- |
| `70-g1-runtime` | Итоги пунктов 1 и 2 под обоими runtime (`<runtime>.p1.json`, `.p1crash.json`, `.p2.json`, `.p2ports.json`); под `runsc` — запросы и события хода из пяти запросов, события продолжения, баннер Bun при падении, stderr при ошибке конфигурации |
| `71-g1-hostile-db` | Итоги пункта 3 и всё, что видел приёмник; `runsc.row-directory.requests.json` — запросы хода с подложенным каталогом и ответы его инструментов (событий этот ход не печатает) |
| `72-g1-refusals` | Итоги пункта 4; `events/<форма>.events.json` — события CLI на каждую форму отказа под `runsc`; `requests/<форма>.requests.json` — запросы того же запуска: время, размер, поля, ответ фейка |
| `73-g1-mcp` | Итоги пункта 6; stderr с `--print-logs` на уровнях WARN и INFO |
| `74-g1-config` | Итоги пункта 7 и добавки `p7order`; запросы и события хода со сжатием контекста; события и stderr хода, оборванного запросом разрешения |
| `75-g1-binary` | Выдержки `strings.mjs` из исполняемого файла |

В итогах пунктов id сессий заменены заглушками, значения заголовков убраны, вместо ключа хода и токена MCP — `<dummy llm token>` и `<dummy mcp token>`. События CLI поэтому не побайтовые: в событии `error` поле `responseHeaders` сокращено до `content-type` и `retry-after`, рядом стоит `removedHeaderNames`, id сессии, сообщений и частей — заглушки.

Записи 70–75 сделаны прогонами исполнителя 05.10.2026; `*.p2ports.json` и `*.p7order.json` — прогонами ревью того же дня, выжимки `*.requests.json` — из записей фейка прогонов исполнителя.
